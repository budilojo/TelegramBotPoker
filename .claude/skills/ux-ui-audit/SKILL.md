# Проверка UX и UI проекта (TelegramBotPoker)

Проект — Telegram Mini App с семью играми (покер, дурак, UNOQ, шахматы, шашки, нарды, морской бой), хабом, лобби, магазином косметики, профилем, рейтингом.
Владелец — не программист: результат объясняйте по-русски простыми словами, называйте, что проверено и что **не** проверено (живой Telegram и телефон агентам недоступны).
Правила проекта — `AGENTS.md`; дизайн-система — `docs/redesign.md`, `miniapp/tokens.css`: плоско, без градиентов и свечения, один зелёный акцент, кегли и скругления только из шкалы, зоны нажатия ≥ 44 px, экраны от 320 px, всё по-русски.

## 1. Симуляция «новичок за столом»
Для каждой игры и общих экранов пройдите путь, как это делает человек, который видит экран впервые: открыть → найти главное действие → сделать → понять результат → вернуться.
- Пользуйтесь **только видимым интерфейсом** (кнопки, тап, перетаскивание), без знания внутренних селекторов, где это возможно; скрипты — Playwright (`tools/e2e-*.mjs` как образец, `E2E_PORT` свой).
- Для каждого главного действия считайте: **сколько касаний и какими жестами** (тап, второй тап, перетаскивание, долгое нажатие, клавиатура), есть ли подсказка, что делать дальше, виден ли отказ и **понятна ли его причина**.
- Составьте **матрицу единообразия жестов**: одно и то же по смыслу действие («сыграть карту/фигуру», «подтвердить», «отменить», «назад») должно делаться одинаково во всех играх и в обеих ролях (атака/защита, свой ход/чужой). Разное — это находка.
- Ищите тупики (нет пути назад), немые состояния (ничего не происходит и не объяснено), ловушки (случайное необратимое действие без подтверждения), двойные подсказки, подсказки, противоречащие поведению.
- Известный пример: в Дураке подкинуть — «тап, второй тап», а отбиться — только перетаскиванием; это разные жесты для одного смысла.
Находка = ID, где (игра/экран/состояние), шаги, ожидал / получил, серьёзность (блокирует / мешает / косметика), доказательство (скрипт, снимок), предложение.

## 2. Вёрстка: выезжает, обрезано, налезает
Автоматически и глазами проверьте **каждый экран × каждую ширину (320, 360, 390, 430) × каждое состояние** (пусто, мало, много, длинные имена и числа `1.000.000`, ошибка, загрузка, клавиатура, шторка, нижняя панель):
- горизонтальная прокрутка страницы; элемент, правый/левый край которого вне экрана или вне своего родителя;
- текст обрезан (`text-overflow`, `overflow: hidden`, `scrollWidth > clientWidth`), буквы вылезают из кнопки/карточки/плашки, перенос слов в узком блоке некрасивый (одна буква в строке, «висячие» предлоги);
- наложения: один блок закрывает другой (нижняя панель, чат, кнопка действия, шторка, шапка);
- зоны нажатия < 44 px, мелкий текст, плохой контраст (`npm run kit`, `npm run contrast` — не заменяют глаза).
Нужен инструмент, который обходит DOM и сообщает такие элементы с координатами и селектором (`tools/ui-scan.mjs`, если ещё нет — создайте), затем **посмотрите снимки глазами**: автоизмерения не заменяют взгляд.

## 3. Красота и единообразие
Смотрите снимки как дизайнер: иерархия (что главное), отступы и выравнивание по сетке, одинаковые карточки/кнопки/заголовки в разных экранах, пустые состояния, иконки, плотность текста, «технический» язык, который игроку не нужен («Цена не утверждена», «Найдено: 64», внутренние названия).
Игровой арт (карты, фигуры, доски) — содержание игры, его не перекрашивают палитрой. Не предлагайте то, что запрещено дизайн-системой (градиенты, свечение, золото).
Образец «понятно и приятно» — скриншоты конкурента в `design/competitor/` (Cardbox): берём **структуру и ясность** (одно главное действие, крупные карточки с картинкой, вкладки категорий вместо выпадающих списков, окно подтверждения), **не** копируем их картинки, талисман, тексты, глянец, градиенты, реальные деньги.

## 4. Магазин
Ориентир структуры: вкладки категорий сверху (а не три выпадающих списка), сетка из двух колонок с крупным превью, под превью — название, одна строка и одна понятная кнопка/статус («Примерить», «В коллекции», цена в ⭐, «Скоро»), окно подтверждения снизу, «Мои вещи» по слотам с крупными превью, ясные пустые состояния. Продажи закрыты (`SALES_MODE`), цены не придумывать — читать из `offers.json`/админки; внутренний жаргон игроку не показывать.

## 5. Как оформлять результат
Таблица «экран × ширина × состояние → результат» + список находок + что исправлено + что не проверено. Каждую новую защиту (тест, скан) проверяйте «на зубы»: верните поломку — проверка должна упасть. Метки доказательств: 1 прочитано в коде; 2 запущено (команда, дата); 3 с заглушкой Telegram; 4 требует живого Telegram; 5 не проверено.
