# Косметика v2 — источник и применение

Авторская векторная геометрия **Codex B**, 31.10.2026. Источник:
`tools/build-cosmetics-v2.mjs`. Сторонних изображений, шрифтов, библиотек арта,
внешних ссылок, растровых вставок, градиентов, фильтров и анимаций нет.
Новый арт **ещё не утверждён владельцем** (`source.approved:false`). Одобрение
старых SVG Графита к этому пакету не относится; `../art/` не менялся.

114 SVG: 54 самостоятельных предмета в шести коллекциях (по девять),
54 preview + 54 game и 6 preview комплектов. Комплект — состав девяти вещей,
не десятый самостоятельный предмет. Все 60 стабильных id, названия, описания,
игры, слоты и составы — в `manifest.json`, по `docs/cosmetics-v2/item-plan.json`.
`readiness:art-ready` означает готовность ресурсов, не серверной интеграции.
`price:null` не разрешает продажу. Манифест не выдаёт никому прав.

## Воспроизведение

Из корня репозитория:

```
node tools/build-cosmetics-v2.mjs
node --test tools/cosmetics-v2-art.test.js
node tools/check-cosmetics-v2.mjs --sheet docs/cosmetics-v2/reports/art-sheets
node tools/cosmetics-v2-art-teeth.mjs --browser
```

Можно генерировать в отдельную папку: `--out /absolute/path`. Импорт генератора
ничего не записывает, повтор даёт тот же результат. Запись ограничена SVG этого
пакета и его manifest в выбранной папке; README и посторонние файлы не удаляются.
При осознанном изменении арта сначала исправить источник, пересоздать SVG/manifest,
повторить тесты, поломки и просмотр изображений. Не редактировать SVG вручную.

## Descriptors для C/D

Читать `manifest.items` по стабильному id. Там есть поля договора A, `assets`,
а также прямые URL `preview`/`game`. У комплекта `game:null`. Метаданные ресурсов
в `manifest.files`: basename, item, role, slot, width/height/viewBox, bytes,
sha256 и protectedRegions. Не принимать URL, CSS или цвет из запроса игрока.

| Слот | preview | game | Прозрачная область в координатах viewBox |
|---|---|---|---|
| cardback | 200×280 | 40×56 | нет; только закрытая карта покера |
| unoq-cardback | 200×280 | 40×56 | нет; только закрытая стопка UNOQ |
| table | 480×320 | 480×320 | эллипс (240,160), радиусы 218×138 |
| frame | 160×160 | 48×48 | круг в центре, радиус 60/160 ширины |
| badge | 160×160 | 24×24 | нет; отдельная эмблема рядом с именем |
| chess-board | 400×400 | 400×400 | x/y 24…376 |
| checkers-board | 400×400 | 400×400 | x/y 24…376 |
| nardy-board | 480×360 | 480×360 | два окна x=24…232 и 248…456; y=24…336 |
| battleship-panel | 400×400 | 400×400 | x/y 24…376, одинаковый ресурс для обоих полей |
| bundle | 480×320 | — | составная миниатюра, не игровой слой |

У стола и нард стоит preserveAspectRatio=none: орнамент адаптируется к
пропорциям контейнера, не оставляя широкую полосу в высоком покерном овале.

Рамки/доски — **только декор**, без фигур, координатного текста, флота, кубиков,
шахматной разметки или символов попадания. Они накладываются на отдельный слой;
прежние поля/координаты/игровые знаки остаются в DOM. Для миниатюры доски C/D
может компоновать preview с классической доской; прозрачный файл сам по себе
показывает раму. Шашечная рама имеет крупные чередующиеся вставки; морской бой —
спокойные линейки и угловые эмблемы, отличимые от шахмат/шашек.

C должен совместить игровые области с прозрачными окнами, сохранив хитбоксы,
зоны действий и текущие цвета. Нарды: вертикальный бар находится в x=232…248;
не помещать декор поверх номеров/стопок. Морской бой: координаты и сетка должны
быть внутри окна, декор не создаёт ни одного игрового знака. Одинаковый ресурс
годится для обеих сторон независимо от флота. При тесном экране допустимо
обрезать внешний орнамент, нельзя перекрывать поле/действия или делать
горизонтальную прокрутку. Это проверяется после подключения C/E.

Рамка имеет внешний размер 4/3 размера круглого аватара (48 для аватара 36);
центр 75% ширины полностью свободен. Внешняя геометрия не увеличивает контейнер
игрока; `pointer-events:none`, `aria-hidden=true`, без tabIndex. Размеры SVG —
геометрия арта, не размеры UI-кнопок. У значка есть словесное имя из item.title,
он не означает ранг/роль/право. Карта game использует усиленную линию и
упрощённый рисунок; не грузить detail для маленькой карты.

Локальные `<use href="#tile">` повторяют только собственную геометрию внутри
того же SVG. Нет `<image>`, вложенных SVG и внешних href. clipPath использует
локальный id и чётно-нечётный вырез; локальные id комплектов имеют префикс.
Валидатор разрешает только этот малый набор тегов/атрибутов, проверяет локальные
ссылки и запрещает рекурсивные use. Предпочтительно подключать SVG через img,
не вставлять строку из сервера как произвольный HTML.

Preview загружать по открытию карточки, game — только выбранный ресурс.
Ошибка SVG должна вернуть классику один раз без повторяющегося запроса (C/D).
Не подменять игровой флот, faces или четыре цвета UNOQ изображением превью.

## Размер и визуальная проверка

Общий SVG-пакет **392.719 байт** (383,51 KiB), максимум preview **19.750**,
максимум game **3.509**. Все лимиты 24/8 KiB и общий 1 MiB соблюдены;
manifest/README и отчётные PNG в SVG-бюджет не входят. Повторение tile вынесено
в локальную ссылку, а игровая версия имеет меньше деталей.

Четыре просмотренных листа: `docs/cosmetics-v2/reports/art-sheets/` — contact,
small, bundles, readability. Последний — **тестовая композиция** с настоящими
SVG карт/фигур и цветами полей проекта, а не работающая интеграция семи игр.
Пиксельный тест всех SVG проверяет прозрачность 7.134.768 внутренних пикселей
и неизменность композиции на непрозрачном игровом фоне; край антиалиасинга
(полоса 1 px) исключён из внутренней области, но не из загружаемого SVG.
Проверка нового арта в работающей партии, права/snapshot/fallback и телефон —
этапы C/E. Владелец отдельно утверждает новый арт. Продажи/рейтинг не открывались.
