# Chip Table

Виртуальные фишки для покера **настоящими картами**.

Компания достаёт колоду, один человек создаёт комнату, остальные сканируют QR
или вводят четырёхбуквенный код — и телефоны полностью заменяют стопку фишек.

Приложение **не раздаёт карты, не определяет комбинации и не решает, кто выиграл**.
Оно отвечает только за фишки: стеки, ставки, банк, очередь хода, блайнды и
сайд-поты.

Есть две оболочки поверх одного и того же движка ставок:

- **веб-приложение** — фишки для игры настоящими картами: комната по коду
  или QR, у каждого свой телефон, победителя отмечают люди;
- **телеграм-бот** (`bot/`) — игровой хаб в Telegram Mini App: в группе
  `/game` → «Покер» или «Дурак» → лобби с карточкой в группе → друзья
  присоединяются. Покер — стол с сукном, своими картами, банком и панелью
  FOLD / CALL / RAISE; бот сам тасует, сдаёт, вскрывает и делит банк (или
  игра идёт настоящими картами, а бот считает фишки). Дурак — подкидной или
  переводной, 2–6 игроков, серия партий со счётом. Группа — лобби и итоги,
  без спама после каждого хода. См. [bot/README.md](bot/README.md),
  [docs/game-hub.md](docs/game-hub.md) и [docs/miniapp-ux.md](docs/miniapp-ux.md).

Движок ставок один на обе оболочки. Карты и оценка комбинаций живут только в
боте (`bot/deck.js`, `bot/eval.js`, `bot/cards.js`), поверх движка —
`server/game.js` про карты ничего не знает и не должен.

```bash
npm start                      # веб
npm run bot                    # телеграм-бот (токен, HTTPS-адрес — в .env, см. bot/README.md)
```

## Запуск

```bash
npm install && npm start
```

В консоли появятся два адреса:

```
Этот компьютер : http://localhost:3000
Телефоны в сети: http://192.168.x.x:3000
```

Второй адрес открывают телефоны, подключённые к той же Wi-Fi сети. Ноутбук
можно не трогать — он просто держит сервер.

Тесты:

```bash
npm test
```

Иконки перегенерируются через `npm run icons` (чистый Node, без зависимостей).

### Проверить стол в одиночку

Телефон и ноутбук — это уже два настоящих устройства, остальных доберут боты.

1. `npm start`, с телефона открыть адрес вида `http://192.168.x.x:3000`
   (сервер печатает его сам) и создать комнату — вы хост.
2. На ноутбуке добрать стол, подставив код комнаты:

```bash
node tools/bots.mjs КОД                # победителя отмечаете вы
node tools/bots.mjs КОД --auto         # стол играет сам, без вас
node tools/bots.mjs КОД --auto --wild  # + олл-ины, то есть сайд-поты
```

Без `--auto` боты играют раздачу, но банк не закрывают — это остаётся
человеку. С `--auto` стол крутится сам: удобно оставить на час и посмотреть,
как поднимаются уровни блайндов.

Боты уважают роли. Сделайте дилером **себя** — и они перестанут закрывать
банки и сдавать: вы получите ровно тот сценарий, ради которого роль и нужна.
Сделайте дилером **бота** — и он будет вести стол за вас, а вы проверите, как
это выглядит со стороны игрока.

Одна ловушка: **две вкладки одного браузера не считаются за двух игроков.** У
них общий `localStorage`, и они начнут выбивать друг друга — на это есть
экран «Игра открыта в другом месте». Нужен второй клиент на ноутбуке — берите
другой браузер или приватное окно.

Бот импортирует `server/game.js` **как есть** — один источник правды на обе
оболочки. `server/rooms.js` переиспользовать нельзя: он завязан на токены
сессий и общий для всех `publicState`, а в боте личность — подпись Telegram,
и у каждого игрока своё состояние (свои карты). Идеи
оттуда (отложенные блайнды, undo-снапшоты, права хоста отдельно от места за
столом) перенесены, код — нет.

### Сервер — единственный источник истины

Клиент **никогда не меняет фишки**. Он отправляет намерение
(`{t:'action', action:'raise', amount:500, seq}`), сервер проверяет его,
применяет и рассылает всем **полный снапшот комнаты**.

Снапшоты, а не дельты — сознательное решение: за покерным столом максимум
десять игроков, снапшот весит килобайты, зато переподключение становится
тривиальным. Вернувшемуся клиенту не нужно доигрывать пропущенные события —
он просто получает правду заново.

Карты физические, поэтому **секретов в состоянии нет**: все игроки видят
одинаковый снапшот. Единственное, что не покидает сервер, — токены сессий.

### Защита от двойного нажатия и гонок

У комнаты есть монотонный счётчик `seq`. Клиент прикладывает к действию тот
`seq`, который видел на экране. Если состояние успело измениться (сосед уже
сходил, палец нажал дважды), сервер отвечает `STALE` и **не делает ничего**.

Тест `a stale seq (double tap) is dropped instead of acting twice` проверяет
именно это: два одинаковых колла улетают подряд, применяется ровно один.

На клиенте — второй рубеж: кнопка мгновенно получает класс `.sent`, а
`app.act()` держит блокировку до ответа сервера (с таймаутом, чтобы
интерфейс не завис навсегда).

### Переподключение

`playerId` и `token` лежат в `localStorage`. При каждом открытии сокета клиент
первым делом шлёт `resume`, и сервер возвращает его на то же место с тем же
стеком. Обновление страницы, блокировка экрана, потеря сети, закрытая
вкладка — всё это один и тот же сценарий.

Дополнительно:

- **`visibilitychange`** — телефон вышел из блокировки, состояние
  синхронизируется сразу, а не через 12 секунд.
- **Вход по имени** — если `localStorage` потерян (новый телефон, очищенный
  браузер), достаточно ввести код и то же имя: отключённое место вернётся
  владельцу. Занятые места так забрать нельзя.
- **Две вкладки** — не воюют за сокет. Вторая вкладка показывает экран
  «Игра открыта в другом месте» с кнопкой «Играть на этом устройстве».
- **Сервер перезапустился** — комнаты восстанавливаются из `data/rooms.json`
  (снапшот пишется каждые 10 секунд).

### Логика ставок

`server/game.js` — чистые функции над объектом комнаты, без ввода-вывода.
Реализовано по правилам no-limit hold'em:

- **Блайнды и позиции.** Хедз-ап: баттон — малый блайнд и ходит первым до
  флопа, но последним после. За столом от трёх: SB слева от баттона, первым
  до флопа ходит игрок за BB, после флопа — первый живой слева от баттона.
- **Опция большого блайнда.** Если все только уравняли, BB всё равно получает
  право повысить.
- **Минимальный рейз** считается от последнего полноценного повышения.
- **Короткий олл-ин не открывает торговлю заново.** Если игрок пошёл ва-банк
  на сумму меньше полного рейза, те, кто уже сходил, могут только уравнять
  или сбросить — кнопка RAISE им не показывается.
- **Сайд-поты** считаются по уровням вложений: для каждого уровня берётся
  сумма вкладов и список тех, кто не сбросил и дошёл до этого уровня.
  Фишки сброшенных игроков остаются в банке как мёртвые деньги. Банк, на
  который претендует один игрок, — это непоколлированная ставка, она
  возвращается автоматически.
- **Раздел банка.** При ничьей нечётные фишки достаются первому победителю
  слева от баттона.
- **Досдача при олл-ине.** Когда ходить больше некому, оставшиеся улицы
  пропускаются и раздача сразу идёт к вскрытию.

Инвариант, который проверяется на 600+ случайных раздач с 2–8 игроками:
**сумма всех стеков и банка не меняется никогда**.

### Кто победил

Приложение не знает комбинаций, поэтому после торговли кто-то должен указать
победителя. Кто именно — зависит от того, назначен ли дилер:

- **Дилер назначен** — решает он, на отдельном экране (см. ниже). Остальные
  видят «Макс определяет победителя» и ничего не могут нажать.
- **Дилера нет** — как и раньше, решает стол: выбор синхронизируется в
  реальном времени, подтвердить может любой, а ошибку откатит Undo.

Для нескольких банков каждый разыгрывается отдельно, с собственным списком
претендентов. Ничья — отметить нескольких.

### Растущие блайнды

По умолчанию блайнды фиксированные. В настройках хост включает режим
«Растущие», и комната получает лестницу из десяти уровней, построенную от
стартовых блайндов кратностями 1, 2, 3, 4, 6, 8, 12, 16, 24, 32 — для 25/50
это 25/50 → 50/100 → 75/150 → 100/200 и так далее. Лестница видна целиком ещё
до старта.

Три правила, которые делают это пригодным для живой игры:

- **Блайнды меняются только между раздачами.** Движок перечитывает
  `settings.bigBlind` при сбросе минимального рейза на каждой улице, поэтому
  смена внутри раздачи двигала бы правила под игроками. Любое изменение —
  и по таймеру, и вручную — паркуется в `pendingBlinds` и применяется при
  следующей сдаче. Это же чинит старое поведение ручной правки блайндов,
  которое обещало «со следующей раздачи», но применялось сразу.
- **Часы уровня встают вместе с игрой.** Пауза на перекур не сжигает уровень.
- **Медленная раздача сдвигает лестницу ровно на один шаг.** Если между
  сдачами прошло три уровня, блайнды всё равно поднимутся один раз — никого
  не выносит скачком.

Хост может поднять уровень досрочно через меню комнаты: результат тот же,
применится со следующей раздачи.

Таймер не гоняется на сервере: снапшот несёт остаток текущего уровня, а
телефоны отсчитывают его локально. Уровень фактически сдвигается в момент
сдачи следующей раздачи, так что лишнего трафика нет вообще.

### Права хоста

Пауза, ручная коррекция стека, удаление игрока, передача прав, завершение
игры и **Undo последнего действия** (глубина 40 шагов). Каждое опасное
действие проходит через диалог подтверждения с точными цифрами:
`Макс: 9 100 → 10 100. Это видно всем за столом.`

Ручное пополнение стека увеличивает и «бай-ин» игрока, поэтому в итоговой
таблице оно не выглядит выигрышем.

Если хост отключился больше чем на минуту, права автоматически переходят к
игроку, который подключился раньше других, — стол не остаётся заблокированным.

Отдельная кнопка появляется, когда очередь хода дошла до игрока не в сети:
хост может сбросить карты за него, чтобы игра не встала.

## Роли: ROLE и PERMISSION — разные вещи

Это главное архитектурное решение проекта. Пользователь описывается двумя
независимыми полями:

```js
role:   'player' | 'dealer'   // что вы делаете в раздаче
isHost: true | false          // право управлять комнатой
```

Хост — **не игровая роль**, а разрешение. Поэтому возможны обе комбинации:

| Комбинация | Что видит человек |
|---|---|
| `HOST + PLAYER` | обычный игровой стол + кнопка меню комнаты |
| `HOST + DEALER` | режим дилера + та же кнопка меню комнаты |
| `PLAYER` | только игровой стол |
| `DEALER` | только режим дилера |

Интерфейс выбирается по `role`, права проверяются по `isHost` — ни один экран
не завязан на одно поле. На сервере это три отдельные проверки:

- `isHost` — назначение ролей, настройки, пауза, удаление, завершение игры;
- `canRunTable` — хост **или** дилер: Undo, fold за отключившегося;
- `canDecideWinner` — дилер (и хост как запасной вариант). Если дилер не
  назначен, решает весь стол — как и было до появления ролей.

Дилер в комнате **ровно один**: назначение нового снимает роль со старого и
возвращает его за стол со следующей раздачи. Это касается и отложенных смен —
две промоции, поставленные в очередь в одной раздаче, не могут приземлиться
обе.

Разрешение — не приглашение. У хоста-игрока есть право закрыть банк на случай
севшего телефона дилера, но пока дилер на связи, экран выбора победителя ему
**не открывается сам**: он видит «Саша определяет победителя» и неприметную
кнопку «Определить победителя самому». По той же причине следующую раздачу
начинает дилер: он ещё собирает карты, и чужой тап выставил бы блайнды раньше,
чем колода перетасована. Без назначенного дилера стол по-прежнему двигает себя
сам — любой участник.

### Player

Играет и имеет стек. Видит POT, свой стек, текущую ставку, остальных игроков,
их действия и чей сейчас ход. Действия — те же CHECK / CALL / BET / RAISE /
FOLD / ALL-IN.

### Dealer

Раздаёт настоящие карты, поэтому **не занимает место за столом**: ему не
раздают, он не ставит блайнды и не рискует фишками. Его стек сохраняется и
возвращается, если хост вернёт ему роль Player.

Экран дилера — отдельный: весь стол крупными карточками (стек, текущая
ставка, fold, all-in, чей ход), банк, этап раздачи, история. Внизу — одна
большая кнопка, которая всегда говорит, что делать дальше.

### Назначение ролей

Хост нажимает на участника и получает bottom sheet «Роль участника» с двумя
крупными вариантами и кнопкой «Применить». Изменение сразу расходится по всем
устройствам.

Роль можно менять в любой момент. Если игрок прямо сейчас в раздаче и не
сбросил карты, смена **откладывается до следующей раздачи** — иначе его фишки
остались бы в банке без владельца. В списке участников это видно как
`PLAYER → DEALER`.

**Дилер за столом один.** Карты раздаёт одна пара рук, поэтому роль дилера
не копируется, а **передаётся**: назначили дилером другого — прежний в тот же
момент вернулся к игре обычным Player. Иначе «назначить другого дилера» тихо
посадило бы за стол двух операторов, убрало бы обоих из раздачи, а все
телефоны продолжали бы показывать дилером **прежнего**. Если оба в раздаче и
смена отложена, отменяется и уже поставленная в очередь — доезжает ровно одна.

## Экран дилера: кто забрал банк

Дилер держит карты в одной руке и телефон в другой, поэтому:

- **Один банк — два нажатия.** Тап по игроку → «Подтвердить победителя».
  Под кнопкой подпись: *Дима — Получит +1 875*.
- **Ничего не списывается до подтверждения.** Первый тап только выбирает.
- **Split** включается кнопкой «Разделить банк»: выбор становится
  множественным, и каждая карточка сразу показывает свою долю.
- **Сайд-поты** проходят по шагам: «Банк 1 из 2 · MAIN POT», затем
  «SIDE POT 1» — и в каждом показаны **только те, кто имеет на него право**.
  Сбросившие карты не предлагаются нигде.
- **Итоговый экран «Распределение»** показывает разбивку по банкам и суммы на
  руки, и только после него меняются балансы.
- **Возврат непоколлированной ставки** дилера не спрашивают: банк, на который
  претендует один игрок, помечается как «ВОЗВРАТ» и считается автоматически.

Числа в превью считает **сервер** той же функцией `distribution()`, которая
потом реально раздаёт фишки, — превью не может разойтись с результатом.
Правило нечётной фишки при ничьей: она достаётся первому победителю слева от
баттона.

### Защита от ошибок дилера

| Риск | Что сделано |
|---|---|
| Случайный тап | Выбор и подтверждение — разные нажатия |
| Двойное нажатие | Блокировка `pending` + `seq`-проверка на сервере |
| Ошибся победителем | Undo доступен дилеру, а не только хосту |
| Выбрал сбросившего | Такие игроки вообще не отображаются |
| Выбрал не того в сайд-поте | Список ограничен теми, кто имеет право |
| Ручной подсчёт банков | Сайд-поты считает сервер, дилер только выбирает |
| Дилер потерял связь | Хост может подтвердить результат вместо него |

## Лобби

После создания комнаты **никто никуда не проваливается** — все ждут в лобби.

Сверху: название стола и код подключения крупно, с кнопкой копирования и
QR-кодом; количество участников и состояние связи; текущие настройки игры с
кнопкой «Изменить» для хоста.

Ниже — список участников: инициалы в аватаре, имя, статус связи и роль в
формате `HOST • DEALER` / `PLAYER`. Хост нажимает на любого, чтобы назначить
роль, поправить стек, передать права или удалить.

Внизу у хоста — крупная «Начать игру». Она включается, только когда за столом
есть минимум два участника с ролью Player и фишками; иначе объясняет, чего не
хватает.

### Настройки

До старта хост меняет и стартовый стек, и блайнды — стеки раздаются заново.
После старта меняются только блайнды и вступают в силу со следующей раздачи;
стартовый стек заморожен, чтобы итоговый P/L оставался честным.

## Решения по UX, которые стоит объяснить

**FOLD прячется, когда можно чекнуть бесплатно.** Сбросить карты, имея
возможность посмотреть следующую улицу даром, — всегда ошибка. На телефоне
это самое дорогое случайное нажатие, поэтому в такой ситуации кнопки просто
нет: остаются CHECK и BET.

**Быстрые ставки прямо в панели действий.** Над основными кнопками —
`½ POT`, `POT` и `ALL-IN` с уже посчитанными суммами. Обычная ставка делается
одним нажатием, без открытия панели. Полный интерфейс со слайдером, ручным
вводом и шестью пресетами открывается по RAISE, когда нужна точная сумма.

**ALL-IN требует подтверждения, остальные быстрые ставки — нет.** Случайно
поставить половину банка неприятно, но поправимо; случайно поставить весь
стек — нет.

**Банк показывает все фишки на столе.** Не «банк прошлых улиц отдельно,
текущие ставки отдельно», а одно число: сколько всего разыгрывается. Текущие
ставки при этом видны на карточках игроков. Для компании друзей это самая
понятная модель.

**Порядок игроков на столе** начинается со следующего за вами — как за
настоящим столом, где вы смотрите на соседа слева.

**Своя позиция** (D / SB / BB) показана рядом со своим стеком: карточки для
самого себя на столе нет, а знать позицию нужно.

## Состояния интерфейса

Проработаны не только удачные сценарии:

| Ситуация | Что видит игрок |
|---|---|
| Неправильный код | Ячейки кода вздрагивают, «Комната не найдена» с подсказкой |
| Игра уже началась | Превью комнаты + «вы вступите со следующей раздачи» |
| Ожидание хода | «Ходит Макс» с пульсирующими точками |
| Игрок отключился | Красная точка у имени, у хоста — «сделать fold за него» |
| Соединение потеряно | Верхняя плашка со спиннером, автопереподключение |
| Переподключение | Экран «Возвращаемся за стол» + аварийный выход через 3 с |
| Хост вышел | Плашка «Хост отключился — игра продолжается» |
| Пауза | Плашка + заблокированные действия |
| Действие отправляется | Кнопка мгновенно гаснет, повторное нажатие не проходит |
| Действие отклонено | Тост с причиной и немедленная ресинхронизация |
| Игра открыта дважды | Экран «Игра открыта в другом месте» с выбором |
| Игра завершена | Итоговая таблица с P/L, дилеры помечены отдельно |
| Победителя выбирает дилер | «Макс определяет победителя» с пульсацией |
| Роль сменят со следующей раздачи | В списке участников `PLAYER → DEALER` |
| За столом меньше двух игроков | Кнопка старта объясняет, кого не хватает |
| Дилер не в сети на вскрытии | Хост подтверждает результат вместо него |

## Совместимость

Mobile first: iPhone → Android → планшет → десктоп.

- `viewport-fit=cover` и `env(safe-area-inset-*)` — контент не лезет под
  «чёлку» и системную полосу внизу.
- Никакого горизонтального скролла и случайного зума
  (`touch-action: manipulation`, `maximum-scale=1`).
- Основные кнопки — не меньше 56–62 px, в зоне большого пальца.
- Есть `manifest.webmanifest` и иконки: приложение можно добавить на
  домашний экран и запускать как нативное.
- `prefers-reduced-motion` отключает анимации, включая полёт фишек.
- Десктоп показывает то же приложение в телефонной рамке по центру — это
  инструмент для телефона, и притворяться иначе незачем.

## Известные расхождения в движке

При написании бота нашлись два места в `server/game.js`, где поведение
расходится с правилами no-limit hold'em. Движок не тронут; разбор, причины и
воспроизведение — в [ENGINE-NOTE.md](ENGINE-NOTE.md) и
`node tools/engine-findings.mjs`. Ни одно из них не создаёт и не теряет фишки,
поэтому инвариант на 600+ случайных раздач их не ловит.

## Чего здесь намеренно нет

Раздачи карт, определения комбинаций, автоматического выбора победителя,
рейтингов, аккаунтов, чата и истории между играми. Карты лежат на столе,
а разговаривают люди вживую — приложение считает фишки и молчит.
