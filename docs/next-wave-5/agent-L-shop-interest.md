## Задание

Витрина набора «Ночной казино-клуб» для проверки спроса. Никаких платежей: человек смотрит вещи, **примеряет** их
и нажимает **«Хочу»**; мы считаем нажатия по двум вариантам цены. Подробности — план волны.

## Что сделать

1. **Каталог первым пушем** (`miniapp/cosmetics/catalog.js` + заглушки `miniapp/cosmetics/placeholder/*.svg` —
   плоские, с пометкой `TEMP`, чтобы всё работало без картинок владельца): 10 вещей из плана с полями контракта.
   Добавь `SETS` (название набора, описание одной строкой, порядок), `itemById`, `itemsOfSet`, `isItem(id)`; чистый
   модуль без DOM (его читает сервер для белого списка). Тексты — по-русски, живые («Тёмная рубашка с неоновой
   каймой. Её видят все за столом»), не канцелярит. Цены: `stars: { a, b }` по таблице-ориентиру (реши и обоснуй в
   `decisions/097`): мелочь 15/25, рамка и рубашка 50/75, сукно 75/100, набор целиком — как сумма со скидкой ≈ 25 %
   (набор — отдельная вещь `nc-bundle`, вид `bundle`, `items:[…]`; добавь вид в контракт и скажи M). Курс Stars → доллары не
   показывать, пока он не проверен (`docs/monetization.md` §8): цена только в Stars.
2. **Спрос — сервер** (`bot/shop.js`, один небольшой блок в `bot/hub.js`): сообщение `{ t:'shop', op:'interest', item,
   action:'view'|'want', variant:'a'|'b' }` и `{ t:'shop', op:'mine' }` (что я уже нажал). Личность — только из
   `initData`; чужой id в теле игнорируется; неизвестные `item/action/variant` — отказ словами; частота — по часам
   `app.clock.now()` (не чаще N событий в минуту, повторное «Хочу» той же вещи не считается дважды); хранение — новая
   таблица `shop_interest` через `CREATE TABLE IF NOT EXISTS` (версия схемы 5 **не поднимается**; старый код
   должен открывать такую базу — проверь как при профиле, `git show 7afb285:bot/store.js`). **Вариант цены игроку
   назначается сервером** (по `user_id`, постоянно: один человек всегда видит одну и ту же цену); клиент свой вариант
   не выбирает. Игрок видит только своё; в админке (`bot/admin*`, экран «Сводка» — найди, как сделаны счётчики) —
   **только суммы** по вещи и варианту: просмотров, «Хочу», доля «Хочу» от просмотров; имён нет. Удаление: «Сбросить
   мои отметки» (подтверждение). Тексты отказов — в `MESSAGES.md`.
3. **Экран «Магазин»** (`miniapp/shop/`, `miniapp/shop.css`): вход — из вкладки «Настройки» (после профиля) и из
   профиля; сверху набор «Ночной казино-клуб» с одной строкой-обещанием, дальше сетка вещей (картинка, название,
   цена в Stars, у «Хочу» — состояние «Вы хотите ✓»). Карточка вещи — шторка или полный экран (реши; если шторка —
   не пересоздавай прокручиваемый узел, `docs/scroll.md`): большая картинка, название, описание, цена, кнопки
   **«Примерить»** (`look.setLook`, открывает `renderFitting` M) и **«Хочу»**. Под кнопкой честная строка: «Оплаты
   пока нет — мы проверяем, что вам интересно. Нажав «Хочу», вы ничего не покупаете.» Никаких «осталось 2 часа»,
   «все уже купили» и прочих манипуляций — только правда. Вещи других типов (звание-текст) показывать корректно.
   Интерфейс вокруг картинок — плоский, по токенам (решение 096: исключение только для самих картинок набора).
4. **Админка/отчёт спроса:** добавь в пульт владельца блок «Магазин: спрос» (вещь, вариант A/B, просмотры, «Хочу»,
   %) — читать из вашей таблицы, без имён; выгрузка не нужна.
5. **Тесты («на зубы»):** `bot/shop.test.js` — личность из `initData`; чужой id в теле игнорируется; белый список
   вещей из каталога; вариант цены стабилен для одного человека и разный (примерно поровну) у разных; «Хочу»
   дважды = один раз; частота (`FakeClock`); игрок не видит чужих отметок; админка отдаёт только суммы (проверь «что
   получил каждый телефон»: ни одного `user_id` в ответах чужим и в админских суммах); таблица создаётся повторно и
   старый код открывает базу. **Сломай каждую защиту — тест падает** (отчёт). `tools/e2e-shop.mjs` (в `npm run e2e`):
   путь Настройки → Магазин → вещь → «Примерить» открывает примерочную → «Хочу» → «Вы хотите ✓»; 320 и 390 px; без
   горизонтального скролла; без ошибок в консоли; `assertNoJump` (`tools/lib/scroll-probe.mjs`) на переключателях.
6. `npm test`, `npm run e2e`, `layout`, `kit`, `contrast`, `preview` — **посмотри глазами** магазин и карточки на
   320 и 390 px.

## Не проверить без живого Telegram — скажи прямо

Как выглядят картинки и заглушки на телефоне, нажатия пальцем, поведение шторки. **Платёж не проверяется — его нет.**

## Чего не делать

Не подключать оплату, не создавать счетов и кнопок «Купить», не писать «куплено». Не трогать рейтинг и правила игр.
Не показывать цену в рублях/долларах. Не менять файлы M (`look.js`, `apply*`, хуки в играх) — только вызывай его API.


## Дополнение владельца (2026-10-27): привилегии, «Надеть» и выкатка

Владелец хочет **сам пользоваться набором** и играть в нём, в том числе в играх с ботами, а потом **выкатить на
сервер**. Поэтому к заданию L добавляется (сначала допиши то, что уже в работе):

1. **Все вещи разблокированы для администраторов.** Кто администратор — решает сервер (`app.isAdmin(userId)`, список
   `ADMIN_IDS` из настроек, как в пульте). Ответ `{ t:'shop', op:'mine' }` получает поле `unlocked: true` у администратора
   (серверная проверка по `initData`, не по телу сообщения; обычный игрок поле получить не может — тест «на зубы»:
   тело `{ unlocked: true }` или чужой id ничего не дают).
2. **Кнопка «Надеть» вместо «Хочу»** у разблокированных вещей: `look.setLook({ [kind]: id })` из `miniapp/cosmetics/look.js`
   (автор M), и «Снять» (`clearLook`). Для остальных игроков — как раньше (примерка и «Хочу»). Надетое хранится на этом
   телефоне и **применяется везде, где M уже показывает вид: стол покера и дурака, в том числе в играх с ботами** (проверь на
   экране «Игры с ботами» → Покер/Дурак, что рубашка, сукно, рамка и эффект действительно видны).
3. **Подключить «Примерить»** к `renderFitting` M (он уже в `redesign`) — и убери из отчёта оговорку «M ещё нет».
4. **Список тестеров** (необязательно, если легко): настройка `COSMETICS_TESTERS` — id через запятую, вещи разблокированы и
   у них (друзьям на проверку); по умолчанию пусто. Без этого — только админы.
5. Это **не покупка**: у остальных игроков по-прежнему только «Хочу» и счётчики; платежей нет (решение 096 и план).
6. Тексты — в `MESSAGES.md`; тесты (`bot/shop.test.js`, `tools/e2e-shop.mjs`) расширь под пункты 1–3; сломай защиту
   (`unlocked` по телу сообщения) — тест падает.

Выкатку на сервер делает владелец отдельным шагом (`docs/next-deploy-prompt.md`), ты её не выполняешь.
