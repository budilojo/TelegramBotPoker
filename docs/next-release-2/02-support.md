# G — поддержка внутри бота

## Слова владельца
«По поводу поддержки надо сделать так, чтобы они могли писать прям в бота, и я мог им отвечать от его имени».

## Цель
Игрок пишет боту в личке — сообщение доходит до владельца; владелец отвечает, и ответ приходит игроку от имени бота. Это закрывает требование Telegram
про `/paysupport` и заменяет «публичный контакт поддержки» ботом. (Реквизиты ИП и срок ответа по закону остаются в `owner-inputs.md`.)

## Что сделать
1. **Вход игрока:** кнопка «Написать в поддержку» (в «Мои покупки», «Настройках» рядом с «Коллекции» и в ответах `/paysupport`, `/terms`); открывает личку с ботом по
   ссылке `?start=support` (проверить по официальной документации Telegram, что ссылка из Mini App открывается — `Telegram.WebApp.openTelegramLink`; если нет — не обещать).
   В личке: короткое приветствие («Напишите вопрос одним сообщением. Пароли и коды не присылайте»), дальше обычные сообщения не-команды — это обращения.
2. **Доставка владельцу:** каждое обращение уходит всем из `ADMINS` (через админ-бота, если он настроен, иначе через основного) с номером обращения, id отправителя
   и текстом. Номер обращения и id — единственное, что показываем сверх текста; личные данные игрока не подтягивать.
3. **Ответ:** владелец отвечает **ответом на сообщение** (reply в Telegram) — бот шлёт игроку «Поддержка: …»; запасной путь `/reply <№> текст`.
   Только `ADMINS` (по Telegram id из самого сообщения Telegram, не из текста). Остальным бот молчит об этих командах.
4. **Управление:** `/tickets` — открытые обращения; `/close <№>`; `/support_block <id>` и `/support_unblock <id>` (спам); игрок может закрыть своё обращение кнопкой.
5. **Защиты:** не более 5 сообщений в минуту и 20 в сутки от одного игрока; длина до 2000 знаков; только текст (фото и файлы — отказ словами: «пока только текст»); если в тексте
   похоже на токен/пароль/код входа — предупреждение игроку и пометка владельцу, текст в журнал не пишется целиком. Игрок видит только свою переписку; id из тела сообщения игнорируются.
6. **Хранение:** новые таблицы в той же SQLite через `CREATE TABLE IF NOT EXISTS` (старый код их не трогает); срок хранения — предложить в отчёте (по умолчанию 12 месяцев, удаление по запросу)
   и **дописать в проект политики данных** `docs/next-release/legal/privacy-policy.md` (категория «обращения в поддержку», цель, срок). Версию документа поднять по правилу A.
7. **`/paysupport` и шлюз продаж:** `PAY_SUPPORT=bot` (или эквивалент) считается заданным контактом; `/paysupport` объясняет «напишите прямо сюда». Проверить, что `gate()` не открывает `live` при пустом остальном.
8. **Недоставка:** игрок заблокировал бота — ответ не доставлен, владельцу сообщается; бот перезапустился — обращения на месте; один ответ не должен уйти дважды.
9. Тексты — `MESSAGES.md`; `docs/admin.md` — раздел «Поддержка».

## Проверки
Тесты через стенд: игрок → владелец → игрок; чужой не отвечает; игрок A не видит ответ игроку B; лимиты; блокировка; перезапуск с файловой базой; повтор доставки ничего не удваивает;
`/paysupport`. Все новые защиты — «на зубы». Что не проверено в живом Telegram — перечислить (в т. ч. работа ссылки `?start=support` из Mini App на iOS/Android).
