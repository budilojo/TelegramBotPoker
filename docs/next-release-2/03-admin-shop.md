# H — магазин в админке владельца

## Слова владельца
«Дай мне доступ, чтобы я мог через админку давать товар, забирать его, менять цены — вот все возможности у меня были».
И: «цены выбери сам, подходящие».

## Цель
В существующей админке Mini App (`miniapp/admin.js`, вкладки «Цифры / Сейчас / Рассылка / Обслуживание»; доступ — только `ADMINS` по `initData`) появляется вкладка **«Магазин»**.
Владелец может: видеть вещи и цены; менять цену; скрыть/показать вещь; выдать вещь игроку; забрать выданную вещь; видеть заказы и историю; сделать возврат;
остановить/возобновить новые продажи; видеть, чего не хватает для открытия продаж (`gate()` — причины словами).

## Цены по умолчанию (выбраны за владельца, `00-plan.md`)
рубашка `graphit-cardback` **75**, знак `graphit-profile` **50**, стол `graphit-table` **100**, комплект `graphit-bundle` **175** (⭐). Занести в `bot/payments/offers.json`
с пометкой «выбрано по поручению владельца 2026-10-30, меняется в админке». Продажи это **не открывает**: остальные условия `gate()` остаются; «Ночной казино-клуб» не продаётся.

## Что сделать
1. **Цены в базе:** новая таблица с переопределением цены и видимости по вещам (`CREATE TABLE IF NOT EXISTS`); `offers.json` — значения по умолчанию. Сервер — единственный источник цены.
   Диапазон `isPrice` (1…10 000) сохраняется. Смена цены действует на **новые** заказы; уже выставленные счета со старой ценой оплатить нельзя (как B-3) — сказать об этом в окне подтверждения.
   Журнал смен (кто, когда, было → стало) без секретов; подтверждение двумя шагами («75 → 100 ⭐ — Подтвердить»).
2. **Выдать / забрать:** по Telegram id (и поиском по нику из профиля, если есть). Выдача админом — **отдельный источник права** (`admin`), не покупка и не тестерский доступ: независимые источники не мешают друг другу.
   «Забрать» снимает только админский источник; купленное не отзывается; надетый вид снимается, только если права не осталось ни из одного источника. Все операции — с `req`-идемпотентностью и записью в журнал.
   Выдача не создаёт платёж и не попадает в «Мои покупки» как покупка (там её видно с пометкой «подарок от администратора»).
3. **Заказы и возвраты:** список заказов (поиск по id игрока и номеру); возврат — **теми же серверными функциями и тем же двухшаговым кодом**, что `/refund` в боте; никаких новых путей к деньгам.
4. **Продажи:** кнопка «Остановить новые продажи / Возобновить» (то же, что `/salesstop`, обработка уже оплаченного не ломается) и блок «Готовность к продаже» с причинами из `gate()` (цены, поддержка, документы, режим).
5. **Безопасность:** все действия — по подписанному `initData` и `ADMINS` на сервере, не по полям страницы; постороннему вкладка неотличима от несуществующей; журнал и лимиты частоты; ничего из админки не раскрывает чужие карты/ходы (в игры не заглядываем).
6. Дизайн-система, 320/390 px, кнопки от 44 px; тексты — `MESSAGES.md`; документация — `docs/admin.md`, `docs/next-release/payment-design.md` (раздел «Цены и выдача админом»).

## Проверки
Серверные тесты: не-админ получает отказ на каждую операцию; выдача/отзыв и независимые источники (купил + выдан → забрали выдачу → осталось купленное; обратное); смена цены не меняет цену выставленного счёта;
повторное нажатие; возврат только через двухшаговый код; остановка продаж. «На зубы» на каждую защиту (по образцу `tools/payments-teeth.mjs`). Браузер: `tools/e2e-admin*.mjs` (вкладка «Магазин», 320/390 px), `layout`, `kit`, `contrast`, `preview` с просмотром.
Честно: настоящие платежи и телефон не проверены.
