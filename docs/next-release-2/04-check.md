# I — независимая проверка второго пакета

Проверяй фактический результат F–H (код, а не отчёты). Выполни `npm test`, полный `npm run e2e`, `layout`, `kit`, `contrast`, `preview` с просмотром снимков, `colors` — если затронут UNOQ.
Не прячь нестабильные падения (известное: `preview` иногда падает по таймауту — записать, если повторится).

Проверить отдельно:
1. **Шахматы (F):** воспроизвести сценарий отзыва на настоящих страницах: мат → итог словами обоим → сообщение в группу → «Сыграть ещё раз». Остальные дуэли — результат короткого прогона F.
2. **Поддержка (G):** круг игрок → владелец → игрок; чужой не может ответить; игрок не видит чужую переписку; лимиты; что `PAY_SUPPORT=bot` не открывает продажи сам; что политика данных дополнена и согласована с кодом (срок хранения, удаление).
3. **Магазин в админке (H):** отказ не-админу на каждой операции; независимость источников права; смена цены не трогает уже выставленные счета; возврат только двухшаговым путём; продажи остаются закрыты (`gate()` называет причины); цены 75/50/100/175 — на месте и меняются админкой; нет пути купить игровое преимущество.
4. **Откат и копия:** новые таблицы (поддержка, цены, журнал) — старая версия `3a7fcc8` открывает такую базу и не падает; восстановление из копии как в `docs/next-release/release-readiness.md` §3.
5. **Документы против поведения:** `legal/*` и тексты бота совпадают с кодом (поддержка внутри бота, срок хранения, «подарок от администратора»).

Обновить `docs/next-release/release-readiness.md`: новый раздел «Дополнение 2026-10-30» — решения «готово / не готово» по коду, бесплатным функциям, открытию продаж, рейтингу; препятствия с доказательствами; пересборка единого списка владельцу (`owner-inputs.md`: убрать закрытое, сохранить нужное); телефонный чек-лист дополнить (шахматы после мата, поддержка туда-обратно, вкладка «Магазин» в админке); проект плана выкатки (не выполнять, с `/pause`).
Не заявлять «всё законно» и «оплата работает»: пока нет тестовой среды Telegram и ответов юриста/бухгалтера, это неправда.
