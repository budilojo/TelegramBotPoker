## Задание владельца

1. **Внутренний чат для участников одного игрового стола**, доступный во время партии,
   через общее ядро — в **любой** игре. Вход — **внизу игрового экрана**. На телефоне
   — **компактная панель**, чтобы переписка не перекрывала постоянно доску и игровые
   кнопки. **Непрочитанные** сообщения видны. Продумать: пустое состояние, длинные
   сообщения, открытие клавиатуры, возврат к игре. Автора определяет **сервер по
   подтверждённой личности**. Сообщения — **только участникам этого стола**. Разумные
   ограничения длины и частоты.
2. **Реакции и чат — один интерфейс, не два.** Сейчас смайлики (волна 1) — кнопка 🙂
   **в шапке** и пункт меню «Не показывать смайлики». Сделай так, чтобы вход в чат и в
   реакции был **один, внизу** экрана игры, а кнопка в шапке исчезла.

## Что решить самому (и записать в `decisions/036–040`)

- **Как связаны чат и реакции.** Рекомендация: один вход «💬» → компактная нижняя
  панель; над полем ввода — **ряд быстрых реакций** (3–5 универсальных, из набора R,
  поле `quick`), рядом кнопка «ещё» открывает **категории** (Реакции · Покер · игра
  стола) — не одна длинная лента; тап по реакции отправляет её и **кладёт в историю
  чата маленькой строкой** («Иван: 😂»), пузырь над аватаром остаётся как сейчас. Если
  выберешь иначе — объясни.
- **Кто участник.** Рекомендация: сидящие за столом игроки (в лобби — тоже); зритель
  чата не видит и не пишет (отказ словами); ушедший/удалённый хостом — нет. В партии с
  ботами чата нет (говорить не с кем) — вход скрыт.
- **Что с историей.** Рекомендация: последние 50 сообщений в памяти комнаты, **не в
  базе, не в карточке группы, не в `view`**, пропадают с перезапуском и с удалением
  стола; новому участнику при входе — история **с момента, когда он сел**, или вся —
  реши и назови.
- **Где кнопка на каждой игре** (покер — внизу кнопки действий; дурак — рука; UNOQ;
  шахматы, шашки, нарды, морской бой — нижний ряд кнопок). Нужно место, которое **не
  закрывает** карты, доску и кнопки хода, на 320 px. Рекомендация: небольшая круглая
  кнопка (≥ 44 px) у нижнего края с бейджем непрочитанных, не перекрывающая панель
  действий. **Проверь на всех семи играх, на 320 и 390 px.**

## Что должно быть (обязательное)

**Сервер** (`bot/chat.js` + блок в `bot/hub.js`; ничего в `server/game.js`):
- Сообщение страницы `{ t: 'chat', text }`; автор — только `session.user` (всё из тела
  игнорируется). Не участник → отказ словами.
- **Текст:** обрезать пробелы, схлопнуть переводы строк (не больше 3 подряд), длина
  1…300 символов (по символам, а не байтам); управляющие и невидимые символы (zero-width,
  RTL-override) вырезать; пустое после очистки — отказ. Сообщение — **всегда текст**:
  клиент рисует через `textContent`/`h()` без `innerHTML`; ссылки не кликабельны.
- **Частота** (по часам приложения `app.clock.now()`, как у реакций): не чаще одного
  сообщения в 1,5 с и не больше 12 в минуту на человека; одинаковый текст подряд не
  принимается 10 с. Отказ — словами с «подождите N с».
- **Доставка** только страницам участников этого стола, лёгким сообщением, **без**
  пересборки состояния, **без** записи в базу и **без** правок карточки группы
  (лимиты Telegram — `bot/outbox.js`). Непрочитанные: счётчик на сервере для каждого
  участника (в памяти), сбрасывается сообщением `{ t: 'chat-read' }`; присылается в
  каждом пуше чата и при входе на стол/переподключении.
- Тексты отказов — в `ERRORS`/`CORE_ERRORS` и в `MESSAGES.md`.

**Клиент** (`miniapp/chat.js`, `miniapp/chat.css`):
- Нижняя панель (~50% высоты на 390×844; на 320×568 — не выше половины видимой
  области), закрывается свайпом/кнопкой/тапом вне; пока открыта, игра **не
  блокируется** и **ход виден** (в шапке панели — «Ваш ход», таймер), чтобы игрок не
  проспал. Закрытие возвращает **ровно** прежний экран игры.
- **Клавиатура:** панель следит за `visualViewport` — поле ввода и последние
  сообщения остаются над клавиатурой, доска не прыгает; после закрытия панели высота
  возвращается без сдвига вёрстки игры.
- Пустое состояние: «Пока тихо. Напишите первым — увидят только игроки за этим
  столом.» Длинные слова и ссылки переносятся (`overflow-wrap: anywhere`), длинное
  сообщение — сворачивается/прокручивается, а не растягивает панель. Новые сообщения —
  автопрокрутка вниз, **если** пользователь был внизу, иначе кнопка «новые ↓».
- Поле ввода: растёт до 3 строк, «Отправить» ≥ 44 px, Enter — отправить, Shift+Enter —
  новая строка; счётчик символов у предела; отказ сервера (частота, длина) — понятно
  словами под полем.
- Автор: аватар и имя (через `avatarEl` T, когда появится), свои сообщения — справа.
- **«Не показывать чат и реакции»:** один переключатель в меню стола (заменяет пункт
  «Не показывать смайлики»; `localStorage`); у выключившего нет бейджа и пузырей.
  Не терять существующий порядок работы реакций: лимит 3 с / 6 в минуту, пузырь над
  аватаром, «подождите N с».
- Реакции берутся из `miniapp/emoji/manifest.json` (R): сервер — белый список
  `id` для данной игры (`games`), клиент — категории и быстрый ряд. Пока манифеста
  нет — прежние 16 реакций и запасные эмодзи; когда R запушит — подключи.

## Порядок работы

1. Сервер + `bot/chat.test.js`: личность из `initData` и подмена автора в теле;
   не участник (зритель, чужой стол, ушедший, удалённый) — отказ **и ничего не
   получает**; длина, очистка, частота и повтор (с `FakeClock`); текст не меняется на
   HTML; история — только участникам; непрочитанные считаются и сбрасываются; **не в
   базу, не в `serialize`, не в карточку группы, не в `view`**; «что получил каждый
   телефон» за партию; решение для партии с ботами. **«На зубы»:** убрать проверку
   участника / частоту / очистку / запись в базу — каждый тест обязан упасть.
2. Клиентский модуль и стили (новые файлы), панель, клавиатура, пустое состояние.
3. **Последним шагом** — вход в клиентах игр (одна кнопка в каждом файле) и снятие
   кнопки из шапки. Перед этим `git pull --rebase origin redesign` (там уже P и T).
4. `npm test`; `npm run layout`; `npm run kit`; `npm run contrast`; обновить
   `tools/e2e-reactions.mjs` и добавить `tools/e2e-chat.mjs` (в `npm run e2e`):
   покер на троих — открыть панель, написать, у другого бейдж, прочитал, ответил;
   зритель вход не видит; длинное сообщение; клавиатура (эмуляция `visualViewport`);
   дуэль; 320 и 390 px. `npm run preview` — **посмотреть** панель, пустое состояние,
   клавиатуру, кнопку на всех семи играх.

## Не проверить без живого Telegram — скажи прямо

Настоящая клавиатура iOS/Android (поведение `visualViewport` в webview), жест
закрытия панели пальцем, как выглядит кнопка у края (safe-area), скорость отправки по
мобильной сети.
