## Договорённости между агентами (контракты — чтобы работать независимо)

**1. Набор эмодзи (R → Q).** R кладёт файлы в `miniapp/emoji/<набор>/<id>.png` и
описание `miniapp/emoji/manifest.json`:
```
{ "version": 1,
  "sets": [
    { "id": "universal", "title": "Реакции", "games": "*",      "items": [ { "id": "gg", "file": "universal/gg.png", "label": "Хорошая игра" } ] },
    { "id": "poker",     "title": "Покер",   "games": ["poker"], "items": [ … ] } ] }
```
Q читает манифест и на сервере (список допустимых `id` для игры — белый список), и
на клиенте (категории). Пока манифеста нет — Q работает с имеющимися 16 реакциями
и запасными эмодзи; когда R запушил — подключает.

**2. Профиль (T → S, Q).** T даёт: на сервере `profileOf(userId) → { name, avatar }`
(`bot/profile.js`), в видах игр у игрока поле `avatar` (id из фиксированного списка
или `null`), на клиенте `miniapp/profile.js`: `avatarEl(player, cls)` (круг: картинка
из набора или прежний инициал) и `renderProfileSettings(container)`. S подключает
экран настроек, Q — показывает автора в чате через `avatarEl`. Пока T не запушил —
S и Q используют прежний `avatar()` и заглушку.

**3. Нижняя навигация (S) и чат (Q).** Навигация есть **только на экранах хаба**
(Игры · Рейтинг · Настройки) и **скрыта за игровым столом** — доску и кнопки
действий она не отнимает. Вход в чат/реакции — **только на экране игры**, внизу.
Они не должны встречаться на одном экране.

**4. Зоны и общие файлы.** `miniapp/games/*.js` — кнопка чата (Q, последним шагом),
вызовы `avatarEl` (T, одна-две строки), правки P (нарды, морской бой). Всё это —
**разные места файлов**; перед каждым пушем `git pull --rebase origin redesign`;
конфликт в `status.md`/`tasks.md`/`ideas.md` — «оставить обе стороны». `miniapp/ui.js`
правит только T (функция `avatar`) — остальные только читают.

**5. Номера решений** (`docs/brain/decisions/`): P — 033–035, Q — 036–040,
R — 041–042, S — 043–046, T — 047–051. Файл сессии:
`docs/brain/sessions/2026-10-23-<буква>-<тема>.md`.

**6. У каждого агента — своя копия папки проекта (`git worktree`).** Агенты волны 1
мешали друг другу чужими недописанными файлами. Поэтому владелец запускает каждого
агента **из его собственной папки** (команды — в разделе «Как запустить» ниже). Агент
пушит так: `git pull --rebase origin redesign && git push origin HEAD:redesign`
(его локальная ветка называется `work-<буква>`, на сервер и в `main` она не идёт).

## Как запустить (для владельца)

В Терминале, один раз на агента (буква P, Q, R, S, T и имя агента — из таблицы):

```
cd ~/TelegramBotPoker
git pull origin redesign
git worktree add -b work-P ../TelegramBotPoker-P origin/redesign
cd ../TelegramBotPoker-P
npm install
claude --agent igry
```

Для остальных меняйте: `work-Q` / `TelegramBotPoker-Q` / `obshchenie`; `work-R` /
`TelegramBotPoker-R` / `emodzi`; `work-S` / `TelegramBotPoker-S` / `navigaciya`;
`work-T` / `TelegramBotPoker-T` / `profil`. Каждый — в **своём окне Терминала**. В
окне напишите агенту «Начинай». Когда агент закончил, окно можно закрыть, а папку
`TelegramBotPoker-<буква>` — удалить (`git worktree remove ../TelegramBotPoker-<буква>`).

## Задание владельца целиком (для всех агентов)

> Нужно улучшить дизайн и удобство Telegram Mini App с несколькими настольными
> играми. Пользователь — обычный игрок, интерфейс понятен без инструкций, удобен на
> телефоне и полностью на русском. Работай в рамках текущей дизайн-системы. Не меняй
> старое приложение Chip Table. Не добавляй турниры, музыку и другие крупные функции
> вне задания. Небольшие решения по интерфейсу принимай сам и объясняй в отчёте.
> Проверь интерфейс от 320 px: без наложений, клавиатура, читаемость, зоны нажатия
> 44 px; сделай и **посмотри скриншоты**. Соблюдай правила проекта по приватности,
> проверке личности, текстам, тестам и коммитам; новые защиты — с тестами, которые
> падают при возврате ошибки. На сервер без прямой просьбы не выкатывать.
> В конце — простыми словами по-русски: что сделано; что проверено и какие проверки
> не прошли; что осталось и почему; что проверить вручную в живом Telegram.
