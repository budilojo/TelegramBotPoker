## Контракт (план, п. 2) — обязательно

- Сервер: `profileOf(userId) → { name, avatar }` в `bot/profile.js`; `avatar` — id из
  **фиксированного списка** (`av01`…`av12`, как в `images-avatars.md`) или `null`.
- В видах игр у каждого игрока поле `avatar` (публичное: id, не картинка).
- Клиент `miniapp/profile.js`: `avatarEl(player, cls)` — круг: картинка из набора, а если
  `avatar` нет — прежний инициал в цветном круге; `renderProfileSettings(container)`.

## Что сделать

1. **Хранение — безопасное для отката.** Новая таблица `profiles(user_id TEXT PRIMARY
   KEY, nickname TEXT, avatar TEXT, updated_at INTEGER)` через `CREATE TABLE IF NOT
   EXISTS` в `bot/store.js`; **версию схемы (`meta.schema`) не поднимать без крайней
   необходимости** — старый код должен спокойно открыть базу с лишней таблицей (проверь
   вручную: возьми `bot/store.js` версии сервера из git — `git show 7afb285:bot/store.js` в
   папку вне проекта — и открой им базу, созданную новым кодом; результат в отчёт). Тест
   на повторное создание таблицы и миграцию пустой базы. Если без смены схемы нельзя —
   остановись и объясни владельцу простыми словами, чем это грозит откату.
2. **Правила ника.** Хранится отдельно от имени из Telegram (оно остаётся в `user.name`
   для пульта и аудита). Пустое состояние: **пустой ник = «имя из Telegram»**, кнопка
   «Сбросить к имени из Telegram». Ограничения: 2–20 символов после очистки; буквы любых
   алфавитов, цифры, пробел, `_ - .` и обычные эмодзи; **нельзя** управляющие и
   невидимые символы (zero-width, RTL-override), `@`, `://`, `t.me`, ссылки, ник из
   одних пробелов или знаков. Схлопывать подряд идущие пробелы. **Частота смены:** не
   чаще раза в 10 секунд и 6 раз в час (по часам приложения `app.clock.now()`).
   **Подделка чужого имени:** если за столом уже сидит игрок с таким же отображаемым
   именем (без учёта регистра) — второму **добавляется** ` 2` (как у ботов) или смена
   ника отклоняется — выбери и объясни; тест.
3. **Аватар.** Только из списка; сервер **проверяет** id (всё остальное — отказ
   словами); клиент строит адрес только для id по шаблону `^av\d{2}$`
   (`/avatars/<id>.png`), никаких путей из данных. Файлы: `miniapp/avatars/<id>.png` (когда
   владелец сгенерирует), **временные** `miniapp/avatars/<id>.svg` — **аккуратные плоские
   символы на цветном круге** (двенадцать разных, из токенов проекта, читаются в 32 px;
   нарисуй сам). Клиент: сначала `.png`, при ошибке загрузки — `.svg`, при её отсутствии —
   инициал. **Никаких внешних адресов.**
4. **Сообщение страницы** `{ t: 'profile', nickname?, avatar? }`: личность — **только из
   `initData`**; чужой профиль изменить нельзя (в теле нет «чей»); ответ — новое состояние
   профиля или отказ словами; профиль **сам игрока** приходит ему в состоянии хаба/«настроек».
5. **Где отображается** (проверь каждое): за столом **во всех семи играх** (имя и
   аватар у места, в шапке дуэли, в итогах, в карточке в группе — имя), в **чате** (Q) и в
   **рейтинге** (имя и аватар из профиля **при показе**, а не копия в старых строках). Имена
   у уже сидящих за столом обновляются в памяти при смене ника (реши: сразу или со
   следующей раздачи/партии; назови). В группе карточка и итоги показывают отображаемый
   ник — это **публично для группы**; предупреди об этом в экране настроек одной строкой.
6. **Клиент настроек** (`renderProfileSettings`): поле ника (счётчик, понятные отказы
   словами под полем, кнопки «Сохранить» и «Сбросить»), сетка аватаров 4×3 (выбранный
   отмечен не только цветом; «Без аватара» — инициал), **предпросмотр «как вас увидят за
   столом»** (круг 40 px + ник). Клавиатура не закрывает поле и кнопку (`visualViewport`).
   Зоны нажатия ≥ 44 px, от 320 px. Тексты — в `MESSAGES.md`.

## Тесты («на зубы» — обязательно)

`bot/profile.test.js`: личность только из `initData` (тело с чужим id игнорируется);
границы и очистка ника (длины, невидимые символы, `@`/ссылки, пробелы); пустой ник = имя
из Telegram; частота (с `FakeClock`); неизвестный аватар; профиль не даёт прав (ник
«хост» или имя другого игрока не делает человека хостом и не даёт его действий);
дубль имени за столом; `view` каждой игры содержит `avatar` только из списка; ник не
попадает в чужие тайные данные; отображение в рейтинге; таблица в базе и повторный запуск.
Сломай каждую защиту — тест падает. `tools/e2e-profile.mjs` (в `npm run e2e`): смена ника
и аватара, обновление за столом у второго игрока, 320 px, клавиатура.

## Проверки

`npm test`; `npm run layout`; `npm run kit`; `npm run contrast` (круг, подписи);
`npm run preview` — **посмотреть** экран настроек, сетку, стол (покер, шахматы) с новыми
аватарами, итоги. Обязательно прогнать e2e **всех** игр: ты трогаешь `view` каждой.

## Не проверить без телефона — скажи прямо

Клавиатуру в webview; как выглядит аватар в круге 32 px на экране телефона; сохранение
после перезапуска Telegram.
