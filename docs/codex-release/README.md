# Продолжение релиза через Codex

Подготовлено 31.10.2026 по просьбе владельца после остановки Claude. Сам релиз этим коммитом **не проверен** и агенты I–M ещё не запускались через новый механизм.

## Одна команда на этом Mac

```bash
cd ~/Desktop/TelegramBotPoker-main/codex-release && caffeinate -i node tools/codex-release-run.mjs
```

Окно Терминала оставить открытым. `caffeinate -i` не даёт Mac уснуть из-за бездействия, пока работает команда; крышку держать открытой. Каждый этап — новая отдельная сессия Codex, строго по очереди. Модель берётся из настроек установленного Codex; принудительно Sonnet/Opus или другую модель скрипт не выбирает. При необходимости владелец может явно передать `--model ИМЯ`.

1. **I:** проверить исходное состояние, работу Claude и незаконченные правки, закончить независимую проверку второго пакета.
2. **J:** все игры, несколько игроков и приватность.
3. **K:** интерфейс, навигация, настройки, доступность и тексты.
4. **L:** измерения производительности и только доказуемые улучшения/удаления.
5. **M:** новый независимый исполнитель проверяет весь объединённый результат.

После лимита или ошибки повторяется **та же команда**. Принятые и опубликованные этапы не запускаются заново. Если агент оставил незакоммиченные изменения, скрипт запоминает их отпечаток; повтор разрешён только если файлы с тех пор не менялись. Посторонние изменения не удаляются и не откладываются автоматически. После аварийного завершения всего процесса может остаться блокировка: её не удалять наугад, показать сообщение агенту для проверки оставшихся процессов.

Если этап дошёл до зелёных тестов, а push не удался, повторяется публикация того же проверенного коммита. Ошибка fetch или продвижение удалённой ветки останавливают запуск. В таком случае нужно показать вывод агенту: он сохранит обе стороны и проверит объединённую версию. Автоматического force, reset и выкатки нет.

Команды без запуска исполнителей:

```bash
node tools/codex-release-run.mjs --status
node tools/codex-release-run.mjs --check
node tools/codex-release-run.mjs --dry-run
```

`--check` и `--dry-run` проверяют наличие материалов, ветку, установленный CLI и локальный статус входа. Модели, fetch, npm test и push не запускаются. Это не проверка доступности модели или отсутствия лимитов аккаунта.

## Что сохраняется и что публикуется

- Исходные `~/TelegramBotPoker`, `~/TelegramBotPoker-release2`, `~/TelegramBotPoker-release3` не изменялись при подготовке. Новая копия — самостоятельный clone на `redesign`, origin — тот же GitHub.
- Незаконченные правки Claude: `claude-interrupted.patch`, происхождение и SHA-256 — `claude-interrupted.json`. Они сохранены **как материал для проверки**, в код автоматически не применены.
- Новое состояние и журналы: `.release-run/codex/` (игнорируется Git). Состояния `.release2-run` и `.release-run/pack3` Claude не импортируются и не перезаписываются. Не удаляйте новую папку состояния: она нужна для продолжения.
- Отчёты исполнителей: `docs/codex-release/reports/`. Статус содержит уникальный `attemptId`, принимается только из коммита с чистым деревом. Старый отчёт не завершает новый этап.
- Исполнитель коммитит в `redesign` после полного `npm test`, но не пушит. Контроллер повторяет `npm test` на точном коммите и делает только обычный push в `redesign`. `main` и серверная ветка не двигаются.
- `blocked`, незавершённая локальная работа, красные проверки и запрещённые изменения останавливают публикацию и следующие этапы. `partial` допускается только при завершённой локальной работе и явно перечисленных внешних проверках/данных владельца. Это **не допуск продаж**.
- Пять сессий используют обычные ограничения Codex и автоматическую проверку разрешений (`--approve-for-me`); отключение sandbox/approvals не применяется. Остановка по таймауту посылает сигнал всей группе процесса, затем принудительно завершает оставшихся потомков этой группы. Агент обязан завершить собственные тестовые серверы.
- Для актуальных официальных источников включён встроенный живой поиск (`--search`); это не разрешение обращаться к рабочему серверу или проводить реальные платежи.

## Границы

Не подключаться к рабочему серверу, не выкатывать, не менять обслуживание. Не создавать реальные счета, оплаты, возвраты или выплаты. Не открывать продажи/рейтинг. Не читать секреты. `server/`, `public/`, `deploy/`, `.env` и контроллер запуска защищены от публикации изменений в рамках этого запуска. Это проверки контроллера и инструкции исполнителю, а не отдельная изоляция удалённого сервера на уровне ОС.

Основа CLI проверена по локальному `codex exec --help` (0.162.1) и [официальной документации OpenAI о неинтерактивном запуске](https://learn.chatgpt.com/docs/non-interactive-mode), 31.10.2026.
