## Результат и объём

Семь игр из реестра покрыты общей
[матрицей](../../next-release-3/multiplayer-matrix.md): 48 новых сценариев через
настоящий Hub/App, плюс браузер четырьмя независимыми BrowserContext на игру
на 320×568 и 390×844. Два контекста — одна подтверждённая личность; ещё два —
соперник и зритель. Покрыты создание/конкуренция/последнее место, несколько
столов и групп в одном App, права хоста/нехоста и уход из группы, подмена хода,
повторы и старые пакеты, disconnect/reconnect, настройки, разделы/возврат/часы,
завершение и повторный стол. Каждый контекст сохраняет весь поток, включая
кадры до закрытия/возврата. Table.pages намеренно не использован как архив:
он хранит только последнюю страницу личности.

Покупки и поддержка проверены на **непустой временной SQLite**: настоящие
модули приложения, API Telegram — только заглушка. Собственная история
доступна двум страницам и после reconnect при закрытых продажах; подмена
userId не даёт чужих заказов, ashop игроку недоступен. Номер/charge/payload
и текст обращения не ушли другим игрокам, зрителю и в публичную группу.
Имя/выбранный аватар/числа счёта остаются публичным оформлением по контракту.

Исправлены два воспроизведённых дефекта и регрессия первоначального исправления.
Правила игр, формула рейтинга, платежи и подтверждённые цены не менялись.
Тексты интерфейса не менялись: используется существующий русский отказ STALE,
поэтому новых строк MESSAGES нет. Новый e2e включён в `npm run e2e`.
Решения — 181 (версии пакета) и 182 (публичный счёт без id).

## Дефекты и доказательства (1/2/3)

### J-01 — задержавшийся ход предыдущей партии выполнялся в новой, средняя

**Где/версия:** 6c732ea, `bot/games/{chess,checkers,nardy,battleship}/index.js`
принимали ply/turn/shot, которые обнуляются с каждой партией; общая версия
стола seq для дуэлей не проверялась, клиент её не прикладывал.

**Воспроизведение:** `node --test --test-name-pattern='старый пакет предыдущей партии'
bot/multiplayer.test.js`. Сохранить первое допустимое действие, отменить и
повторить партию два раза (в шахматах с согласием двоих): возвращается тот же
цвет/сторона, счётчик снова 0. Послать сохранённый пакет с прежней seq.
Ожидался отказ и неизменность новой партии; фактически приняты ход/шаг/выстрел.
**До защиты: все четыре новых теста красные** с изменением match.
Это собственное задержавшееся действие, не захват чужой личности.

**Исправление:** текущий `miniapp/net.js` дополняет пакет seq и matchNo,
явные исходные версии сохраняет. `bot/hub.js` проверяет номер партии перед
передачей модулю; для move/fire/roll/end/undo проверяет ещё seq. При отказе —
слова STALE и собственный свежий view. Никакой принятой клиентом личности.
Перечень positionActions объявляют сами модули, ядро не перечисляет ходы игр.
Старый seq и старый matchNo со свежей seq отдельно проверены; свежий ход проходит.

**Проверка:** четыре сценария V, дубли E, весь e2e; поломка проверки seq,
отдельно matchNo, отдельно отправки клиентом ловится «на зубы».
**Граница:** старые клиенты без новых полей сохраняют прежний протокол с
ply/turn/shot; для новой защиты нужно переоткрыть Mini App. Обе версии —
дополнительная защита порядка, не авторизация и не запрет человеку делать
новый законный ход. Смешанные версии и мобильные задержки в Telegram — 4/5.

### J-02 — Telegram id игроков в публичном score четырёх дуэлей, низкая (приватность)

**Где/версия:** 6c732ea, `bot/games/{chess,checkers,nardy,battleship}/view.js`.
Публичный `score: score(room)` включал внутреннее поле id из правил.
Оно уходило даже зрителю уже в лобби; таблицы клиента используют имя/числа/флаги,
id для этого не нужен (1).

**Воспроизведение:** новые проверки полного потока `J <игра>: весь поток…`:
на каждом кадре проверить отсутствие id в score. **Четыре теста красные до
правки**, Hub ловит исключение отправки в t.errors, тест проверяет и этот
канал. Ожидался публичный счёт без идентификатора; фактически id передавался.

**Исправление:** четыре view отбрасывают id при сборке публичного score.
Внутренние score, результаты, история и рейтинг не менялись.
**Проверка:** серверный поток, четыре BrowserContext, текущие профильные тесты;
возврат прямого score(room) по очереди в каждой игре роняет новый тест (4/4).
Гарантий сокрытия публичного имени/аватара не заявляется и не требуется.

### J-03 — регрессия первого исправления: «Я готов» отклонялось, исправлено

**Версия:** промежуточная незакоммиченная правка J (не исходный продукт).
Первая проверка seq применялась ко всем сообщениям дуэли. Настоящий клиент
морского боя одним нажатием шлёт place→ready с одной исходной версией; place
меняет seq, ready ошибочно получает STALE. Полный e2e после обновления контракта
запроса воспроизвёл таймаут «Иван готов».

**Подтверждение до уточнения защиты:** отдельный 48-й тест с двумя связанными
сообщениями place/ready и одной seq — красный, ready[0]=false вместо true.
**Исправление:** номер партии проверяется для связанных действий; проверка
версии позиции ограничена атомарными действиями из J-01. Два согласия next
и place→ready могут исходить из одного состояния одной партии.
**Проверка:** новый тест зелёный, старые четыре воспроизведения по-прежнему
падают при снятии защиты; финальный e2e включает расстановку и запирание флота.

### Изменение существующего теста — названо отдельно

Первый полный e2e остановился в `tools/e2e-battleship.mjs:219`: «Случайно»
ожидало ровно `{t}`, получило `{t,seq}`. Это несовместимое ожидание теста после
добавления метаданных, не утечка флота. Теперь ассерт требует **ровно**
`matchNo/seq/t`, проверяет обе версии; флот, координаты и произвольные поля
по-прежнему запрещены. Ограничение «случайность только серверная» не ослаблено.
В промежуточном сообщении сначала ошибочно назвал этот тест нардами;
уточнено: морской бой. Исходные падения не скрыты.
