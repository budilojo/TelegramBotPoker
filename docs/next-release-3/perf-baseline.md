# L: изолированная исходная точка до правок приложения — 31.10.2026

Сохранённая исходная серия предыдущей попытки L (`c80080dd`), начата в
07:44:33 UTC. При продолжении `e1591183` проверены полный JSON, версия и
SHA-256; новый независимый повтор записан отдельно в `perf-data/suite-resume.json`
и описан в [perf-after.md](perf-after.md). Старые отчёты I/J/K не считаются
текущими измерениями L.

Версия приложения `11d086c031e7f912dbc904e8cdd861ac30809dc0`; SHA-256 измерителя `2784a69872e345bbf196a38adee1c833ba884bad16d6297ba03d92f69dd5fc8e`.

Только локальные HTTP/WS (127.0.0.1, случайные порты), временные SQLite,
подписанные тестовые личности и TelegramStub. .env/сервер/боевой Telegram не
используются. macOS 26.6.2 (Darwin 25.6.0) arm64, Node 24.12.0,
Playwright 1.63.0/Chromium; 10 логических ядер. Нет соседних тестов агента;
другая активность самой ОС не контролируется. Файлы ОС могут быть прогреты.

Команда: `node --expose-gc --disable-warning=ExperimentalWarning tools/perf-suite.mjs`.
Три повтора: каждый — новая SQLite; 14 свежих контекстов Chromium
(7 игр × CPU 1/4), 320×568, затем отдельные 120 секунд Node/WS с ботами.
20 refresh на экран; одно реально применённое действие на экран; обработка
состояния включает синхронную перерисовку. Никаких ограничений скорости pass/fail.

Нагрузка сервера: 10 шахматных столов/20 WS с refresh каждые ~250 мс и
7 приватных столов/7 WS с ботами уровня 1 (у покера/дурака/UNOQ два соперника),
действия человека выбираются только из собственного view. Законченные партии
повторяются, боты думают настоящим драйвером с обычными паузами и потоками.
Каждые ~10 секунд 10 шахматных страниц reconnect. Каждые ~10 секунд GC heap/RSS.
Считаются подготовки и исполнения SQLite; параметры и результаты SQL не пишутся.
Настроены семена карт/ботов/флотов, кости нард [5,3]; планирование реальных
потоков и таймеров делает число ходов разным — сравнивать нужно ещё и объём.

Метки **2/3** — текущие локальные запуски 31.10.2026 с TelegramStub.
**1** — изучение инструмента/кода; **4/5** — телефон, настоящая сеть/SDK,
GPU/нагрев, сервер и реальные операции не проверены. CPU ×4 не модель телефона.
Указанные три значения — три независимых повтора; медиана/разброс трёх первых
открытий не являются надёжным p95. Для выборок n<20 p95 в JSON близок к максимуму.

## Исходные данные и пределы

Полные сводные JSON: [suite-before](perf-data/suite-before.json),
[legacy-before](perf-data/legacy-before.json). В них n/min/median/p95/max,
long tasks, rAF интервалы, байты, запросы, CPU/память и временной ряд heap/RSS.
Числа байтов относятся к завершённым Resource Timing ресурсам без HTML и SDK;
локальный HTTP без сжатия не равен трафику Caddy/мобильной сети. HEAD/платежи
и настоящий Telegram не измерялись. Node CPU/RSS не включают дочерний Chromium.

Прогон ограничен 120 секундами за повтор (6 минут серии), не сутками.
Память инструмента/GC/истории партий влияет на heap. Нули после cleanup —
конкретные счётчики, не доказательство отсутствия любой утечки. Ёмкость боевого
сервера не измерена. Продолжение — [perf-after.md](perf-after.md).
