# J — матрица нескольких игроков, 31.10.2026

Исходная версия `6c732ea`, `redesign`; текущие проверки — в
[отчёте J](../codex-release/reports/multiplayer.md). Старые отчёты не являются
результатом этой матрицы. Реестр `bot/games/index.js` содержит семь игр.

Метки: **1** чтение; **2** текущий локальный запуск; **3** TelegramStub;
**4** нужна внешняя среда; **5** не проверено (причина/следующий шаг ниже).
Каждая заполненная локальная клетка ниже — **2/3**, а не проверка телефона.

Обозначения новых сценариев `bot/multiplayer.test.js` (48 тестов):

- **A** «две вкладки создают одно лобби, последнее место и повторный вход»:
  повтор создания, заполнение всех мест, конкурентные sit за последнее,
  отказ проигравшему словами; две вкладки одной личности, один стул, закрытие
  одной страницы не закрывает другую; новый вход восстанавливает роль.
- **B** «изоляция столов/групп, полномочия, уход хоста»: одновременно три стола
  одной игры в одном App, два из одной группы, третий из другой. Запрет join
  другой группы; не-хост с подменённым id/seat не меняет настройки/хоста,
  не удаляет и не завершает стол. Хост встаёт, возвращается из другой вкладки,
  передаёт права; старый хост больше не удаляет. Соседние столы целы.
- **C** «весь поток, подмена хода, настройки, разделы и reconnect»: игрок и
  зритель не ходят за другого; запрет словами и полная неизменность партии;
  настройки хоста/не-хоста; переход в хаб/закрытый рейтинг/обратно,
  часы не сдвигаются; новое подключение возвращает ту же роль/карты.
- **D** «завершение, новый стол двумя вкладками и старый код»: finish,
  конкурентный again с одним reqId создаёт один стол с копией настроек;
  старый гость остаётся в старом столе; удалённый код — NO_ROOM словами.
- **E** «два одинаковых хода одновременно и часы вне стола»: два запроса от
  двух страниц одной личности, ровно один принят, второму отказ; все уходят
  в хаб, FakeClock до срока вызывает ход/конец, место не дублируется.
- **F** «хост вышел из Telegram-группы»: событие left_chat_member, передача
  прав оставшемуся, обе страницы прежнего хоста теряют права; никакого
  предположения, что disconnect означает выход из Telegram-группы.
- **V** «старый пакет предыдущей партии не ходит в новой»: четыре дуэли,
  две отмены и повтора возвращают тот же цвет/сторону и начальный счётчик;
  старый seq не ходит; прежний matchNo со свежей seq тоже не ходит; новый ход проходит. До защиты четыре теста падали.
- **P** «непустые покупки и поддержка»: в тестовой SQLite покупка и обращение
  действительно существуют. Все семь игр, две страницы покупателя, соперник,
  зритель, разные группы. История своя после reconnect, подмена userId не
  даёт чужую; закрытые продажи не мешают истории; ashop игроку недоступен.
  Ни номера/платёж/payload/текст обращения не попадают другим и в группу.

**W** = `tools/e2e-multiplayer.mjs`: четыре независимых BrowserContext на игру
(хост ×2, соперник, зритель), **320×568 и 390×844**. Создание одновременно,
сесть/начать кнопками, роль/один стул, Telegram Back (заглушка), нижняя панель
→ настройки/рейтинг/игры → «Вернуться к столу», закрытие WS и автоматический
reconnect, reload и повторное открытие, неизменные часы. Сохраняются все
WS-кадры каждой страницы, включая до reconnect; проверяются id в счёте,
рука/ходы/флот зрителя и отсутствие серверных полей. Проверяется именно
`net.send`: версии позиции/партии отправлены, явная старая версия не перезаписана.

## Что именно проверено в приватности

`page()` нового теста сохраняет каждое сообщение каждой страницы, даже если
страницу закрыли; Table.pages для этого недостаточно (заменяет предыдущую
страницу личности). Проверки выполняются на каждом кадре, а ошибки callback
дополнительно проверяются через `t.errors`, поскольку Hub логирует исключения.

У карточных игр собственные карты сравниваются с настоящей рукой владельца,
у чужих — только открытые по правилам; колода/руки целиком не передаются.
В дуэлях нет Telegram id в score; legal только ходящему; флот зрителя скрыт
до конца. P проверяет непустые платёжные/личные данные, не только пустую базу.

Дополнительно `tools/fuzz-privacy.mjs all 10` в текущем запуске: 10 партий
каждой скрытой игры, 4.863 проверенных перерисовок. Для каждого вида меняется
всё, что ему знать нельзя; вид, карточка группы, хаб и личное напоминание
не должны измениться. Это проверка невмешательства, а не поиск одного поля.
Длинные игры, все специальные окончания/вскрытия/таймеры/откат/рестарт
дополнительно покрываются существующими профильными тестами текущего прогона.

## Границы (4/5)

Нет доказательств живых Telegram/iOS/Android: ввод пальцем, клавиатура,
системный Back, фон/пробуждение WebView, доставка сообщений/ссылок/шеринг
и настоящая мобильная сеть. После отдельно разрешённой выкатки владелец
проходит единый список `docs/next-release/owner-inputs.md`, п. 10, двумя
аккаунтами, двумя устройствами одного аккаунта и зрителем. Сервер/обслуживание
не опрашивались. Официальная тестовая и настоящая оплата/возврат не проверены.

Перечень атомарных positionActions объявлен в модуле каждой дуэли; контракт
добавлен в docs/game-hub.md. Ядро не перечисляет типы ходов игр.

Старые клиенты без seq сохраняют прежний протокол (проверки ply/turn/shot).
Новая защита межпартийных задержек действует для пакетов текущего клиента
с seq; она дополняет авторизацию и не делает seq подтверждением личности.
Смешанные версии в настоящем Telegram — внешний тест; после обновления
нужно заново открыть Mini App. Запрет ходить за другого остаётся серверным.
