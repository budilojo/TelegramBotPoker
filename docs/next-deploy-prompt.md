# Выкатка в прод

Этот файл не надо переписывать перед каждой выкаткой: в нём нет ни одного
хеша. Проверка «туда ли мы едем» делается не сравнением с записанным числом, а
вопросом к самому репозиторию: **нынешний коммит сервера должен принадлежать
нашей ветке.** Если да — мы просто двигаемся вперёд. Если нет — на сервере
что-то чужое, и это надо разобрать руками.

Схема базы не менялась (v5), новых зависимостей нет. Выкатка кодовая: ничего
не мигрирует и ничего не пересобирается.

**Что едет в этот раз — исправления аудита безопасности** (`docs/audit/findings.md`):

- **B-02, критическая:** любой человек из интернета, без Telegram, одним
  «кривым» сообщением ронял бота, а шестью за минуту — укладывал до ручного
  перезапуска. **Ради этого выкатку и делаем.**
- D-05 (покер мог зависнуть навсегда), B-01, C-01, E-01…E-05, G-01, G-02,
  I-01, D-01 — исправления из отчёта.
- Решения владельца: в играх на двоих лобби закрывает только хост (A-03);
  выход из группы больше не спасает от минуса в рейтинге — покер, дурак, UNOQ
  (D-02, D-03); не больше 10 партий с очками в плюс у одного человека в сутки
  (D-04).
- Сервер строже (H-01, H-02): бот слушает только `127.0.0.1` (снаружи — через
  Caddy), у юнита systemd предел памяти и дополнительная защита, база и
  бэкапы читает только сам бот, а `update.sh` в следующий раз сначала гоняет
  тесты на отдельной копии.
- **Морской бой в коде есть, но людям не виден** (пометка «черновик»): ни в
  хабе, ни в командах, ни в «Играх с ботами». Так и должно быть — он ещё не
  доделан.
- Если прошлая выкатка (шашки, нарды, покер с растущими блайндами, рассылка в
  группы) на сервер ещё не ездила — она едет тоже: шаг 1 покажет весь список.

**Важно про тесты на сервере.** Тестов теперь около 1000, среди них тяжёлые
проверки ботов. `update.sh` гоняет их на сервере **до** перезапуска: на слабом
сервере это **несколько минут**. Не прерывай `update.sh` и не пугайся тишины —
бот в это время на паузе.

**Этот раз — особенный для `update.sh`.** Скрипт копирует себя в начале работы,
поэтому сейчас выполнится ещё **прежняя** версия (тесты после `git reset`, юнит
systemd сам не ставится). Новый юнит и права на каталоги ставятся руками в
шаге 2; со следующей выкатки скрипт всё это делает сам.

## Шаг 1 — вы, в Telegram

```
/pause Обновляемся — вернёмся через пару минут
```

Игра замрёт целиком: у всех, кто за столом, экран с этим текстом, часы встанут
и ничей ход не сгорит.

**Если обслуживание уже включено с прошлого раза** — этот шаг пропускаете, бот
и так стоит. Проверить: админ-бот отвечает на любую команду строкой
«⏸ Идёт обслуживание».

## Шаг 2 — отдаёте Claude Code всё, что ниже разделителя

---

Выкати на сервер новую версию. Обслуживание я уже включил через админ-бота —
сам его не трогай и не снимай.

Уже проверено на последнем коммите ветки `redesign`, перепроверять не надо:
схема базы не меняется (v5), новых зависимостей нет, `npm test` — около 1000
тестов без падений, e2e (покер, дурак, админка, шахматы, шашки, нарды, игры с
ботами и школа покера), вёрстка и кит — зелёные; `update.sh` прогнан в
песочнице с заглушками (оба случая: тесты упали / прошли). Новый юнит systemd
на настоящем systemd **не запускался** — поэтому шаг 2 ставит его осторожно,
с копией старого.

**0. Выровняй ветки (на моём Mac, в папке проекта).** Сервер ездит по ветке
`claude/bold-carson-kjswyx` (её по умолчанию берёт `deploy/update.sh`), а вся
работа лежит в `redesign`. Ветка сервера — предок `redesign`, поэтому её можно
просто подвинуть вперёд, не трогая настройки сервера.

```
git fetch origin
git merge-base --is-ancestor origin/claude/bold-carson-kjswyx origin/redesign && echo "можно двигать вперёд — ок" || echo "НЕ ПРЕДОК — стоп"
git log --oneline origin/claude/bold-carson-kjswyx..origin/redesign | cat
git log --oneline -1 origin/redesign
```

Покажи мне, сколько коммитов поедет и какая вершина. **Остановись и спроси
меня**, если ветка сервера не предок `redesign`. Если всё в порядке:

```
git push origin origin/redesign:claude/bold-carson-kjswyx
```

Только обычный push, **без `--force`**: если git откажет, не обходи отказ —
покажи мне вывод.

**1. Осмотрись на сервере, ничего не меняя.**

```
systemctl is-active worldcard
sudo -u worldcard git -C /opt/worldcard fetch origin claude/bold-carson-kjswyx
sudo -u worldcard git -C /opt/worldcard log --oneline -1
sudo -u worldcard git -C /opt/worldcard merge-base --is-ancestor HEAD origin/claude/bold-carson-kjswyx && echo "коммит сервера в нашей ветке — ок" || echo "ЧУЖОЙ КОММИТ — стоп"
sudo -u worldcard git -C /opt/worldcard log --oneline HEAD..origin/claude/bold-carson-kjswyx | cat
sudo -u worldcard git -C /opt/worldcard status --short
ls -la /opt/worldcard/backups/ | tail -3
df -h /
```

Покажи мне: какой коммит сейчас (запомни его — он нужен для отката), что
именно приедет (список), и чисто ли рабочее дерево. **Остановись и спроси
меня**, если: коммит сервера не из нашей ветки, в рабочем дереве есть
изменения, или приезжать нечего (уже вершина).

**2. Обнови.**

```
sudo /opt/worldcard/deploy/update.sh claude/bold-carson-kjswyx
```

Скрипт сам снимает бэкап базы, забирает ветку, ставит зависимости
(`npm ci --omit=dev`), **гоняет тесты на сервере** и только потом
перезапускает. Если тесты упадут — он не перезапустит бота; ничего не чини на
ходу, покажи мне вывод.

Потом — юнит systemd и права на каталоги. Сначала запомни, как бот работает
сейчас, и покажи разницу юнитов:

```
systemctl show worldcard -p MainPID -p NRestarts
sudo ss -ltnp 'sport = :8080'
diff /etc/systemd/system/worldcard.service /opt/worldcard/deploy/worldcard.service
```

Жду в diff только такие отличия (и комментарии к ним):
`StartLimitBurst` / `StartLimitIntervalSec` в `[Unit]` (если прошлая выкатка не
ставила юнит), `Environment=BIND_HOST=127.0.0.1`, `PrivateDevices`,
`ProtectKernelTunables`, `ProtectKernelModules`, `ProtectControlGroups`,
`RestrictAddressFamilies`, `RestrictSUIDSGID`, `LockPersonality`,
`MemoryHigh`, `MemoryMax`. **Если в diff есть что-то ещё — остановись и
покажи мне**: значит, юнит на сервере правили руками.

Если всё так — поставь, **сохранив старый** (он нужен для отката):

```
sudo cp /etc/systemd/system/worldcard.service /root/worldcard.service.before-audit
sudo install -m 644 /opt/worldcard/deploy/worldcard.service /etc/systemd/system/worldcard.service
sudo systemctl daemon-reload
sudo chmod 700 /opt/worldcard/data /opt/worldcard/backups
sudo systemctl restart worldcard
sleep 3
systemctl is-active worldcard
systemctl show worldcard -p StartLimitBurst -p StartLimitIntervalUSec -p MemoryMax
sudo ss -ltnp 'sport = :8080'
stat -c '%a %U %n' /opt/worldcard/data /opt/worldcard/backups
```

Жду: `active`; `StartLimitBurst=5`, `StartLimitIntervalUSec=1min`,
`MemoryMax=629145600`; порт 8080 слушается на **`127.0.0.1:8080`** (а не
`0.0.0.0` или `*`); права `700 worldcard` у обоих каталогов.

**Если бот с новым юнитом не поднялся** (`failed` / `activating`) — сразу верни
старый юнит и покажи мне журнал, код не трогай:

```
sudo install -m 644 /root/worldcard.service.before-audit /etc/systemd/system/worldcard.service
sudo systemctl daemon-reload
sudo systemctl restart worldcard
journalctl -u worldcard -n 80 --no-pager
```

**3. Проверь, что живое.**

```
systemctl is-active worldcard
journalctl -u worldcard -n 50 --no-pager
curl -s -o /dev/null -w '%{http_code}\n' https://<домен>/health
curl -s https://<домен>/health
curl -s -o /dev/null -w '%{http_code}\n' https://<домен>/colors/R5.svg
curl -s -o /dev/null -w '%{http_code}\n' https://<домен>/chess/wK.svg
curl -s -o /dev/null -w '%{http_code}\n' https://<домен>/chess.css
curl -s -o /dev/null -w '%{http_code}\n' https://<домен>/solo.js
curl -s -o /dev/null -w '%{http_code}\n' https://<домен>/school.js
curl -s -o /dev/null -w '%{http_code}\n' https://<домен>/games/checkers.js
curl -s -o /dev/null -w '%{http_code}\n' https://<домен>/games/nardy.js
curl -s -o /dev/null -w '%{http_code}\n' https://<домен>/checkers.css
curl -s -o /dev/null -w '%{http_code}\n' https://<домен>/nardy.css
curl -s https://<домен>/tokens.css | grep -c 'color-success'
sudo -u worldcard sqlite3 -readonly /opt/worldcard/data/bot.db "SELECT value FROM meta WHERE key='schema';"
curl -s -o /dev/null -w '%{http_code}\n' --max-time 5 http://<IP сервера>:8080/health || echo "снаружи 8080 закрыт — так и надо"
```

И главное — **критическая ошибка B-02 закрыта**. Проверка шлёт боту те самые
кривые кадры, которыми его раньше роняли (подпись Telegram не нужна — как и
нападающему). Запусти только **после** обновления: на старом коде она уронила
бы бота.

```
systemctl show worldcard -p MainPID -p NRestarts
sudo -u worldcard node /opt/worldcard/tools/check-bad-frames.mjs ws://127.0.0.1:8080/ws
systemctl show worldcard -p MainPID -p NRestarts
```

Жду последнюю строку `B-02: бот кривыми кадрами не роняется — ок`, а `MainPID`
и `NRestarts` **до и после — одинаковые** (бот не перезапускался).

Жду: сервис active, в логах нет ошибок (и нет строк про `Memory` или
`Permission denied` — это был бы новый юнит), `/health` отдаёт 200, картинки
`/colors/R5.svg` и `/chess/wK.svg` и файлы `/chess.css`, `/solo.js`,
`/school.js`, `/games/checkers.js`, `/games/nardy.js`, `/checkers.css`, `/nardy.css`
отдаются 200, в
`tokens.css` строка `color-success` встречается хотя бы раз (новая палитра
приехала), версия схемы равна **5** — она не должна меняться.

Две тонкости в этой команде, обе стоили нам по нескольку выкаток:

- **версию схемы хранит строка `schema` в таблице `meta`** (`bot/store.js`),
  а не `PRAGMA user_version` — тот у нас всегда 0;
- **база лежит в `data/bot.db`**, а не в корне приложения (`deploy/install.sh`,
  `DB_PATH`). На несуществующем пути `sqlite3` молча создаёт пустую базу, и
  `SELECT` из неё вернёт пустую строку — выглядит ровно так, будто миграция не
  прошла. `-readonly` это предотвращает и заодно ручается, что проверка живой
  базы ничего в неё не запишет.

**4. Доложи и остановись.**

Скажи: какой коммит теперь, сколько тестов прошло на сервере, что в логах, что
ответил `/health`, на каком адресе слушается 8080, права каталогов и итог
проверки B-02 (с `MainPID`/`NRestarts` до и после). **Обслуживание не снимай** — его сниму я, когда проверю
бота руками.

**Если что-то пошло не так — откат** (подставь коммит, который был на сервере
до обновления, ты его показал на шаге 1):

```
sudo -u worldcard git -C /opt/worldcard reset --hard <коммит до обновления>
sudo -u worldcard npm --prefix /opt/worldcard ci --omit=dev
sudo install -m 644 /root/worldcard.service.before-audit /etc/systemd/system/worldcard.service
sudo systemctl daemon-reload
sudo systemctl restart worldcard
```

(Права `700` на `data/` и `backups/` оставь — старому коду они не мешают.)
**Помни: откат возвращает и критическую ошибку B-02.** Откатывайся, только
если бот не работает, и скажи мне.

База не трогается: схема не менялась, старый код читает её как читал. Бэкап
всё равно лежит в `/opt/worldcard/backups/`.

**Откатывай, пока обслуживание включено** — тогда ни одного стола новых игр
и ни одной партии с ботами ещё нет: при обслуживании столы не создаются. Столов
морского боя не будет вовсе — он скрыт. Если
откат нужен уже после `/resume` — не откатывай сам, сначала скажи мне. Старый
код не знает игр `checkers` и `nardy`, а столы с ботами (`chat_id` вида
`solo:…`) примет за группы. Сколько таких столов, покажет
`sudo -u worldcard sqlite3 -readonly /opt/worldcard/data/bot.db "SELECT game, count(*) FROM rooms WHERE game IN ('checkers','nardy') OR chat_id LIKE 'solo:%' GROUP BY game;"`,
а решение об их закрытии — за мной.

Чего не делать: не создавать pull request, не пушить ничего, кроме
fast-forward ветки сервера на шаге 0, не переключать сервер на другую ветку,
не открывать и не показывать `.env`, не снимать обслуживание, не править код
на сервере.

## Шаг 3 — снова вы

Когда Claude Code доложит, снимите обслуживание:

```
/resume
```

И проверьте руками на телефоне — то, что заглушкой Telegram не проверить:

**Исправления аудита**
1. Игра работает как раньше: открыть хаб, создать лобби, сыграть пару ходов.
2. Покер, последняя раздача, когда олл-ин кончает игру (C-01): сначала стол и
   открытие борда, потом раздача фишек, и только потом итоги — итоги не
   появляются раньше ривера.
3. Шахматы, шашки или нарды вдвоём: гость в лобби не может закрыть лобби хоста,
   может только встать (A-03).
4. Дурак втроём: один выходит из группы посреди партии — в группе «он дурак,
   остальным партия засчитана», а не «партия прервана» (D-03).
5. В хабе группы и в «Играх с ботами» **нет морского боя**, команда
   `/battleship` в группе ничего не создаёт.
6. `/help` (в справке нет названий игр), старые столы открываются.

**Если вместе с этим ехала прошлая выкатка** (шашки, нарды, покер) — проверьте и её:

7. Покер: у карт нет слова «null»; Fold есть всегда (при бесплатном Check —
   со второго нажатия «Fold anyway?»); суммы Raise ровные по блайндам;
   «Рост блайндов» в настройках, «ур. 1» в шапке.
8. Шашки (`/checkers`, два аккаунта): обязательное взятие, серия по шагам,
   дамка, перетаскивание пальцем, ничья, сдача, откат, часы.
9. Нарды (`/nardy`, два аккаунта): оба видят одни кубики, «Вернуть» и
   «Готово», голова, шесть подряд, снятие только из дома.
10. `/bot` в личке: шашки и нарды против бота; «Сыграть ещё».
11. Пульт → «Рассылка» → «все группы»: **не отправляйте, пока не проверили
    «Сначала себе».**

Если что-то не так — `/pause` обратно и зовите меня: откат занимает минуту.
