# Выкатка в прод

Этот файл не надо переписывать перед каждой выкаткой: в нём нет ни одного
хеша. Проверка «туда ли мы едем» делается не сравнением с записанным числом, а
вопросом к самому репозиторию: **нынешний коммит сервера должен принадлежать
нашей ветке.** Если да — мы просто двигаемся вперёд. Если нет — на сервере
что-то чужое, и это надо разобрать руками.

Схема базы не менялась (v5), новых зависимостей нет. Выкатка кодовая: ничего
не мигрирует и ничего не пересобирается. Шахматные столы лежат в базе тем же
JSON, что и столы других игр; старые столы читаются как читались.

**Что едет в этот раз** (всё, что накопилось с прошлой выкатки): редизайн
фаз 1–7 (новая палитра, плоский стиль), «+ Ещё один стол в эту группу»,
UNOQ на новом ките, **шахматы** — первая игра на двоих, с часами, ничьей,
перетаскиванием фигур и анимацией хода, и несколько лобби одного хоста в
играх на двоих.

## Шаг 1 — вы, в Telegram

```
/pause Обновляемся — вернёмся через пару минут
```

Игра замрёт целиком: у всех, кто за столом, экран с этим текстом, часы встанут
и ничей ход не сгорит.

**Если обслуживание уже включено с прошлого раза** — этот шаг пропускаете, бот
и так стоит. Проверить: админ-бот отвечает на любую команду строкой
«⏸ Идёт обслуживание».

## Шаг 2 — отдаёте Claude Code всё, что ниже разделителя

---

Выкати на сервер новую версию. Обслуживание я уже включил через админ-бота —
сам его не трогай и не снимай.

Уже проверено на последнем коммите ветки `redesign`, перепроверять не надо:
схема базы не меняется (v5), новых зависимостей нет, `npm test` — 607 тестов
без падений, e2e (покер, дурак, админка, шахматы), вёрстка, проверка экрана
UNOQ, контраст и кит — зелёные.

**0. Выровняй ветки (на моём Mac, в папке проекта).** Сервер ездит по ветке
`claude/bold-carson-kjswyx` (её по умолчанию берёт `deploy/update.sh`), а вся
работа лежит в `redesign`. Ветка сервера — предок `redesign`, поэтому её можно
просто подвинуть вперёд, не трогая настройки сервера.

```
git fetch origin
git merge-base --is-ancestor origin/claude/bold-carson-kjswyx origin/redesign && echo "можно двигать вперёд — ок" || echo "НЕ ПРЕДОК — стоп"
git log --oneline origin/claude/bold-carson-kjswyx..origin/redesign | cat
git log --oneline -1 origin/redesign
```

Покажи мне, сколько коммитов поедет и какая вершина. **Остановись и спроси
меня**, если ветка сервера не предок `redesign`. Если всё в порядке:

```
git push origin origin/redesign:claude/bold-carson-kjswyx
```

Только обычный push, **без `--force`**: если git откажет, не обходи отказ —
покажи мне вывод.

**1. Осмотрись на сервере, ничего не меняя.**

```
systemctl is-active worldcard
sudo -u worldcard git -C /opt/worldcard fetch origin claude/bold-carson-kjswyx
sudo -u worldcard git -C /opt/worldcard log --oneline -1
sudo -u worldcard git -C /opt/worldcard merge-base --is-ancestor HEAD origin/claude/bold-carson-kjswyx && echo "коммит сервера в нашей ветке — ок" || echo "ЧУЖОЙ КОММИТ — стоп"
sudo -u worldcard git -C /opt/worldcard log --oneline HEAD..origin/claude/bold-carson-kjswyx | cat
sudo -u worldcard git -C /opt/worldcard status --short
ls -la /opt/worldcard/backups/ | tail -3
df -h /
```

Покажи мне: какой коммит сейчас (запомни его — он нужен для отката), что
именно приедет (список), и чисто ли рабочее дерево. **Остановись и спроси
меня**, если: коммит сервера не из нашей ветки, в рабочем дереве есть
изменения, или приезжать нечего (уже вершина).

**2. Обнови.**

```
sudo /opt/worldcard/deploy/update.sh claude/bold-carson-kjswyx
```

Скрипт сам снимает бэкап базы, забирает ветку, ставит зависимости
(`npm ci --omit=dev`), **гоняет тесты на сервере** и только потом
перезапускает. Если тесты упадут — он не перезапустит бота; ничего не чини на
ходу, покажи мне вывод.

**3. Проверь, что живое.**

```
systemctl is-active worldcard
journalctl -u worldcard -n 50 --no-pager
curl -s -o /dev/null -w '%{http_code}\n' https://<домен>/health
curl -s https://<домен>/health
curl -s -o /dev/null -w '%{http_code}\n' https://<домен>/colors/R5.svg
curl -s -o /dev/null -w '%{http_code}\n' https://<домен>/chess/wK.svg
curl -s -o /dev/null -w '%{http_code}\n' https://<домен>/chess.css
curl -s https://<домен>/tokens.css | grep -c 'color-success'
sudo -u worldcard sqlite3 -readonly /opt/worldcard/data/bot.db "SELECT value FROM meta WHERE key='schema';"
```

Жду: сервис active, в логах нет ошибок, `/health` отдаёт 200, картинки
`/colors/R5.svg` и `/chess/wK.svg` и файл `/chess.css` отдаются 200, в
`tokens.css` строка `color-success` встречается хотя бы раз (новая палитра
приехала), версия схемы равна **5** — она не должна меняться.

Две тонкости в этой команде, обе стоили нам по нескольку выкаток:

- **версию схемы хранит строка `schema` в таблице `meta`** (`bot/store.js`),
  а не `PRAGMA user_version` — тот у нас всегда 0;
- **база лежит в `data/bot.db`**, а не в корне приложения (`deploy/install.sh`,
  `DB_PATH`). На несуществующем пути `sqlite3` молча создаёт пустую базу, и
  `SELECT` из неё вернёт пустую строку — выглядит ровно так, будто миграция не
  прошла. `-readonly` это предотвращает и заодно ручается, что проверка живой
  базы ничего в неё не запишет.

**4. Доложи и остановись.**

Скажи: какой коммит теперь, сколько тестов прошло на сервере, что в логах, что
ответил `/health`. **Обслуживание не снимай** — его сниму я, когда проверю
бота руками.

**Если что-то пошло не так — откат** (подставь коммит, который был на сервере
до обновления, ты его показал на шаге 1):

```
sudo -u worldcard git -C /opt/worldcard reset --hard <коммит до обновления>
sudo -u worldcard npm --prefix /opt/worldcard ci --omit=dev
sudo systemctl restart worldcard
```

База не трогается: схема не менялась, старый код читает её как читал. Бэкап
всё равно лежит в `/opt/worldcard/backups/`.

**Откатывай, пока обслуживание включено** — тогда ни одного шахматного стола
ещё нет (при обслуживании столы не создаются). Если откат нужен уже после
`/resume` и шахматные столы появились — не откатывай сам, сначала скажи мне:
старый код не знает игру `chess` и либо пропустит такой стол с записью в лог,
либо оживит его как битый покерный. Столы надо сперва закрыть (`/cancel`).

Чего не делать: не создавать pull request, не пушить ничего, кроме
fast-forward ветки сервера на шаге 0, не переключать сервер на другую ветку,
не открывать и не показывать `.env`, не снимать обслуживание, не править код
на сервере.

## Шаг 3 — снова вы

Когда Claude Code доложит, снимите обслуживание:

```
/resume
```

И проверьте руками, по порядку. Первые два пункта — то, что заглушкой не
проверяется в принципе: они про живой телефон и живую связь.

1. Откройте приложение **из лички бота**, зайдите за стол, выключите и снова
   включите интернет на телефоне — кнопка «← Все игры группы» должна остаться
   на месте, а не пропасть.
2. **Шахматы пальцем на телефоне.** Нажмите на фигуру — в центре клеток, куда
   можно сходить, появятся точки. Потяните фигуру: она идёт за пальцем чуть
   выше него, страница под ней не прокручивается; отпустите на клетке с точкой —
   ход сделан. Отпустите не туда — фигура вернётся. Если фигура «залипает» или
   страница дёргается — напишите, на каком телефоне.
3. `/game` → в хабе **четыре игры: Покер, Дурак, UNOQ, Шахматы**; иконки
   разные.
4. Общий вид: плоский тёмный фон, тёмно-изумрудная кнопка без неонового
   свечения, «Ваш ход» читается, зелёная кнопка не сливается с сукном на
   покерном и дурацком столах.
5. **Шахматы вдвоём** (два аккаунта): создайте стол с часами, второй
   присоединяется, сыграйте несколько ходов. У соперника фигура скользит на
   новую клетку; часы идут у того, чей ход; «Ничья» → «Принять»; «Сдаться».
   В конце в группе одно сообщение «ИТОГИ · ШАХМАТЫ», а карточка стола не
   меняется на каждом ходу.
6. **Два стола одного хоста:** создайте шахматное лобби дважды подряд — должно
   получиться два стола и две карточки в группе. Потом `/cancel` без кода —
   бот должен спросить, какую из игр, и перечислить коды; `/cancel КОД` —
   удалит только названную.
7. В UNOQ доведите кого-то до одной карты и **не нажимайте «UNOQ!»** — у
   остальных должна появиться кнопка «🫵 Поймал! <имя> молчит» со словами и
   отсчётом, а на аватаре молчуна — красная метка.
8. Нажмите **UNOQ** в хабе → шторка должна спрашивать про **накопление «+2»** и
   таймер. Если там «подкидной или переводной» — старая версия, зовите меня.
9. Кнопка **«Рейтинг игроков»** — с меткой «скоро», по нажатию объяснение, а не
   таблица.
10. Завершите игру UNOQ — итоги подписаны **«ИТОГИ · UNOQ»**, а не «РАДУГА».
11. `/help` — в справке не должно быть названий игр вообще.
12. Старый покерный или дурацкий стол, если остался, открывается как раньше.

Если что-то не так — `/pause` обратно и зовите меня: откат занимает минуту.
