# B — магазин, платежи, права и возвраты

Используй 01-common.md; сначала прочитай результат A и текущий каталог/примерку. Подготовить реальные покупки косметики за Telegram Stars в этом релизе. Реальные счета и операции не выполнять. Старый отклонённый магазин не восстанавливать вслепую: сделать понятный путь «вещь → примерить → состав/цена/условия → купить → результат → надеть». Только косметика; без подписок, подарков, продажи фишек и влияния на игру.

Сначала опиши контракт и состояния в docs/next-release/payment-design.md: заказ, неизменяемые товар/цена/валюта/покупатель, платёж, выдача прав, возврат, повторные события, сверка и ошибки. Сервер — источник цены и прав. Клиентский статус окна оплаты не подтверждает покупку. Выдача только по проверенному successful_payment; сверка покупателя, payload, суммы, валюты и товара. Проверка pre_checkout в срок Telegram. Уникальность платёжного идентификатора, идемпотентность, транзакционность и восстановление между оплатой и выдачей обязательны. Не держать транзакцию SQLite во время сетевого запроса.

Серверные права на вещи и выбранный вид сохраняются между устройствами; localStorage не доказывает покупку. Примерка временная, не даёт постоянных прав. Существующий админский/тестерский доступ учитывать отдельно от покупки. Заранее определить поведение набора и уже купленных его частей: исключить случайную повторную оплату одной вещи. Цены владельцем не утверждены — сделать конфигурацию, не запускать продажу со старыми A/B-ценами.

Возврат: сверка владельца платежа, права администратора, подтверждение конкретной операции, полный возврат по поддерживаемому API, запрет двойного возврата, безопасный повтор после таймаута и сверка результата. Отзыв соответствующих прав и снятие вещи без отзыва независимой покупки/другого источника права. Обработать поддерживаемые Telegram события возврата/спора. Лог операций без секретов, доступ владельцу, история покупок пользователю и поддержка через кнопки плюс /paysupport. Контакт пока неизвестен — обязательное условие открытия продаж.

Проверить: успех, отмена, недостаток Stars, двойное нажатие/событие, подмена цены/товара/покупателя, чужой/пересланный счёт, устаревший счёт, товар скрыт, повторная покупка, набор с пересечениями, обрыв до/после оплаты, падение до/после выдачи, восстановление из базы, возврат надетой вещи, повторный возврат, таймаут API и поздний результат. Неподтверждённый платёж не выдаёт вещь. Режим остановки новых продаж не должен ломать обработку уже совершённых оплат, историю, сверку и возвраты.

Нужны серверные тесты через стенд, «на зубы» на каждую новую защиту и браузерный путь на 320/390 px. При возможности проверить в официальной тестовой среде Telegram без реальных средств; если доступа нет — честно записать блокер. Проверить резервирование, восстановление и совместимость отката: старая версия не должна терять или игнорировать платежи. Описать безопасную последовательность отката при несовместимости, не считать добавление таблиц достаточным доказательством.

Включение продаж отдельным серверным выключателем: по умолчанию закрыто до заполнения обязательных сведений, готовности товаров/цен, внешних проверок и разрешённой выкатки. Подготовка платежей должна быть полной, заглушки — только в тестах. Не называть такую подготовку уже запущенными продажами.
