# Подготовка релиза с покупками — как запустить агентов

Задания A–E лежат рядом (`02-law.md` … `06-release-check.md`), план — `00-plan.md`, общая часть — `01-common.md`.
Запуск делает `tools/release-run.mjs`: **по очереди** A → B → C → D → E (как требует план, без параллельности).
Реальных счетов, платежей, возвратов и выкатки на сервер запуск не делает и делать не должен.

## Одна команда (Mac, папка проекта, ветка `redesign`, дерево чистое)

```
cd ~/TelegramBotPoker && git pull origin redesign && node tools/release-run.mjs
```

Сначала можно проверить без запуска агентов: `node tools/release-run.mjs --dry-run`.
Состояние: `node tools/release-run.mjs --status`.

## Что происходит

1. Проверки: Node ≥ 22.5, `git`, `claude` с нужными параметрами, ветка `redesign`, чистое дерево, `origin` доступен и не ушёл вперёд, манифест корректен, нет второго запуска.
2. Создаётся отдельная рабочая копия `../TelegramBotPoker-release` на ветке `release/run` (от `origin/redesign`). Основная папка не меняется.
3. Шаги идут по одному, каждый — `claude -p --agent release-<имя>`: A `law`, B `payments`, C `navigation`, D `rating`, E `check`. Агент пишет отчёт `docs/next-release/reports/<id>.md` и статус `<id>.status.json`, коммитит, но не пушит.
4. После каждого шага скрипт проверяет свежий статус и чистое дерево, сам прогоняет `npm test`. Красный — остановка, ничего не публикуется. Зелёный — один обычный `git push origin release/run:redesign` (без `--force`).
5. `done` — идём дальше. `partial` и `blocked` — остановка (после `partial` можно продолжить с `--continue-partial`). Упёрлись в лимит использования — остановка с пояснением; та же команда после сброса лимита продолжит с места остановки и попытку не тратит.

## По шагам вручную

`node tools/release-run.mjs --only law` — только A (предыдущие шаги должны быть выполнены). Так можно смотреть результат после каждого шага.

## Параметры

`--no-push` (не публиковать), `--model <модель>` (перекрывает модели из `.claude/agents/release-*.md`: B, E и A — `opus`, C, D — `sonnet`),
`--permission-mode <режим>` (по умолчанию `auto`), `--agent-timeout-min N` (по умолчанию 240), `--continue-partial`.

## Что получится и что нет

Итог — `docs/next-release/release-readiness.md` (E) с решениями «готово / не готово» отдельно для кода, бесплатных функций, открытия продаж и рейтинга, единым списком для владельца и телефонным чек-листом.
Единый список недостающих фактов ведётся в `owner-inputs.md`. Продажи остаются закрыты серверным выключателем до заполнения обязательных сведений и отдельно разрешённой выкатки.

Определения агентов — `.claude/agents/release-*.md`; журналы запуска — `.release-run/logs/` (в git не попадает).
