# Отчёт B (payments) — покупки косметики за Stars, 2026-10-29

**Итог: подготовлено, не запущено.** Код и проверки готовы; продажи закрыты серверным выключателем по умолчанию.
Реальных счетов, оплат и возвратов не было; платёжный API Telegram — только заглушка в тестах. На сервер не ходил.
Статус — `partial`: в тестовой среде Telegram и на телефоне ничего не проверено (доступа нет), а без этого
(условие У-7) готовность покупок заявлять нельзя.

## Что сделано (простыми словами)

- **Контракт** — `docs/next-release/payment-design.md`: заказ, проверка перед оплатой, выдача, права, возврат,
  сверка с Telegram, журнал, совместимость и откат, резервная копия, решения B-1…B-8.
- **Что продаётся:** только «Графит» (рубашка, стол, знак, комплект). «Ночной казино-клуб» не продаётся (О-13).
  Цены — в `bot/payments/offers.json`; сейчас **пусто** и «не утверждено»: старые демо- и A/B-цены не используются.
- **Выключатель:** по умолчанию закрыто. `SALES_MODE=test` — только вместе с `TG_TEST_ENV=1` (тестовая среда Telegram,
  звёзды ненастоящие). `SALES_MODE=live` откроется, только если утверждены цены, задан контакт поддержки
  (`PAY_SUPPORT`) и документы в `legal/` «Действует» без пустых полей; иначе бот называет причины в `/sales`.
  Владелец может остановить новые продажи `/salesstop` — выдача уже оплаченного, история, сверка и возвраты работают.
- **Путь игрока:** «Настройки» → «Коллекции» → вещь → «Примерить» → на карточке состав, цена, «Условия покупки»,
  «Правила возврата» → «Купить за N ⭐» → окно Telegram → «Куплено» → переключатель «надеть». «Мои покупки» с номерами
  заказов и кнопкой «Написать в поддержку» (бот присылает ответ в личку); `/paysupport` и `/terms` в личке.
- **Сервер:** вещь выдаётся **только** по `successful_payment` после сверки покупателя, суммы, валюты, заказа и вещи —
  одной транзакцией базы, без сети внутри. Повтор события ничего не удваивает (уникальный id платежа). Перед оплатой
  (`pre_checkout_query`) — только проверки в базе и один ответ Telegram. Окно «оплачено» на странице вещь не выдаёт.
- **Возврат:** только владелец, в личке игрового или админ-бота, двумя шагами: `/refund <заказ>` → код → `/refund
  <заказ> <код>`. Полный возврат через `refundStarPayment`, права и надетый вид снимаются (не трогая доступ тестера).
  Второй возврат невозможен; после таймаута повтор сначала сверяет с Telegram. `refunded_payment` тоже снимает права.
- **Сверка** (`getStarTransactions`) при запуске и `/reconcile`: подбирает оплаты, пропущенные при простое или откате,
  и возвраты, сделанные мимо бота.
- **Прод при выкатке с настройками по умолчанию не меняется:** коллекции никому не видны, тестерского доступа нет,
  счетов нет. Новое — команды `/paysupport`, `/terms` и подписка бота на `pre_checkout_query`.

## Решения, которые я принял сам

- B-1: комплект не продаётся, если часть уже есть (цены «дополнения» нет) — недостающее по одной.
- B-2: если вещь уже доступна (в т. ч. тестеру), купить её нельзя.
- B-3: неоплаченный счёт живёт 15 минут; сменилась цена или версия условий — оплатить старый счёт нельзя.
- B-4: автоматических возвратов нет, даже при несовпадении — только уведомление владельцу.
- B-5…B-8: тестовый режим только в тестовой среде; тестерский доступ только при включённом режиме; команды владельца в
  обоих ботах; заказ, которого нет в базе (ранняя копия), восстанавливается сверкой только по текущей цене.
- Старый тест «нет выдуманной оплаты» (`bot/collections.client.test.js`) охраняет демо-экраны и не тронут; слово
  «Купить» живёт в новых `purchase.js`/`pay.js`, их охраняют новые тесты. Из комментария `item.js` слово убрал.
- В `tools/graphit-server-teeth.mjs` и `graphit-client-teeth.mjs` обновил три места поломки: код, который они ломают,
  сдвинулся. Одно из них показало дыру: проверка права в `choiceOf` перестала охраняться — убрал ранний выход, теперь
  все 9 и 12 поломок снова ловятся.

## Что НЕ проверено (честно)

- **Тестовая среда Telegram** — доступа нет (нужны тестовый аккаунт и тестовый бот владельца). Это блокер У-7.
- **Живой Telegram и телефон:** настоящее окно `openInvoice`, что показывает Telegram при нехватке звёзд, приходят ли
  `refunded_payment` после нашего возврата, формат ответа `refundStarPayment` на повтор (я рассчитываю на
  `CHARGE_ALREADY_REFUNDED` — по описанию, не по прогону), успевает ли ответ на pre_checkout за 10 секунд на сервере,
  вид экранов на телефоне.
- **Откат:** старая версия на базе с таблицами `pay_*` не запускалась; что она их не трогает — вывод из кода
  (`CREATE TABLE IF NOT EXISTS`, версия схемы та же). Порядок безопасного отката описан в `payment-design.md`, раздел 11.
- **Споры (chargeback):** отдельного события боту нет; сверка показывает незнакомые исходящие — разбирать вручную.
- Правовая часть — по документам A; юридической вычитки нет.
