# Контракт A → B → C → D (31.10.2026)

Статус: решение исполнителя A на основе текущего кода и утверждённого 01-design.md.
Это контракт реализации следующих этапов, **не заявление об уже готовых 54 товарах**.
Исходная версия 1781699. Аудит/исправление A — [audit.md](audit.md).

Расширять `miniapp/collections/catalog.js`, `bot/collections/index.js` и существующие
`collection_choice`, `collection_req`, `pay_entitlement`, `shop_grant`.
Не создавать v2-store/кошелёк/параллельные покупки. `miniapp/cosmetics/catalog.js`
остаётся архивом nc-* и спроса, не смешивается с коллекциями и не определяет права.

Машиночитаемый перечень всех **54 предметов и 6 комплектов** —
[item-plan.json](item-plan.json). Это исходный договор B/C, не runtime-каталог.
Все 60 id перечислены явно; не переименовывать их после B. Шесть collection id:
`sever`, `obsidian`, `chertezh`, `terracotta`, `orbita`, `porcelain`.
Названия/описания можно уточнить по-русски без изменения слотов/состава/объёма.
`colors` — настоящий id UNOQ в обоих существующих реестрах игр; `unoq` не id игры.

Каждая запись: `id`, `collection`, `kind:item|bundle`, `slot` (null у набора),
`games`, `visibility`, `title`, `description`, `price:null`, `readiness`,
`artSource`, `assets:{preview,game}`. Набор дополнительно `includes` — ровно
девять id своей коллекции, без вложенных комплектов. readiness последовательно
`planned` → `art-ready` → `integrated`; никакого «готово» только по записи каталога.
Для Графита прежние `id`, `slot`, `color` и `includes` неизменны; общие функции
`itemById`, `slotOf`, `itemsOfBundle` расширяются, не заменяются по префиксу.

Имена новых серверных слотов совпадают с этой таблицей. Девять слотов доступны
независимо; `cardback` и `table` — расширения существующих. Прежний `profile`
остаётся совместимым парным оформлением Графита (рамка + знак), не превращается
в новый id/два платных товара. Явные v2 frame/badge перекрывают только свой
компонент; при отсутствии новой записи действует старый profile. «Снять» новый
компонент должно давать классику, а не внезапно возвращать старый Графит:
для этих двух новых слотов допустима явная запись `base-frame` / `base-badge`
с `color:'classic'` в collection_choice. Это бесплатные служебные значения,
не товары/покупки, наружу превращаются в null. Применение прежнего profile
атомарно удаляет эти два override и снова включает прежнюю пару. Старую строку
profile не стирать при выборе нового компонента — она нужна для rollback.

Рамки/значки v2 видны также **во время игры** во всех семи играх — это расширение
прежнего ограничения SPEC Графита. Собственный старый Графит сохраняет прежний
вид/места; не надо глобально возвращать архивную рамку nc-* ради новых рамок.
Публичность чужого оформления не создаёт права зрителю/соседу.

## Арт — B, интеграция — C

Пути определены в item-plan.json: `/collections/v2-art/<id>-preview.svg` и
`<id>-game.svg`; у комплекта только preview, отдельной игровой картинки нет.
Манифест `miniapp/collections/v2-art/manifest.json`:

```
{ v:2, generator:'tools/build-cosmetics-v2.mjs',
  source:{kind:'project-generated', author:'Codex B', approved:false},
  collections:[{id,title,palette:{...}}],
  budget:{detailBytes:24576, smallBytes:8192, totalBytes:1048576},
  items:[{id,collection,slot,games,visibility,preview,game,includes?}],
  files:[{file,item,role:'preview'|'game',slot,viewBox,width,height,bytes,sha256}] }
```

`file` — basename в v2-art, preview/game в items — URL из договора; пути и hash
проверяются против файлов. Всего 114 SVG: 54 пары и 6 preview наборов.
Манифест — сопоставление ресурсов, не новые права и не новый каталог цен.
`approved:false` у нового арта до решения владельца; старый одобренный SVG
Графита не перегенерировать и не менять его manifest/hash.

Размеры/viewBox: рубашки обоих типов preview 200×280, game 40×56; table
preview 480×320, game 480×320 (прозрачный центр); frame preview 160×160,
game 48×48 (прозрачное лицо); badge preview 160×160, game 24×24;
chess/checkers board preview/game 400×400; nardy preview/game 480×360;
battleship panel preview/game 400×400; bundle preview 480×320. SVG масштабируется
через viewBox, game — упрощённый рисунок, не detail в уменьшенном CSS.

Доски/панели — декоративные слои без фигур, флота, кубиков и игровых отметок.
Клетки шахмат/шашек допускают безопасную малоконтрастную фактуру; не менять
хитбоксы. Все игровые символы остаются в существующем DOM поверх арта. Для
морского боя только внешняя рама/координатная область обоих полей; ни один
ресурс не зависит от расстановки/секретов. UNOQ украшает только закрытую сторону.
Без скриптов/foreignObject/внешних ресурсов/шрифтов, градиентов и тяжёлых фильтров.
Палитры каждого нового рисунка B фиксирует в manifest и README; UI-токены
по-прежнему в tokens.css/redesign, арт не перекрашивает кнопки магазина.

До 24 KiB preview, до 8 KiB game, целевой общий SVG ≤1 MiB; превышение
обосновать/оптимизировать, а не молча ослаблять тест. Детальные preview lazy
по открытию карточки, игровой файл — только для реально выбранного предмета.
B создаёт контактную доску всех 54 предметов и проверяет глаза/размеры/контраст;
его тесты не меняют общие app/hub/store/каталог. C подключает готовые descriptors.

## Протокол и snapshot — C

Сохранить `t:'col'`, `state/apply/clear/grant`, req 8–64 и лимит 20/мин.
Новые клиенты посылают `v:2` в col, новые state/ответы имеют v:2;
клиент к старому серверу v:1 показывает доступный Графит и честную недоступность
новых операций. Без v:2 сервер обслуживает прежний поднабор Графита v:1;
не отказывает прежним корректным запросам. Обновление требует переоткрытия Mini
App: старый JS не умеет новые предметы, а право не должно зависеть от его кэша.

Новая операция `apply-bundle {item,req,v:2}`: проверка полного состава, всех прав,
слотов, цвета (для Графита) до записи, затем единая SQLite-транзакция выбора и
req. Недостающий предмет → COL_NOT_OWNED, **ни один** слот не меняется.
Частичное владение не даёт скидку/доплату; их правило не утверждено. Одиночный
apply всегда сохраняет другие слоты. clear снимает только указанный слот.
Цвет Графита по прежнему whitelist; у v2 нет пользовательской перекраски:
служебное `color:'default'` в текущем столбце choice, сервер проверяет соответствие
предмету. Запросы не принимают произвольные пути SVG/CSS.

Личное col-state: owned с отдельными source, choice/pending по слотам, shop
(готовность/цены сервера), честная when. Публичный `look` v:2 сохраняет старые
`table`, `backs`, `dealNo` и добавляет `board`, `deckBack` (null вне своей игры).
Запись предмета — только `{item,color}`; рубашки покера — `{seat,item,color}`.
Личные frame/badge в players/results/score — публичные `{item,color}|null`.
Никаких Telegram id, owned/source/покупок/путей/текста игрока/тайных полей.
Публичные данные не строятся spread-ом приватного state/room.

Внутренний `room.look` хранит v:2, table/board/deckBack и backs/frames/badges по
id (только внутри комнаты). Номер: poker handNo, остальные шесть игр gameNo.
Лобби пересобирается после выбора/смены хоста. Успешный старт/новая партия
замораживает снимок; смена/уход хоста и reconnect/restart не меняют его.
Для battleship snapshot снимается при начале партии, включая расстановку, а
не по первому выстрелу. `afterDeal`/settle не должны постоянно пересобирать v2
из-за старой проверки `v !== 1`. Держатель клиента тоже различает комнату и
номер. Разные типы комнат не делят один holder.

Старый сохранённый snapshot v:1 сохраняется до конца текущей раздачи, v2-поля
пусты; со следующей — v2. Отсутствующий снимок старой комнаты дополняется один
раз из проверенного выбора. Неизвестная версия/предмет/слот/цвет → классика,
никакой подстановки nc-* или ближайшей новой коллекции. При фактическом отзыве
последнего источника права предмета безопасная классика имеет приоритет;
независимые источники не отзываются. Обычная смена выбора откладывается.

## Права, цены, gate — C (обязательная ловушка текущего кода)

`purchase` только существующее successful_payment с проверкой; `admin` только
shop_grant; `demo` только в демосреде; прежний `staff` по прежнему правилу.
Новый `owner` — отдельный вычисляемый источник по `app.isAdmin(session.user.id)`
из серверной конфигурации ADMINS, действует на новые 54 предмета при off.
Не сохранять его как купленное/подарок, не выдавать обычным игрокам/ботам/хостам
или всем COSMETICS_TESTERS автоматически. Тело браузера ничего не доказывает.

Публичная витрина/preview/мои вещи доступны при off, но не расширяют owned.
`enabled` означает доступность витрины; оплату решает только прежний pay gate.
Расширить visibleFor отдельно от staffOwns/priceOf, без снятия gate.

**Сейчас SELLABLE = new Set(ITEMS.map(...)), а test priceOf подставляет 1 Star
для отсутствующей цены.** До подключения нового каталога C обязан зафиксировать
продаваемый whitelist прежними четырьмя id Графита, чтобы новые null не стали
продаваться даже в test. Прежние offers/eff/overrides: cardback 75, profile 50,
table 100, bundle 175. Не переносить исторические demo price 99/79/199/249 в
реальную цену; не сбрасывать overrides. Новые 60 price=null во всех предложениях,
карточках и оплате, без счета даже на заглушке. Покупки/отзывы не имитируются UI.

Ошибки: существующие COL_ITEM/SLOT/COLOR/NOT_OWNED/FAST/OP/STALE/OFF и русские
тексты; при новой операции добавить в protocol/MESSAGES. Нехост вправе выбрать
свою тему для будущего своего стола, но не менять look чужой комнаты: при попытке
адресного изменения общей темы — существующий отказ хоста. В UI «Общий стол
выбирает хост». when pending: «Применится со следующей партии» (в покере допустимо
«раздачи»). Неизвестные права — загрузка/повтор, успех только после server ack.

## Совместимость/откат — C, контроль E

A не меняет DDL, сервер, права/заказы/счета. nc-* остаются в архивном каталоге и
localStorage без миграции/удаления. Они никогда не продавались текущим pay API;
это не основание удалять гипотетическую неизвестную строку из базы.
Существующие pay_* и shop_grant сохраняют id/source/order/charge/цену/историю.
Неизвестные записи не показывать как доступные, но **не удалять**. Особенно
проверить dropUnowned: сейчас он чистит любые неизвестные выборы; C должен
различать реальный отзыв известного права, служебную базу и неизвестную строку.
Схема может остаться 5: choice хранит строковые слоты/item/color. Если C выберет
новое хранение, нужны обоснование, миграция и backup/старый код/возврат нового.

Rollback на 1781699 не знает новые предметы и покажет классику; строки остаются,
при возврате нового кода выбор/права восстанавливаются. Старый cleanup не следует
вызывать над новыми неизвестными слотами. Перед C/E — файловая тестовая копия:
купленный Графит + admin на ту же вещь + demo + nc-* + неизвестное + новые
вещи/база + snapshot v1/v2, .backup, открытие старым Store/App на копии,
возврат новым кодом. Сравнить все строки прав/заказов до/после, integrity_check,
meta.schema. Реальную базу и Telegram не трогать.

D использует общий каталог/серверное подтверждение; локальный preview не меняет
choice/снимок и не посылает apply. Ошибка SVG → классика/нейтральная миниатюра
без повторного цикла загрузки; ходы доступны. Фильтры/прокрутка/возврат к столу
и неизвестные права — по 01-design. Нельзя считать готовыми пункты B/C/D по
одной документации этого этапа. E заново проверяет все семь игр и всю историю
двух игроков/зрителя, права/rollback/арт/производительность/телефонный остаток.

## Передача B → C: готовый пакет арта

B реализовал `miniapp/collections/v2-art/manifest.json` (114 SVG, 54 предмета +
6 комплектов) по всем id A. Descriptors — `manifest.items`, включая исходные
названия/описания/price:null/слоты/games, прямые preview/game и assets; у набора
game=null. Readiness только art-ready, source.approved=false. Общий runtime
каталог C ещё не менялся. Палитры/размеры/точное совмещение прозрачных окон —
`miniapp/collections/v2-art/README.md`; источник — tools/build-cosmetics-v2.mjs.

Preview досок/стола/рамок — прозрачный декоративный слой без фигур. Витрина
может компоновать его с классическим игровым содержанием. Game — отдельная
упрощённая геометрия. Для обоих полей морского боя ресурс один и тот же,
ни от какого состояния/флота он не зависит. Локальные use/clipPath ссылаются
только на собственную геометрию SVG; внешних ресурсов нет. Не использовать
публичность файлов как источник owned и не продавать null-цену.

Пакет SVG 392.719 байт; preview ≤19.750, game ≤3.509. Контактные листы и
композиции с игровыми элементами — reports/art-sheets; это не доказательство
подключения в партии. Файлы Графита, прежние id/покупки/права/цены B не менял.
Новый арт требует отдельного просмотра/утверждения владельцем.
