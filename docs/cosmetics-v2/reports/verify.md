## Найденные дефекты и изменения E

E исправил три доказанных дефекта: инструмент поломок E-01, загрузку
подробных SVG E-02 и перекрытие игрового действия чатом после магазина E-03.
Правила, серверные права/цены/хранение, старые id и сами SVG
не менялись. Добавлены независимый прогон настоящих партий, сравнение загрузки
и проверки их временной поломкой; shop-e2e получил отдельную папку снимков
и контроль запросов/состава малой миниатюры/открытия большого изображения.

**E-01: устаревшие точки платёжных поломок.** Собственный первый
`node tools/payments-teeth.mjs` вернул exit 1: поймал 43 случая, но два вывел
как «место поломки не найдено». C изменил условие `dropUnowned` и заменил
динамический SELLABLE whitelist-ом; инструмент всё ещё искал прежние строки.
Обновлены только две точки временного внесения дефекта. Дополнительно случайный
crash больше не засчитывается: нужен exit 1 и настоящий AssertionError без
Syntax/Reference/TypeError. Платёжные тесты/ассерт не ослаблялись, приложение
не менялось. Усиленный контроль выявил четыре обращения к полям отсутствующего
результата в `payments.test.js`/`payments.final.test.js`: три сценария
(частичный комплект, независимое право, восстановление возврата) давали TypeError.
Теперь те же точные ожидания PAY_PARTIAL/sapphire/refunded проверяются через
optional access и дают AssertionError при отсутствии данных. Никакие факты
и условия тестов не ослаблены. Итог: **45/45** временных поломок приняты только
по настоящему assert; восстановленная группа зелёная.

Первый `npm test` внутри sandbox был прерван: listen localhost запрещён.
Отдельный минимальный `http.createServer().listen(0,'127.0.0.1')` действительно
вернул `EPERM listen 127.0.0.1`. Это снято разрешённым локальным запуском;
не названо внешним blocker или успехом приложения. Все окончательные команды
ниже выполнялись с разрешёнными localhost/Chromium и на восстановленных файлах.

**E-02: каталог загружал шесть подробных SVG комплектов до открытия карточек.**
Первый собственный performance-прогон сохранил URL/байты в
[performance-before-fix.json](performance-before-fix.json). Новый строгий
assert на исходном коде дал exit 1 и **6 !== 0**, именно AssertionError.
Причина: `itemArt` всегда выбирал preview для bundle, даже в каталоге.
`loading=lazy` не откладывает большой файл до открытия карточки; Chromium
действительно запросил все шесть.

Исправлено только построение малой миниатюры комплекта: сетка из девяти
существующих game-ресурсов. Ни нового SVG, ни цены, ни id, ни выдачи прав.
Крупный preview остаётся прежним и загружается по открытию карточки. Отступы
из токенов, без новых UI-текстов/цветов/скруглений. Браузерный контроль требует
шесть композиций × девять частей, отсутствие всех v2 detail URL в каталоге,
а затем успешную загрузку большого SVG комплекта в карточке.
Возврат прежней ветки снова роняет тот же assert, файл восстановлен.
Снимки [малый комплект 320](verify-shop-screens/bundle-320.png) и
[крупный комплект 390](verify-shop-screens/bundle-item-390.png).

Первый полный повтор после E-02 выявил внесённую E регрессию на **430 px**:
старое широкое правило `.col-grid .col-card-art .col-art { width:96px }`
затронуло и девять вложенных ячеек новой миниатюры. `e2e-collections` остановил
весь npm run e2e по assert выхода изображений вправо. Исправлен селектор на
прямого ребёнка `> .col-art`: 96 px получает только внешняя миниатюра.
Ассерт не ослаблен. Этот красный полный прогон не считается успехом;
после исправления обязательные команды повторяются.

Первый запуск нового performance-инструмента для 1781699 не нашёл `server/game.js`
в неполном временном архиве. В архив добавлена неизменная импортируемая
зависимость; рабочий `server/` не редактировался. Все замеры затем повторены
на одинаковой полной фикстуре, неудачный запуск не включён в числа.
Одноразовая правка отчёта через Python остановилась на ошибке кодировки до
записи; документ исправлен через apply_patch, данные не потеряны.

**E-03: кнопка чата перекрывала Raise на первом кадре возврата из магазина.**
Найдено визуально в текущей повторной попытке уже после зелёного полного e2e;
прежний сценарий проверял место/часы/фокус, но не положение чата после закрытия.
[Собственный снимок до](verify-regressions/chat-before-320.png).
Это локальный дефект, не внешний blocker. Под магазином `#app` становится
`inert`; `elementsFromPoint` перестаёт видеть кнопки игры. Отложенный `placeFab`
подбирал место по чужому слою, и после закрытия чат некоторое время закрывал
действие, пока следующий отложенный пересчёт не исправлял положение.

Добавлен воспроизводимый браузерный контроль: реальная партия, магазин,
вызов существующего пересчёта во время inert, затем первый кадр возврата и
геометрия всех кнопок игры. **До правки exit 1 / AssertionError: y=440 вместо
302**, точная причина `shop must not reposition chat through inert game content`.
Исправление в `chat.js`: сохранять последнее корректное положение, пока
игровой экран inert. Новых подписок/циклов/таймеров/текстов нет. Проверка
первого кадра включена в семь игр × две ширины обычного shop-e2e.
Узкий `SHOP_DOCK_TEETH=1` запускает реальную покерную сцену для поломки этой
защиты; не подменяет полный магазин. Удаление guard снова дало тот же assert,
файл восстановлен, контроль зелёный. `cosmetics-verify-teeth --dock --perf`
теперь ловит **7/7** собственных поломок. После E-03 полный npm test,
все 33 файла e2e, 84 партии матрицы, layout/kit/contrast/colors/preview
повторены успешно. [Снимок после](verify-regressions/poker-return-320.png).
