# Покер: «Тренировка» — контракт и устройство

Раздел «Тренировка» (волна 3, агент V). Здесь — **окончательный** контракт упражнения,
виджетов, сообщений прогресса и правила добавления нового. Общий план —
`docs/next-wave-3/00-plan.md`; решения — `docs/brain/decisions/057–062`.
Всё, что отличается от плана, помечено **«изменено относительно плана»**.

## Где живёт и как открывается

Покер → «Игры с ботами» → форма покера → переключатель **«Партия · Обучение · Тренировка»**.
«Тренировка» закрывает шторку и открывает **полный экран** (матрица 13×13 и разборы в
шторку не помещаются). Это экран **страницы**: сервер о нём не знает, состояние стола не
меняется. Нижняя панель на экранах Тренировки скрыта (как за столом). Маршруты:
`miniapp/train/route.js` (`openRoute('train')`, `'train-stats'`, `'train-ex'`, `'learn'`).
Переход на другой стол/группу (сменилось «место» состояния) закрывает экран.

Файлы: `miniapp/train/` — `topics.js` (реестр тем, владелец V), `engine.js` (чистый движок),
`skills.js`, `srs.js` (чистые правила, их же считает сервер), `screens.js` (экраны),
`stats.js`, `route.js`, `widgets/`, `content/` (упражнения по направлениям), `miniapp/train.css`;
сервер — `bot/train.js`, таблицы в `bot/store.js`.

## 1. Упражнение

Чистая функция без DOM — чтобы тесты проверяли её без браузера.

```js
// miniapp/train/content/<файл>.js
import { registerExercises, makePick } from '../engine.js';
registerExercises('potodds', [{
  id: 'potodds-need-2',      // латиница/цифры/._-, до 64, уникален; на него ссылаются результаты игроков — не менять
  topic: 'pot-odds',         // из miniapp/train/topics.js; УРОК этой темы откроется из ошибки
  level: 2,                  // 1…5; skill и track берутся из направления
  kind: 'pick',              // 'pick'|'cards'|'range'|'slider'|'bet'|'table'|'order'
  make(seed, rng) → задание, // ДЕТЕРМИНИРОВАНО: тот же seed → то же задание
}]);
```

`make(seed, rng)` — **изменено относительно плана:** вторым аргументом приходит `rng` (готовый
генератор от seed): `rng()` ∈ [0,1), `rng.int(lo,hi)`, `rng.pick(arr)`, `rng.shuffle(arr)`.
Не используйте `Math.random`, `Date.now` — иначе «вернуться к тому же заданию» вернёт другое.

```
задание = {
  prompt,            // текст по-русски, числа с точками (1.000.000)
  setup,             // что показать виджету вида kind: карты, борд, банк, стеки, позиции, options…
  solution,          // изменено относительно плана: один верный ответ В ФОРМЕ answer — тесты
                     //   гоняют check(solution) и требуют ok:true (ловит неверные упражнения)
  check(answer) → разбор,
}
разбор = {
  ok, score,         // верно / оценка 0…1; ok по умолчанию = score ≥ 0,7
  mistakes: [{ code, topic, text }],   // topic ОБЯЗАН быть из реестра тем; code — латиница-дефисы, до 40
  why,               // 2–4 предложения; обязателен (тест)
  alternatives: [{ label, verdict, text }],
  solution,          // что нарисовать в разборе (верный диапазон/ставка…)
}
```

**Каждое число в `why`/`alternatives` считается кодом** (`poker-math.js`, агент X), а не пишется
руками. «Эталонные» данные (диапазоны, размеры ставок, GTO-частоты) не выдумывать и не выдавать
за солвер: учебный ориентир — отдельным файлом с комментарием «откуда» и пометкой «приближённо».

`makePick(rng, { prompt, setup, options:[{id,label,why}], correct, why, mistake:{code,topic} })` —
готовое задание-выбор (перемешивает варианты по `rng`, собирает разбор с альтернативами).

### Движок (`miniapp/train/engine.js`)

`registerExercises(trackId, list)` · `exercisesOf({track,topic,level,skill})` · `exerciseById` ·
`instantiate(id, seed) → {exercise, seed, task}` · `grade(task, answer) → разбор` ·
`pickExercise({track, level, topic?, recent, rand})` · `coverage()` · `rngFromSeed(seed)` ·
`newSeed()` · `reviewProblems(разбор)` · `ROUND = 10` заданий в подходе.
Регистрация сразу проверяет форму (id, тема из реестра, уровень, kind, `make`) и **падает при
загрузке**, а не у игрока.

## 2. Как добавить

- **Упражнение** — объект в массив `registerExercises` вашего файла в `content/`. Тесты
  (`bot/train.test.js`) сами проверят: детерминизм `make`, `check(solution).ok`, `why`, темы из реестра.
- **Файл направления** — новый `content/<имя>.js` + **одна строка `import`** в `content/index.js`.
- **Направление** — строка в `TRACKS` (`topics.js`; id не менять и не удалять) + файл упражнений.
- **Уровень** — число `level` 1…5 у упражнения; на экране он называется `LEVEL_NAMES`.
  Нужен хотя бы один уровень с упражнениями; если на уровне пусто — берётся ближайший.
- **Тема** — строка в `TOPICS` в **своём блоке-комментарии**; урок и упражнение связываются по `topic`.
- **Вид ответа (`kind`)** — строка в `KINDS` (engine.js) + виджет в `widgets/` + строка в `ANSWER_WIDGETS`
  (screens.js).

## 3. Виджеты — `miniapp/train/widgets/<имя>.js`

```js
export function mount(props) → Element
export function update(el, props)       // необязательно
// props: { setup, value, disabled, onChange(value), result }   // result — разбор, когда он уже есть
```

`value`/`onChange` — **изменено относительно плана**: состояние ответа живёт в экране, а не внутри
виджета, поэтому перерисовка страницы (приходит новое состояние сервера) не теряет набранное.
Принадлежность: `choice.js`, `explain.js`, `progress-bar.js` — V; `range-grid.js` — W;
`cards.js`, `board.js`, `odds-bar.js`, `bet-slider.js`, `table-seat.js` — X.
Чужой виджет можно брать, только когда он в `redesign`. Виджет **не перестраивает** себя от нажатия
(правка на месте): иначе экран «подпрыгивает» (Z).

Реестр видов: `ANSWER_WIDGETS` в `screens.js` — `kind → модуль виджета` (статический `import * as x from './widgets/<имя>.js'` и строка в объекте; свою строку добавляет автор виджета). Необязательный признак готовности ответа — `task.isComplete(answer) → bool` (многошаговые задания, ввод числа): «Проверить» включается, когда он `true`; нет функции — достаточно `answer != null`. Свои стили виджетов — своим файлом + `<link>` в `index.html`.
Пока виджета нет, экран честно пишет «этот вид задания ещё не подключён» и даёт пропустить.

## 4. Прогресс: сообщения страницы

Всё — про самого игрока: личность **только** из подписанного `initData`, «чей» в теле нет.
Ответы приходят сообщением `{t:'train', progress}` либо отказом `{t:'train', error:{code,text}}`.

```
{ t:'train', op:'get' }                                  → { t:'train', progress }
{ t:'train', op:'result', ex, track, topic, level, score, ms, seed, mistakes }
                                                         → { t:'train', progress, saved:true }
{ t:'train', op:'level',  skill, level }                 → { t:'train', progress }   // ручной уровень навыка
{ t:'train', op:'reset' }                                → { t:'train', progress }   // «Сбросить мой прогресс»
{ t:'train', op:'placement', … }                         // агент Y: регистрируется через Trainer.registerOp
```

`mistakes` — массив кодов ошибок строками (до 8, `[a-z0-9._-]`, до 40 символов); в журнале ошибок они записываются на тему задания. Лишние поля в сообщении — отказ.

Проверка на сервере: `track/topic/skill` из реестра, `level` целое 1…5, `score` 0…1, `ms` 0…3.600.000,
`seed` целое 0…2³²−1, `ex` — формат id (до 64), `mistakes` ≤ 8 по ≤ 40 символов; частота — по
`app.clock.now()`; не больше 500 результатов на игрока (ротация). Нарушение → отказ словами
(`TRAIN_ERRORS`, `MESSAGES.md`).

### Форма `progress`

```js
{
  now, total,                                   // время сервера; всего решённых заданий
  skills:  { preflop:{ level, rating, n, manual, mastered, suggest } , ranges, math, postflop },
  tracks:  { outs:{ passed:[1,2], n30, accuracy30 } , … },     // пройденные уровни; точность за 30 дней (0…1 | null)
  weak:    [{ topic, track, step, dueAt, lapses, due }],       // темы в повторении
  due:     [тот же вид, только те, у кого срок пришёл],
  mistakes:[{ code, topic, track, n, lastAt, ex, seed }],      // последние ошибки (до 20), ex+seed — вернуться к тому же заданию
  recommend:[{ kind:'review'|'next'|'consolidate', track, topic?, level, why }],  // до 3
}
```

`suggest` — `null` или `{dir:'up'|'down', to, text}` (текст с объяснением: «7 из 8 верно — …»).
**Автоматически уровень не меняется никогда:** только предложение; игрок соглашается (`op:'level'`) или
выбирает уровень сам. Ручной выбор всегда сильнее автоматики: после него счёт для предложений идёт заново.

## 5. Правила навыков (числа — `skills.js`, `srs.js`; решения 058–060)

| Что | Правило |
|---|---|
| Навыки | `preflop`, `ranges`, `math`, `postflop`; у каждого `level` 1…5 (старт 1) и `rating` 0…100 (скользящая оценка, вес нового ответа ≥ 0,2) |
| «Верно» | оценка задания ≥ 0,7 |
| Уровень направления пройден | из последних 10 заданий этого уровня в направлении верно ≥ 8 |
| Предложение сменить уровень | из последних 8 заданий навыка на текущем уровне: ≥ 7 верно → выше; ≤ 2 верно → ниже |
| Навык «освоен» | уровень ≥ 3, оценка ≥ 80, заданий ≥ 20 |
| Повторение | ошибка → тема «слабая»; вернуться через 1 → 3 → 7 → 14 дней при верных ответах **после срока**; ошибка сбрасывает на 1 день; после 14 дней тема закреплена |
| Рекомендации | 1) тема со сроком повторения; 2) следующий непройденный уровень в наименее проработанном направлении; 3) «закрепить» — направление с самой низкой точностью среди пройденных |

## 6. Приватность и хранение

Таблицы `train_skill`, `train_level`, `train_result`, `train_topic`, `train_mistake` создаются
`CREATE TABLE IF NOT EXISTS` — **версия схемы (`meta.schema`) не поднимается**, старый код открывает
такую базу и просто не знает про таблицы (как у `profiles`). Прогресс **личный**: не в рейтинг, не в чат,
не в группу, не в `view` стола, не в админку. «Сбросить мой прогресс» стирает все пять таблиц игрока.
Подсказок в партии нет и не будет (решение 016): «разбор после решения» — часть упражнения, не партии.

## Y. Определение уровня, журнал решений, связка (агент Y; решения 071–075)

**Что хранится о решениях.** Таблица `decision_log` (без смены версии схемы): на каждое **своё** решение
человека за покерным столом — улица, позиция, **свои** две карты, открытый борд, банк, сколько доплачивать,
свой стек, число соперников, большой блайнд, действие и сумма, категория собранной руки, шанс выиграть против
случайных рук (Монте-Карло, 160 прогонов, детерминированно от раздачи) и вид стола (`table` — с друзьями,
`solo` — с ботами). **Не хранится:** чужие карты, исход раздачи, выигрыш/проигрыш, имена, чат. Бот за себя не
пишет; школа покера (подстроенные раздачи) и стол с настоящими картами — не пишутся. Последние 300 на игрока
(старые стираются при записи). Кнопка «Удалить историю решений» (`op:'decisions-clear'`) и «Сбросить мой
прогресс» (`op:'reset'`) стирают всё. Ни в рейтинг, ни в группу, ни в админку журнал не идёт. Хук — одна
строка-обёртка в `case 'act'` (`bot/games/poker/index.js`); падение журнала глотается и пишется в журнал
сервера, партия идёт дальше (тест).

**Оценка — эвристика, не солвер** (`bot/decisions.js`, `rateDecision`). «Ошибка» — только очевидное и
измеримое: сброс при бесплатном чеке; сброс при шансах банка, лучших нужных на 25+ пунктов; колл, когда шанс
выиграть ниже нужного больше чем на 12 пунктов (даже против случайной руки); олл-ин слабой рукой при стеке
от 12 BB против небольшой ставки; сброс AA/KK/QQ/AK; лимп этих рук из ранней позиции. «Хорошо» — зеркальные
случаи. Всё остальное — `unknown` и в учёт не идёт. Исход раздачи и число фишек/партий на вердикт не влияют
(функция читает только белый список полей; тест подсовывает исход). Из истории уровень не выше 4: эвристика
не может ручаться за «Эксперта».

**«По истории».** Доступна при ≥ 40 решений и ≥ 5 оценённых по навыку; иначе навык — «мало данных», а кнопка
серая со словами. Диапазоны журнал не оценивает вообще. Сегодня журнал пуст — доступной эта кнопка станет
после выкатки и накопления партий.

**Диагностика** (`miniapp/train/placement-core.js`): 8–12 заданий, по 2 на навык (+1, если ответы
разошлись); верно → сложнее, неверно/«Не знаю» → проще; уровень = самый высокий верно решённый. Берутся
упражнения из реестра движка; виды не `pick` — только когда экран упражнений V подключён (`ctx.runTask`).
Итог — шкала и «−/+» по каждому навыку. Сервер (`bot/placement.js`) принимает только известные навыки и
уровни 1…5; «по истории» без данных отклоняет словами.

**Связка** (`link.js`, `link-wire.js`): «Изучить тему» из разбора → урок (`openRoute('learn', {lesson, returnTo})`)
→ «Вернуться к заданию» = то же упражнение с тем же seed (контекст в памяти и `sessionStorage`). Цепочка
«ошибка → урок → то же задание» — не более 3 раз подряд на одном и том же задании, потом «домой». Рекомендации
— `recommend.js` (единый источник, форма `progress` как выше).

## Раздел W: диапазоны (матрица 13×13, «Префлоп», «Диапазоны», «Чтение диапазонов»)

Файлы: `miniapp/train/ranges/` (hands — 169 рук, комбо, `parseRange`/`formatRange`, `diff`, блокеры; grid — модель редактора; data — порядок и диапазоны; tasks — оценка и разбор; equity169 — таблица, создаётся `tools/build-range-data.mjs`), виджет `widgets/range-grid.js`, стили `miniapp/ranges.css`, упражнения `content/{preflop,ranges,readrange}.js`.

**Откуда эталоны (честно).** Порядок рук — очки формулы Чена + поправка за эквити против случайной руки (Монте-Карло, 100.000 раздач на руку, ±0,2 п.п.) + 0,5 пары. Диапазоны — верхушка порядка по круглым процентам 6-max, 100 BB. Это **учебный ориентир, не солвер**; настоящие GTO-диапазоны — отдельные данные с лицензией. Решения 063–066.

**Виджет:** `mount({ setup:{ grid:{ mode, steps, ref, presets, text, hint } }, value, disabled, onChange, result })`; режимы edit/readonly/diff/heat/flag; ответ — массив кодов или объект частот; в flag `result.solution` — неверные клетки. Матрица не пересобирается от нажатия.

**Виды ответа:** range, slider (число), table ({ action, to }), pick (id) — экраны V/X должны подключить виджеты под эти виды.

## Волна 4 (F): ситуация и диапазон на экране задания

- Виды `pick` и `range` показывают над ответом **сцену** (`sceneEl` в `widgets/table-seat.js`): ряд позиций, карты (`hero:[карты]` или `hole:[карты]` + `hero:'BTN'`), банк/стек в BB, борд, история, готовая матрица `setup.grid` режима `readonly`. `setup.you` — ваша позиция, когда `opener` — тот, на кого смотрим (3-бет, чтение диапазона): `hero` строкой в таких заданиях **не ставить**.
- `task.reveal = { grids:[{ title, ref, mark:[рука] }] }` (через `makePick`) — после ответа в разборе раскрывается диапазон на матрице, рука задания обведена; нажатие на клетку отвечает строкой (`ranges/cell-note.js`). Пустые диапазоны не рисуются.
- Точки подхода и «Где ошибались» — `screens.js`. Проверки: `bot/train.scenes.test.js`, `tools/e2e-train-scenes.mjs`.
