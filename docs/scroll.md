# «Прыжки» экрана: причины, как устроено теперь, правило для новых экранов

Жалоба владельца: при выборе числа игроков, блайндов, таймеров, вкладок и
переключателей экран дёргается и уезжает наверх. Ниже — что нашлось замером
(Chromium с эмуляцией телефона, `tools/e2e-scroll.mjs`), а не догадкой.

## Реальные причины (обе доказаны замером «до/после»)

1. **Шторка пересоздавалась целиком.** `refreshSheet()` на каждое нажатие делал
   `$sheets.replaceChildren(backdrop, sheet)` — то есть создавал заново и саму
   `.sheet`, а она и есть прокручиваемый элемент. Новый узел начинает с
   `scrollTop = 0`, и заново играла анимация появления. Замер: форма «Игры с
   ботами → Покер» на 320×568 прокручена до 175 px → любое нажатие → 0 (так же
   лобби-настройки: 163→0, «Новое лобби» в хабе: 54→0, форма шахмат: 12→0). На
   390×844 форма покера: 44→0. Во всех 34 нажатиях из таблицы.
2. **Экран пересоздавал свой прокручиваемый корень.** У экранов хаба и лобби
   прокручивается корневой `.lobby` (`html, body { overflow: hidden }`). Каждое
   состояние с сервера вызывало `render()`, а тот делал
   `$app.replaceChildren()` — `.lobby` рождался заново. Замер: лобби покера на
   низком окне прокручено до 187 px → друг сел за стол (пришло состояние) → 0.

## Что проверено и оказалось НЕ причиной

- `focus()` / `scrollIntoView` на перерисованных полях: `poker.js` ставит их
  только по фокусу в поле ввода суммы (для клавиатуры), `profile.js` — только по
  фокусу в поле ника. На нажатие сегмента не срабатывают.
- `overflow-anchor`, `scroll-behavior` в стилях не заданы; высота шторки при
  нажатиях сегментов не менялась (`scrollHeight` до/после совпадал).
- `bus.render()` пересобирает содержимое `#app`, но `document` не прокручивается
  (у `body` `overflow: hidden`) — прыгал именно `.lobby`, см. причину 2.

## Как устроено теперь

- **Шторка** (`miniapp/ui.js`, `showSheet`): оболочка — затемнение, `.sheet`
  (она и прокручивается), ручка — создаётся один раз и живёт, пока шторка
  открыта. `refreshSheet()` заменяет только внутреннее содержимое
  (`content.replaceWith(body)`). Тот же узел-скроллер → браузер сам сохраняет
  `scrollTop`, анимация появления не повторяется. Другая шторка (другое имя) —
  новая оболочка; повторный `showSheet` с тем же именем оболочку не трогает.
- **Экран** (`miniapp/app.js`, `render`): пока экран тот же (тот же ключ
  «экран / место / вкладка»), живой `.lobby` остаётся в странице, а новое
  содержимое и атрибуты переезжают в него (`adoptLobby`). Смена экрана или
  вкладки — пересоздание, прокрутка в начало, как и положено.
- Никто не запоминает `scrollTop` и не возвращает его после перерисовки;
  прокрутка не блокируется; `overflow: hidden` / `position: fixed` на `body` не
  использованы для маскировки.

## Правило для новых экранов

1. **Не пересоздавай скроллер.** Прокручиваемый элемент (`.sheet`, `.lobby`,
   свой контейнер с `overflow-y: auto`) создаётся один раз. Перерисовка — это
   новое содержимое *внутри* него либо точечное обновление (текст, классы
   выбранных сегментов, значения) — образец: `mounted`/`patch` в
   `miniapp/profile.js`.
2. **Шторки — только через `showSheet` / `refreshSheet`.** Не вызывай
   `$sheets.replaceChildren` сам.
3. **Панели разной высоты под вкладками** — резервируй `min-height`, чтобы экран
   не «дышал». Не вызывай `focus()` / `scrollIntoView` без причины (клавиатура,
   поле действительно закрыто; `block: 'nearest'`).
4. **У нового экрана — свой замер** в `tools/e2e-scroll.mjs` (или своём e2e) через
   `tools/lib/scroll-probe.mjs`:

   ```js
   import { assertNoJump } from './lib/scroll-probe.mjs';
   await assertNoJump(page, { scroller: '.sheet', target: page.getByRole('button', { name: '100/200' }), label: 'форма' },
     () => page.getByRole('button', { name: '100/200' }).click());
   ```
   Помощник находит скроллер, ставит на него метку-свойство, снимает
   `scrollTop` на каждом кадре на время действия и падает, если узел пересоздан,
   позиция ушла (даже «подпрыгнула и вернулась») или потерян фокус поля. Если
   содержимое стало короче и прежней позиции больше нет, браузер упирается в
   конец — это не скачок, помощник это учитывает. Экран, который не
   прокручивается, проверка ничего не доказывает — окно сделайте ниже (320×568).
   Используйте `target` (локатор): иначе Playwright сам прокрутит к кнопке при
   клике, и это примут за прыжок.

## Проверка «на зубы»

Старый код (`replaceChildren` целиком в `showSheet`, `$app.replaceChildren()` в
`render`) возвращён → `node tools/e2e-scroll.mjs`: **36 из 36 нажатий со
скачком** (потом вкладки «Обучение»/«Тренировка» формы стали переходами на свой экран, проб осталось 32). Исправление на месте → **0 из 36**.

## Чего эта проверка не доказывает

Chromium с эмуляцией телефона — не настоящий iOS/Android WebView Telegram.
Экранная клавиатура, жесты свайпа Telegram, `viewportChanged`/`expand()` и
поведение прокрутки пальцем так не воспроизводятся. Нужна проверка руками на
телефоне (список — в отчёте и `docs/brain/sessions/2026-10-25-Z-ekran.md`).

## Новые экраны волны 3 (часть 3, проверил K, 2026-10-26)

`tools/e2e-scroll-train.mjs` (входит в `npm run e2e`) обходит на 320×568 и 390×844: выбор уровня
(три карточки), диагностику, итог диагностики, «Обучение» (список, урок, ползунок, «проверьте
себя»), «Тренировку» (список, направление, смена сложности), упражнение каждого из восьми
направлений (встречаются все шесть видов заданий: выбор, матрица, карты, ползунок, раздача,
ставка), разбор, «Изучить тему» → урок → «Вернуться к заданию» и «Мой прогресс». Перед замером
окно делается ниже (иначе нечего прокручивать). Найдено и исправлено по первопричине:

1. **Экран писал в отсоединённый узел** (курс «Обучение», выбор уровня): `adoptLobby` отдавал
   содержимое нового `.lobby` старому, а экран держал в замыкании новый. Нажатия «ничего не
   делали». Теперь такой корень помечен `data-self` (решение 080).
2. **«Крупно» на матрице уводило страницу на 160 px**: браузер брал клетки матрицы опорными
   узлами (scroll anchoring). `overflow-anchor: none` на `.rg`, `.rg-wrap`, `.rg-board`
   (решение 083). Оговорка: iOS-WebView scroll anchoring не поддерживает — там иначе; проверить на телефоне.
3. Слова «null» и «[object HTMLDivElement]» на экранах упражнения и «Мой прогресс» (решение 081).

Что считается скачком: нажатая кнопка сдвинулась на экране больше чем на 2 px; прокрутка к
разбору после «Проверить» и переход к следующему вопросу диагностики — по замыслу и помечены.
Матрица: тап, наборы, «Крупно», режим рисования — без скачка; жесты пальцем вне матрицы и
внутри неё на настоящем телефоне — **не проверены** (эмуляция Chromium — не WebView).
