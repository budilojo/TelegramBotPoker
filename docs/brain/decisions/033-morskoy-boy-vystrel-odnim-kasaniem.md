# 033. Морской бой: выстрел одним касанием, с защитами от случайного тапа

- **Дата:** 2026-10-23
- **Кто решил:** владелец (задание волны 2: «выстрел в одно касание»); защиты придумал агент P (граница — без владельца)
- **Статус:** принято (заменяет двухшаговый выстрел из решения 010 и `docs/battleship.md`, раздел «Выстрел»)

## Что решили

Тап по клетке сразу стреляет; кнопки «Огонь» нет. Чтобы промах пальцем не стал
необратимым по ошибке: потраченные клетки и клетки рядом с потопленным на касание
не реагируют; палец, сдвинувшийся больше чем на 8 px, выстрелом не считается
(стреляет отпускание без сдвига); пока ответ сервера не пришёл, второй выстрел не
уходит; сервер отказывает выстрелу с устаревшим номером хода (`STALE`).
После выстрела адрес и результат крупно — «К10 — мимо».

## Почему

Владелец попросил одно касание. Двухшаговый экран появился из-за мелких клеток
(решение 010): на 320 px клетка 24–28 px. Одно касание оставляет ту же опасность,
поэтому без защит её не принимаем: двойной тап, прокрутка и тап по уже обстрелянной
клетке не должны делать выстрел. Порог 8 px — выбор агента, на телефоне не
проверен (`docs/brain/status.md`, «Не проверено»).

## Где это в проекте

`miniapp/games/battleship.js` — `tapAim`, `aimDown`/`aimMove`/`aimUp`, `boardEl` (потраченные клетки — не кнопки);
`bot/games/battleship/rules.js` — `fire` (проверка `shot` → `STALE`), тесты
`bot/battleship.rules.test.js` («двойной тап: два выстрела с одним номером хода»);
e2e — `tools/e2e-battleship.mjs` (двойной тап по воде → один выстрел; палец
уехал на 30 px → выстрела нет; касание не в свой ход → подсказка). Проверка «на
зубы»: серверная защита — отключить `STALE` → тест падает.
