# Свой сервер: что купить и что с этим делать

Сейчас бот живёт на ноутбуке, адрес выдаёт бесплатный туннель и меняет его при
каждом запуске. Для прода это не годится: закрыли крышку — игра встала.

Здесь — что купить, где и в каком порядке, и как поставить бота так, чтобы он
поднимался сам после перезагрузки, ходил по https с настоящим сертификатом и
раз в сутки делал бэкап. Всё, что можно было сделать за вас, лежит в папке
`deploy/`: ставится одной командой.

> **Цены и правила меняются.** Всё, что ниже, — на осень 2026-го.
> Перед покупкой посмотрите цену на сайте провайдера сами.

---

## 0. Важное, что надо знать до покупки

**Telegram в России с февраля 2026-го «замедляют», в апреле дело дошло до почти
полной недоступности; мессенджер работает, но с перебоями и через обходные
пути.** Для нас из этого следует одно практическое правило:

**Сервер брать в зарубежной локации.** Бот всё время стучится в
`api.telegram.org`. С сервера, стоящего в российском дата-центре, этот стук
может не дойти — и тогда встанет всё, а выглядеть будет как «бот сломался».
Сервер в Амстердаме, Варшаве или Алма-Ате ходит в Telegram напрямую, как
раньше.

Это не решает вопрос с игроками: если у них Telegram еле шевелится, играть они
будут через тот же VPN, что и переписываться. Но хотя бы ваша половина —
сервер, мини-приложение, рассылки — будет работать без оговорок.

Покупать при этом лучше у **российского провайдера с зарубежными площадками**:
российская карта на иностранном сайте не пройдёт, а у наших зарубежные локации
есть.

## 1. Что купить

### Сервер (VPS)

Нужен самый маленький. Бот — это один процесс на Node, база — файл SQLite; всё
это спокойно живёт на одном ядре.

| Что | Сколько |
|---|---|
| Процессор | 1 ядра достаточно |
| Память | **1 ГБ** хватает: бот — это один процесс Node и файл базы. На таком сервере установщик сам добавляет 2 ГБ подкачки, чтобы не спотыкались сборка и тесты |
| Диск | 10–20 ГБ |
| Система | **Ubuntu 24.04 LTS** — под неё написан скрипт установки |
| Локация | **Амстердам / Варшава / Алма-Ата**, не Россия (см. выше) |

Где брать (все принимают российские карты):

| Провайдер | Локации | Порядок цены |
|---|---|---|
| [VDSina](https://vdsina.ru/) | Амстердам | от ~150 ₽/мес за 1 ГБ — самый дешёвый вменяемый вариант |
| [Aeza](https://aeza.net/), [4VPS](https://4vps.su/), [JustHost](https://justhost.ru/) | Европа и Азия | от ~200–400 ₽/мес |
| [Timeweb Cloud](https://timeweb.cloud/services/servers-europe) | Амстердам, Франкфурт, Варшава, Алма-Ата | от ~640 ₽/мес, зато панель поудобнее |

Российские площадки у тех же провайдеров дешевле (от ~350 ₽), но см. пункт 0.

**Оплата.** Берите помесячно, пока не убедитесь, что всё работает. Включите
автоплатёж или поставьте себе напоминание: сервер за неуплату выключают, а
вместе с ним — игру.

### Домен

Нужен, чтобы адрес мини-приложения перестал меняться. Telegram пускает
мини-приложения только по `https` с настоящим сертификатом, а сертификат
выдают на домен.

| Зона | Цена | Особенность |
|---|---|---|
| `.ru` | ~199 ₽ регистрация, ~399 ₽ продление в год | нужны паспортные данные |
| `.com` | ~1200–1600 ₽/год | без паспорта, понятен всем |
| `.xyz`, `.top`, `.fun` | первый год дёшево, дальше дороже | смотрите цену **продления**, а не первого года |

Где: [Beget](https://beget.com/ru/domains), [reg.ru](https://www.reg.ru/),
[Webnames](https://www.webnames.ru/). Разницы для нас нет; удобнее брать домен
там же, где сервер — меньше мест, где что-то настраивать.

Имя лучше короткое и такое, чтобы его можно было продиктовать по телефону.

### Итого

**От ~170 ₽ в месяц** (сервер 150 + домен 199 ₽/год ≈ 17 ₽/мес) до ~700 ₽,
если брать провайдера поудобнее. Это весь прод.

## 2. Порядок действий

### Шаг 1. Купить сервер

Ubuntu 24.04, зарубежная локация. После оплаты провайдер пришлёт **IP-адрес**
и пароль root (или попросит SSH-ключ — тогда следуйте его инструкции).

### Шаг 2. Купить домен и направить его на сервер

В панели регистратора: **DNS → добавить запись**

```
Тип: A       Имя: @      Значение: IP вашего сервера
Тип: A       Имя: www    Значение: IP вашего сервера
```

Записи расходятся по интернету от нескольких минут до пары часов. Проверить с
Мака:

```bash
ping ваш-домен.ру
```

Отвечает ваш IP — можно дальше.

### Шаг 3. Зайти на сервер

С Мака, в Терминале:

```bash
ssh root@IP-вашего-сервера
```

Спросит пароль (при вводе он не показывается — так и должно быть).

### Шаг 4. Запустить установку

**Репозиторий приватный**, поэтому скачать скрипт по прямой ссылке нельзя —
её отдаст только публичный репозиторий. Скопируйте его со своего Мака:

```bash
# на Маке, в папке проекта
scp deploy/install.sh root@IP-сервера:/root/install.sh
```

Потом на сервере:

```bash
ssh root@IP-сервера
sudo bash install.sh ваш-домен.ру
```

> Если репозиторий публичный, скрипт можно взять и прямой ссылкой:
> `curl -fsSL https://raw.githubusercontent.com/budilojo/TelegramBotPoker/claude/bold-carson-kjswyx/deploy/install.sh -o install.sh`

Репозиторий приватный, поэтому скрипт остановится и покажет **ключ** — строку,
начинающуюся с `ssh-ed25519`. Её надо один раз отдать GitHub:

1. Откройте репозиторий на github.com → **Settings** → **Deploy keys** →
   **Add deploy key**.
2. Title: `сервер`. Key: вставьте строку целиком.
3. Галочку «Allow write access» **не ставьте** — серверу хватит чтения.
4. Вернитесь в Терминал и запустите ту же команду ещё раз.

Дальше скрипт сам поставит Node 22, заберёт код, заведёт отдельного
пользователя, пропишет автозапуск, поднимет HTTPS, включит файрвол и заведёт
бэкап.

> Если репозиторий публичный, ключ не нужен: запустите скрипт с
> `REPO=https://github.com/budilojo/TelegramBotPoker.git sudo -E bash install.sh ваш-домен.ру`

### Шаг 5. Вписать токен

Токен скрипт не спрашивает специально: то, что набрано в командной строке,
остаётся в истории и в логах. Впишите его руками:

```bash
sudo -u worldcard nano /opt/worldcard/.env
```

Заполните:

```
BOT_TOKEN=токен от @BotFather
MINIAPP=WorldCard
ADMINS=1065958251
ADMIN_BOT_TOKEN=токен второго бота (если нужен)
```

Сохранить: `Ctrl+O`, `Enter`, выйти: `Ctrl+X`.

### Шаг 6. Запустить

```bash
sudo systemctl start worldcard
systemctl status worldcard
```

Должно быть зелёное `active (running)`.

### Шаг 7. Сказать Telegram новый адрес

У **@BotFather**: `/myapps` → ваше приложение → **Edit Web App URL** →
`https://ваш-домен.ру`

Это последний раз, когда вы туда ходите: адрес больше не меняется.

### Шаг 8. Проверить

В группе `/game` → «Выбрать игру» → должно открыться приложение.

## 3. Что теперь умеет сервер

| Что | Как это выглядит |
|---|---|
| **Автозапуск** | перезагрузили сервер — бот поднялся сам |
| **Перезапуск после падения** | упал — systemd поднимает через 5 секунд |
| **HTTPS** | Caddy сам получил сертификат и сам продлевает его |
| **Файрвол** | наружу открыты только SSH и сайт |
| **Бэкап** | каждую ночь в 4:00, хранится две недели, в `/opt/worldcard/backups` |
| **Отдельный пользователь** | бот не ходит под root; ему доступна на запись только своя папка |

## 4. Команды, которые пригодятся

```bash
systemctl status worldcard          # жив ли бот
journalctl -u worldcard -f          # смотреть логи вживую (выйти — Ctrl+C)
journalctl -u worldcard -n 100      # последние 100 строк
sudo systemctl restart worldcard    # перезапустить
sudo systemctl stop worldcard       # остановить

sudo /opt/worldcard/deploy/update.sh              # обновиться до свежей версии
sudo -u worldcard /opt/worldcard/deploy/backup.sh # бэкап прямо сейчас
```

Обновление само снимает бэкап, прогоняет тесты и только потом перезапускает
бота: если тесты не прошли, старая версия продолжает работать.

**Запасной ход на случай долгих работ:** перед обновлением включите режим
обслуживания в пульте (или `/pause` у админ-бота) — игроки увидят «идёт
обслуживание» вместо ошибки, и ничьё время на ход не сгорит.

## 5. Если что-то не так

| Симптом | Что смотреть |
|---|---|
| Приложение не открывается | `curl -I https://ваш-домен.ру` — если не отвечает, дело в домене или Caddy: `systemctl status caddy` |
| «Сертификат недействителен» | домен ещё не долетел до сервера; подождите и `sudo systemctl restart caddy` |
| Бот молчит в Telegram | `journalctl -u worldcard -n 50`. `401` — не тот токен. Таймауты к api.telegram.org — площадка в России, см. пункт 0 |
| `active (running)`, но игра не идёт | проверьте `WEBAPP_URL` в `.env` и адрес у @BotFather — они должны совпадать |
| Кончилось место | `df -h`, потом `du -sh /opt/worldcard/*` — чаще всего это старые бэкапы или логи |

---

## 6. Чего делать не надо

- **Не запускайте бота второй раз** (на ноутбуке и на сервере одновременно) с
  одним токеном: Telegram отдаёт обновления только одному, и оба будут
  «моргать». На ноутбуке для проверок заведите отдельного тестового бота.
- **Не кладите `.env` в git** и не пересылайте его. Утёк токен — сразу
  @BotFather → `/mybots` → `Revoke`.
- **Не ставьте панели вроде ISPmanager** ради одного бота: больше настроек,
  больше дыр, пользы ноль.
- **Не отключайте файрвол**, чтобы «заработало»: не заработает, а найдут вас
  быстро.
