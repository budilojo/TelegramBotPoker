# Отчёт: homescreen (иконка на рабочий стол)

## 1. Что сделано
* **Сверка с официальным источником (2026-10-27)**, `https://core.telegram.org/bots/webapps` (страница описывает Bot API 10.1): `addToHomeScreen()` и `checkHomeScreenStatus([callback])` — с Bot API 8.0; статусы `unsupported / unknown / added / missed`; события `homeScreenAdded` (может не прийти даже при успехе) и `homeScreenChecked`. **События `homeScreenFailed` в документации нет** — название из контракта было гипотезой; код слушает его необязательно. Точная поддержка платформ (iOS/Android/Desktop/Web) в документации не описана — не подтверждено. Подробности — `docs/homescreen.md`.
* `miniapp/homescreen.js` — чистая логика: недоступно / проверяем / можно / ожидание / добавлено / не получилось. Успех — только по `homeScreenAdded` или ответу `added` на повторную проверку; таймауты 6 с (проверка) и 30 с (ожидание, после чего Telegram переспрашивается). Повторное нажатие в ожидании невозможно.
* `miniapp/homescreen-row.js` — строка «Добавить на рабочий стол» через реестр. Без импорта `ui.js` (иначе тест реестра в Node падал на `window`). Автоматического предложения нет.
* `docs/homescreen.md` — факты, устройство, что не гарантируется, **предложение** правила автоподсказки (3 партии, не чаще раза в 30 дней, «Не напоминать»; пороги не утверждены), риски, метрики, отличие от внешней оплаты.
* Решения 125 и 126.

* `bot/homescreen.test.js` — 15 тестов; `tools/e2e-homescreen.mjs` (Chromium, заглушка Telegram, 320/360/390/430 px, фокус, кнопка ≥ 44 px, без горизонтального скролла, `assertNoJump`, перемотка часов страницы на таймаут) — «всё сошлось». Скриншоты (`SHOTS=1`, `preview/homescreen/`) просмотрены глазами: строка в стиле соседних, без наложений.
* Исправлены **мои** тесты-фикстуры: ожидание подписки (начальное «checking» уже было) и «статус undefined» (значение по умолчанию в заглушке подменяло undefined).
* Первый прогон `npm test` падал на `bot/collections.catalog.test.js` («window is not defined») из-за моей строки — исправлено в продакшен-коде строки, тест не трогал.

## 3. Защиты «на зубы» (`node tools/graphit-icon-teeth.mjs`)
| Защита | Как сломана | Тест упал? |
|---|---|---|
| успех только по подтверждению | `set('added')` сразу после вызова | да |
| строка скрыта без метода/версии | `supported = true` | да |
| таймаут | `arm` ничего не ставит | да |
| нет автопоказа | `setTimeout(add)` при показе строки | да |
| «не добавлено» после попытки ≠ успех | в этом случае `added` | да |
| нет повторного нажатия в ожидании | снято условие состояния | да |

## 4. Не удалось / не проверено
**Не проверено на телефоне в живом Telegram:** реальное добавление иконки (iOS, Android), что возвращает проверка статуса на этих клиентах, приходит ли `homeScreenAdded`, системное окно, вид и запуск иконки, Desktop/Web. Эмуляция в Chromium — не Telegram.
Ограничение: «Настройки» перерисовываются, и строка пересоздаётся; в «ожидании» это приведёт к повторной проверке статуса (она честно покажет «добавлено», если иконка встала).

## 5. Запросы к контракту
Раздел 10: заменить «событие `homeScreenFailed`» на факт — в официальной документации его нет; отказ определяется таймаутом и повторной проверкой статуса.

## 6. Фрагменты для общих файлов
* **`MESSAGES.md`** (место — `miniapp/homescreen.js`, `rowText`, и `miniapp/homescreen-row.js`): заголовок «Добавить на рабочий стол»; «Недоступно в этом Telegram. Обновите приложение Telegram, если хотите добавить иконку.»; «Проверяем…»; «Иконка откроет это приложение внутри Telegram.» (кнопка «Добавить»); «Ждём ответа Telegram. Подтвердите добавление в окне Telegram.»; «Иконка уже на рабочем столе.»; «Не удалось проверить. Попробуйте ещё раз.»; «Telegram не подтвердил добавление. Иконка могла не добавиться — попробуйте ещё раз.» (кнопка «Повторить»).
* **`docs/redesign.md`:** новых токенов нет (используются `.set-row`, `.set-sub`, `.btn.sm`).
* **`package.json`:** `"e2e:homescreen": "node tools/e2e-homescreen.mjs"`; `node tools/graphit-icon-teeth.mjs` — по желанию в проверки.
* **Память проекта:** иконка на рабочий стол — строка в «Настройках», только по кнопке; успех только по подтверждению; события отказа в официальной документации нет; живой Telegram не проверен; решения 125, 126.
