## 2. Протокол «страница ↔ сервер» (`{ t: 'col', … }`)

Общий словарь операций и кодов отказа — `miniapp/collections/protocol.js` (чистый модуль; создаёт `lead-contracts`):

```js
export const OPS = ['state', 'grant', 'apply', 'clear'];
export const ERRORS = {   // коды и тексты по-русски; сервер отдаёт { code, text }
  COL_OFF: 'Коллекции сейчас недоступны.',
  COL_DEMO_OFF: 'Демонстрационное получение здесь выключено.',
  COL_OP: 'Не понял запрос.',
  COL_ITEM: 'Такого предмета нет.',
  COL_COLOR: 'Такого цвета нет.',
  COL_SLOT: 'Этот предмет не подходит сюда.',
  COL_NOT_OWNED: 'Этот предмет не в вашей коллекции.',
  COL_FAST: 'Слишком часто. Подождите немного.',
  COL_STALE: 'Данные устарели — обновите экран.',
  COL_BUSY: 'Запрос уже выполняется.',
};
```

Сообщения (идентичность — **только** `session.user`, полученный из подписанного `initData`; поля `userId`, `uid`, `name`, `owner`,
`demo`, `price`, `unlocked`, `host` в теле **игнорируются**; сессии администратора/`admin` отвечают `COL_OP`):

| Запрос | Ответ при успехе (всегда `{ t:'col', op, … }`, при отказе `{ t:'col', op, error:{code,text} }`) |
|---|---|
| `{ t:'col', op:'state' }` | `state` (ниже) |
| `{ t:'col', op:'grant', item, req }` — демо-получение предмета или комплекта; `req` — строка 8–64 символа `[A-Za-z0-9_-]`, идентификатор запроса | `state`; повтор с тем же `req` возвращает тот же результат, **ничего не удваивая**; вне демосреды — отказ `COL_DEMO_OFF` |
| `{ t:'col', op:'apply', slot, item, color, req }` | `state` + `when: 'now'\|'next-deal'`; нет права — `COL_NOT_OWNED`; цвет/слот не те — `COL_COLOR`/`COL_SLOT` |
| `{ t:'col', op:'clear', slot, req }` — вернуть базу | `state` |

`state` (то, что видит **только сам игрок**; чужое не передаётся никому):

```js
{ t:'col', op:'state', v:1,
  enabled: true,                 // модуль включён на сервере
  demo: false,                   // true ТОЛЬКО в демосреде (см. п. 3); клиент другим путём демо не включает
  owned: [{ item:'graphit-cardback', demo:true }],       // демо-владение помечено; реального владения в этой версии нет
  choice: { cardback:{ item, color }|null, table:…|null, profile:…|null },   // выбранное оформление (null = база)
  pending: { cardback:'next-deal'|null, table:…|null, profile:null }         // применится со следующей раздачи (иначе null)
}
```
`state` приходит в ответе на любой запрос и при подключении/переподключении **только если `enabled`**; иначе клиент получает
`{ t:'col', op:'state', v:1, enabled:false, demo:false, owned:[], choice:{…null}, pending:{…null} }` и не показывает ни одной точки входа.

Ограничения: не чаще 20 запросов/мин на человека (по часам приложения `app.clock.now()`, не по `Date.now()`); `req` обязателен
у `grant`/`apply`/`clear`; параллельный второй запрос с другим `req` на тот же слот, пока первый обрабатывается, — `COL_BUSY`
(на практике сервер синхронный: проверить в тесте повтор и гонку двух страниц одного игрока).

## 3. Демосреда (жёсткие требования)

* Включение — **только** серверной настройкой процесса: переменная окружения `COLLECTIONS_DEMO`, значение ровно `1`
  (любое другое, пустое, `true`, `yes`, пробелы — выключено). Читается **один раз** при создании приложения, передаётся в `App`
  опцией `collectionsDemo` (в тестах — опция). По умолчанию `false`. Не хранится в базе, не меняется командами, не зависит от
  админских прав и от `cosmeticsUnlocked` (это другое: старый магазин).
* Ни параметр URL, ни `localStorage`, ни поле в сообщении, ни `Telegram.WebApp.initDataUnsafe`, ни название предмета, ни цена
  не включают демо. Клиент узнаёт `demo` **только** из серверного `state.demo` и использует его **только** для показа кнопки
  «Получить для демонстрации» и подписи «Демонстрация · Без оплаты»; решает сервер.
* Демо-права лежат в **отдельной** таблице `collection_demo_grant (user_id, item, granted_at, PRIMARY KEY (user_id, item))`.
  Реальных прав в этой версии нет, таблица реальных прав **не создаётся**. Если `collectionsDemo` выключен, строки демо-таблицы
  **игнорируются** при проверке права (база могла быть скопирована из демосреды) и `owned` пуст.
* Демо-право никогда не превращается в реальное: нет кода переноса, миграции или «засчитывания».
* В рабочем режиме (демо выключено): витрина, карточки, примерка и инвентарь **не открываются**, точка входа не показывается;
  вкладка «Магазин» остаётся «скоро» + счётчик (решение 106) и **не меняется**.

## 4. Хранение (новые таблицы; версия схемы 5 **не** поднимается; `CREATE TABLE IF NOT EXISTS`)

```sql
CREATE TABLE IF NOT EXISTS collection_demo_grant (user_id TEXT NOT NULL, item TEXT NOT NULL, granted_at INTEGER NOT NULL,
  PRIMARY KEY (user_id, item));
CREATE TABLE IF NOT EXISTS collection_choice (user_id TEXT NOT NULL, slot TEXT NOT NULL, item TEXT NOT NULL, color TEXT NOT NULL,
  updated_at INTEGER NOT NULL, PRIMARY KEY (user_id, slot));
```

`collection_req` хранит последние идентификаторы запросов на человека (ротация, не больше 50) для идемпотентности. Версия схемы остаётся
5; старый код сервера (`git show 7afb285:bot/store.js`) открывает такую базу — **проверить и показать в отчёте**. Реализовать и в
`Store` (SQLite), и в `MemStore` (тестовая память) — оба с одинаковым поведением. Комплект при получении раскладывается на три
строки предметов (в базе комплекта как сущности нет). Переопределение выбранного цвета предмета — запись в `collection_choice`.

## 5. Оформление комнаты: снимок раздачи

Выбранное (`choice`) и **снимок раздачи** (`room.look`) — разные вещи.

```js
room.look = {
  v: 1,
  table: { item, color } | null,                 // оформление стола комнаты, действующее в ТЕКУЩЕЙ раздаче
  backs: { [playerId]: { item, color } },        // рубашки владельцев на этой раздаче (только покер; нет записи = база)
  frames: { [playerId]: { item, color } },       // рамка+знак на момент снимка (лобби обновляется вживую, см. ниже)
  dealNo: number,                                // номер раздачи/партии, для которой снят снимок (0 — лобби)
}
```
Правила (источник: SPEC «Момент применения»; допущение зафиксировано, а не придумано):
* **Лобби до начала** (нет раздачи): `look` собирается заново при каждом запросе вида и каждом изменении выбора — **сразу**.
* **Начало раздачи** (покер: сдача `startHand` в `bot/room.js`; дурак: начало партии/«ещё одна партия» — найти фактические точки и
  записать в отчёте): снимок собирается **один раз** из текущего выбора: стол — выбор **текущего хоста** (`room.hostId`); рубашки —
  выбор каждого сидящего игрока (только покер); рамки — выбор каждого. Дальше снимок **заморожен** до конца раздачи.
* **В раздаче** изменение выбора любым игроком (в том числе хоста) **не** меняет `room.look`; `pending` в `state` отражает
  «применится со следующей раздачи». Переподключение, перенос хоста, выход/возврат игрока **не** пересобирают снимок.
* **Следующая раздача** — новый снимок из выбора, актуального на этот момент (в том числе стол нового хоста). Кто хост при снимке — берётся
  из `room.hostId` в момент снимка (допущение: стол «хоста»; перенос хоста посреди раздачи ничего не меняет, со следующей — стол нового хоста.
  Если жизненный цикл хоста в коде говорит иначе — `server` фиксирует фактическое поведение в отчёте как «Запрос к контракту»).
* Снимок **сериализуется** вместе с комнатой (переживает перезапуск сервера) и **не** влияет на правила, часы, рейтинг, шансы.
  Старые строки комнат без `look` читаются как «база» (без ошибок).
* Результаты: рамка/знак в уже сохранённых итогах — **снимок на момент итога** (`results.players[].frame`); новые итоги берут актуальное
  оформление.
* Проверка прав при снимке: если в выборе лежит предмет, на который права **нет** (например, демо выключили), в снимок попадает база.

## 6. Поля `view` (персональные, как сейчас: `view(room, viewerId)`)

Добавляется (и больше ничего) в `tableView` покера (`bot/view.js`) и `view` дурака (`bot/games/durak/view.js`):

```js
look: { v:1, table: {item,color}|null,
        backs: [{ seat, item, color }],        // только покер; по номеру места; не больше одной записи на место; без id игрока
        dealNo }                              // чтобы клиент не перерисовывал вид посреди раздачи
players[i].frame: { item, color } | null       // рамка и знак (публичные данные профиля), покер и дурак, лобби и итоги
```
Никаких идентификаторов пользователей, информации о владении другими предметами, демо-флагов, цен и `choice`/`pending` других людей в
`view` нет. Чужие карты и колоды не затрагиваются. Базовый вид = поле `null`/отсутствие записи. Шахматы, шашки, нарды, морской бой, UNOQ:
**не менять** (клиент их вид не использует).

## 7. Ресурсы (SVG, локальные)

Папка `miniapp/collections/art/`; создаёт и поддерживает `assets` (генератор `tools/build-graphit-art.mjs`, детерминированный:
повторный запуск даёт те же байты). Имена (по одной геометрии на вид, цвет — суффикс, `<c>` ∈ `graphite|sapphire|bordeaux|petrol`):

| Файл | Где используется |
|---|---|
| `cardback-detail-<c>.svg` | карточка, примерка, инвентарь (viewBox `0 0 200 280`) |
| `cardback-small-<c>.svg` | закрытые карты в игре и миниатюры (тот же viewBox, упрощённая) |
| `table-ornament-<c>.svg` | край стола покера/дурака; центр свободен; применение — см. `art/README.md` (его пишет `assets`) |
| `table-diamond-<c>.svg` | центральный знак стола (отдельный слой) |
| `frame-detail-<c>.svg`, `frame-small-<c>.svg` | рамка аватара: крупная и малая (квадрат `0 0 120 120`, прозрачный центр) |
| `mark-<c>.svg` | знак рядом с именем (полый ромб, `0 0 24 24`) |
| `thumb-cardback-<c>.svg`, `thumb-table-<c>.svg`, `thumb-profile-<c>.svg`, `bundle-<c>.svg` | витрина, переключатель цвета, комплект |
| `manifest.json` | список файлов, размеры, viewBox, байты, хэш (для тестов и клиента) |

Требования: плоские заливки и линии (**без** `linearGradient`, `radialGradient`, `filter`, `feDropShadow`, `mask` с градиентом, `opacity` для
«тональных переходов», `<image>`, внешних ссылок, `<script>`, `<style>` с `url()`); цвета только из палитры `COLORS` (фон предмета + линия); одна
геометрия, одинаковые viewBox и толщины во всех четырёх цветах; декоративные SVG — `aria-hidden`/без текста; вес каждого файла ≤ 24 КБ
(подробные) и ≤ 8 КБ (упрощённые), общий бюджет — в `art/README.md`. Лица карт и масти **не** перекрашивать. Рамка не обрезает аватар;
знак не расширяет строку имени.

Клиентский помощник `miniapp/collections/art.js` (владелец `client`): `artUrl(kind, color, detail)` → `/collections/art/…`; при ошибке загрузки
`onerror` → база (классика проекта), игра не страдает. Статические файлы раздаются как остальные (`/collections/art/*` — проверить в
`bot/server.js`, как раздаётся `miniapp/`).

## 8. Клиентская часть

* **Точка входа:** строка «Коллекции» в «Настройках» через реестр строк `miniapp/settings-rows.js` (создаёт `lead-contracts`; в реестре два
  модуля: `miniapp/collections/settings-row.js` — владелец `client`; `miniapp/homescreen-row.js` — владелец `homescreen`). Строка показывается
  **только** когда сервер прислал `state.enabled && state.demo` и подпись «Демонстрация · Без оплаты». В рабочем режиме её нет.
* Экраны (`client`): витрина → карточка (предмет/комплект, четыре подписанных цвета с галочкой и нейтральным светлым контуром выбранного,
  не синим) → примерка (отдельное локальное состояние; блок «Так видят друзья» **только** здесь; текущую партию не трогает) →
  «Получить для демонстрации» (подпись «Демонстрация · Без оплаты»; ответ сервера, не локальное предположение) → получение (состав,
  переключатели применения, переход в инвентарь) → инвентарь (вкладки «Карты», «Столы», «Профиль»; база и полученное; «В вашей коллекции»,
  «Применено», «Применится со следующей раздачи»; возврат к базе).
* Частично купленный комплект (в демо — частично полученный): показать имеющееся и недостающее; кнопка комплекта заблокирована с пояснением, что
  цена дополнения не утверждена; **никакого** правила цены не изобретать.
* Выбор считается сохранённым **только после ответа сервера**; до ответа — прежний вид, кнопка защищена от повторного нажатия, при ошибке
  показано словами и «Повторить». Нет связи — «Повторить», владение не выдаётся локально.
* Роутинг сообщений: в `miniapp/net.js` ветка `msg.t === 'col'` → `bus.onCollections(msg)` (владелец `client`).
* Игровые экраны (`screens`) **не** читают `state`; они берут оформление только из `view.look` и `players[].frame` (п. 6).
* Тексты — русские, Stars в подписях — исключение; цены (79/99/199/249) — демонстрационные и показываются только в демо с пометкой.

## 9. Игровые экраны (`screens`)

* Рубашка покера: закрытые карты каждого места рисуются рубашкой из `look.backs` для этого `seat`; лица собственных открытых карт — **не**
  заменять; блок «Так видят друзья» в игре **не** показывать.
* Стол: оформление `look.table` применяется к овалу покера (`.felt`) и дурака (`.dk-felt`) как край-орнамент и центральный ромб; **центр
  свободен**; карты, банк и кнопки читаемы (при минимальных размерах стола 320 px); раскладку (`layoutTable`, `watchBox`) не ломать.
* Рамка и знак: `players[].frame` в **лобби и результатах** покера и дурака; в самой партии рамку не показывать (SPEC); имена не переносятся
  и не расширяют строку (длинные имена сокращаются по текущим правилам, полное имя — в подписи для чтения экраном); готовность — отдельный
  текст, а не рамка.
* Базовый вид — при `null`/отсутствии файла (`onerror`). Смена `look` посреди раздачи не происходит: клиент реагирует на `dealNo`.
* Никаких таймеров/анимаций сверх существующих; `prefers-reduced-motion` уважать.

## 10. Иконка на рабочий стол (`homescreen`) — независима от коллекций
