# Задание: lead-contracts

**Фаза 1 координатора.** Единственный исполнитель, который работает один и **раньше всех**. Результат — проверенные контракты и каркас общих файлов, на которые
опираются остальные.

## Обязательные материалы
`AGENTS.md`; `docs/brain/00-index.md`, `status.md`, `tasks.md`, последний файл `docs/brain/sessions/`; `docs/graphit-launch/README.md`, `00-plan.md`, `contracts.md`,
`ownership.md`, `acceptance.md`; `design/collections/README.md`, `SPEC.md`, `ASSET-LIST.md`, `CLAUDE-CODE-PROMPT.md`; `docs/brain/decisions/106-shop-tab-counter.md`;
`docs/redesign.md`, `docs/game-hub.md`, `MESSAGES.md` (разделы про покер, дурак, лобби, профиль).
Код: `bot/hub.js` (виды сессий, обработка `shop`, `hubView`), `bot/app.js` (опции `App`, `cosmeticsUnlocked`), `bot/index.js` (чтение окружения), `bot/store.js` (`Store`, `MemStore`,
прецедент таблиц `profiles`, `shop_tab`), `bot/room.js` (сдача покера, `hostId`, `reassignHost`, `serialize`), `bot/view.js`, `bot/games/poker/index.js`,
`bot/games/durak/{index,rules,view}.js` (старт партии, «ещё одна партия», `nextGame`), `bot/server.js` (как отдаётся `miniapp/`), `miniapp/net.js`, `miniapp/nav.js` (вкладка «Настройки»),
`miniapp/index.html`, `miniapp/games/poker.js` и `durak.js` (лобби и результаты), `bot/harness.js`, `tools/graphit-run.mjs` (как тебя запускают).

## Цель
1. Сверить `contracts.md` с кодом **по каждому разделу**. Для каждого: «подтверждено» или «поправка». Найти и записать **фактические** точки снимка раздачи (покер: функция, где
   начинается раздача; дурак: начало партии и «ещё одна партия»), жизненный цикл хоста (создание комнаты, передача, исчезновение хоста), способ сериализации комнаты, как
   клиент получает сообщения нового типа, как раздаются статические файлы под `/collections/…`, где читается окружение для опции демосреды. Записать в раздел 12 «Поправки (фаза 1)» в
   `contracts.md` — **только поправки и факты**, структуру контракта не переписывай.
2. Создать каркас общих файлов: `miniapp/collections/catalog.js` и `protocol.js` по разделам 1–2 контракта (чистые модули, без DOM и без зависимостей); тест
   `bot/collections.catalog.test.js` (идентификаторы уникальны и стабильны; цвета ровно четыре и с HEX из SPEC; комплект содержит три предмета; `itemById` не принимает префиксы;
   база не конфликтует с id предметов; цены помечены как демонстрационные); реестр `miniapp/settings-rows.js` и подключение в `miniapp/nav.js` («Настройки» показывают строки из
   реестра после существующих; пустая строка `null` не рисуется как слово); **заготовки** `miniapp/collections/settings-row.js`, `miniapp/homescreen-row.js` (экспорт функции строки,
   возвращающей `null`), пустые `miniapp/collections.css`, `miniapp/collections-look.css` с комментарием и ссылки на них в `miniapp/index.html`. Реестр не должен менять вид «Настроек» сейчас.
3. Убедиться, что **ничего из рабочего режима не изменилось** (вкладки, «Магазин — скоро», профиль): `npm test`, `npm run e2e` на файлах про навигацию/настройки/профиль/магазин.

## Границы
Никакого функционала коллекций, сервера, ресурсов, экранов. Не менять `contracts.md` за пределами раздела 12. Старый набор «Ночной казино-клуб» не трогать.

## Зависимости
Нет (запускаешься первым). Все остальные ждут твой статус `done`.

## Вход / выход
Вход: репозиторий на `gr/integration` (= `redesign` на момент старта). Выход: коммиты в `gr/lead-contracts` (файлы из `owns` и `stubs`), раздел 12 контракта, отчёт и статус.

## Проверки
`npm test` зелёный; `node --check` изменённых модулей; `npm run e2e` для навигации/профиля/магазина; в отчёте — список «подтверждено / поправка» по разделам 1–11 контракта и точные
имена функций и файлов, которые понадобятся `server` и `screens`.

## Общие правила исполнителя (одинаковы у всех заданий пакета)

* **Где ты:** запущен скриптом `tools/graphit-run.mjs` в своей рабочей копии `../TelegramBotPoker-gr-lead-contracts` на ветке `gr/lead-contracts`. Проверь:
  `git branch --show-current` → `gr/lead-contracts`. Основную папку `~/TelegramBotPoker` и ветку `redesign` **не трогай**. `git push` **не делай** — слияние и публикацию
  выполняет скрипт. Коммить только в свою ветку; перед **каждым** коммитом — `npm test` целиком; коммиты русскими предложениями («коллекции: …»).
* **Повторный запуск:** если в ветке уже есть твои коммиты или `docs/graphit-launch/reports/lead-contracts.md`, сначала прочитай `git log --oneline gr/integration..HEAD`
  и свой отчёт, **продолжи** с места остановки, не переделывай готовое и не дублируй файлы.
* **Зона:** правь только файлы из `agents.json` → `owns` («Карта ответственности» — `docs/graphit-launch/ownership.md`). Общие файлы (`MESSAGES.md`,
  `docs/redesign.md`, `package.json`, `AGENTS.md`, `docs/brain/*` кроме своих решений, `miniapp/index.html`) **не правь**: тексты, токены, строки e2e и память
  оформи фрагментами в отчёте. Чужую зону не правь даже «по мелочи».
* **Связь с другими агентами нет** (нет `SendMessage`): нужное изменение контракта — раздел «Запросы к контракту» в отчёте и минимальный совместимый вариант.
  Контракт — `docs/graphit-launch/contracts.md`; при противоречии побеждают `design/collections/SPEC.md`, затем фактический код.
* **Правила проекта (`AGENTS.md`):** личность только из подписанного `initData`; персональные `view`, чужие карты/колоды не передавать; оформление не влияет на правила,
  часы, рейтинг, шансы; `server/game.js` не менять; токен бота не спрашивать и не показывать, `.env` не открывать; без PR, выкатки, `--force`, правок на сервере;
  интерфейс русский, числа `1.200`, покерные действия английские (Fold, Check, Call, Bet, Raise, All-in); дизайн-система `docs/redesign.md`
  (плоско, без золота, градиентов, свечения, теней; токены; 6/8/12; зона нажатия ≥ 44 px; ничего с внешних доменов).
* **Порты и параллельность:** другие исполнители работают одновременно на этом же компьютере. Для браузерных проверок тебе выдана переменная `E2E_PORT` (не меняй её); если тест упал из-за занятого порта или
  нагрузки — повтори этот файл отдельно, не записывай это как красное без повторной проверки (и пиши в отчёт, что повторял).
* **Тесты не ослаблять.** Падает тест — по умолчанию неправ код. Каждую новую защиту проверь «на зубы» (верни поломку — тест падает) и запиши результат.
  Не заявляй проверку в живом Telegram: эмуляция Chromium — не Telegram.
* **Решения:** свои решения — файлами `docs/brain/decisions/NNN-короткое-имя.md` по шаблону `000-template.md`, номера **107–109** (только твой диапазон).
* **Отчёт (обязательно):** `docs/graphit-launch/reports/lead-contracts.md` по-русски простыми словами: 1) что сделано; 2) какие проверки запущены и результат (числа); 3) таблица «защита →
  как сломана → упал ли тест»; 4) что не удалось/не проверено, **отдельно «Не проверено на телефоне в живом Telegram»**; 5) «Запросы к контракту»; 6) «Фрагменты для общих файлов»
  (тексты для `MESSAGES.md` с местом в коде; токены для `docs/redesign.md`; строки e2e для `package.json`; заметки для памяти проекта); 7) вопросы владельцу.
* **Статус (обязательно, последним шагом):** `docs/graphit-launch/reports/lead-contracts.status.json`:
  `{"id":"lead-contracts","status":"done|partial|blocked","summary":"одна-две фразы","at":"ISO-время завершения (например, 2026-10-27T12:34:56Z; поле обязательно и должно меняться при каждой записи)","tests":{"npm_test":"N/N","other":["…"]},"commits":["хэш…"],"not_verified":["…"],"requests":["…"]}`.
  `done` — всё в задании выполнено и проверки зелёные; `partial` — часть сделана (что именно — в `summary`); `blocked` — дальше нельзя (причина). Отчёт и статус коммитятся в твою ветку.
