# Задание: homescreen

**Иконка на рабочий стол встроенной возможностью Telegram.** Независимо от магазина, платежей и коллекций.

## Обязательные материалы
`AGENTS.md`; `docs/graphit-launch/README.md`, `00-plan.md`, `contracts.md` (раздел **10**), `ownership.md`, `acceptance.md`; `docs/brain/00-index.md`, `status.md`, `tasks.md`; `docs/redesign.md`; `miniapp/nav.js` (вкладка «Настройки»),
`miniapp/settings-rows.js`, `miniapp/homescreen-row.js` (заготовка), `miniapp/ui.js` (`tg`), `miniapp/profile.js` (образец строки настроек), `tools/e2e-profile.mjs` (заглушка Telegram в e2e), `docs/scroll.md`.
Официальные источники **сначала**: `https://core.telegram.org/bots/webapps` (разделы о главном экране/`addToHomeScreen`, `checkHomeScreenStatus`, событиях, `isVersionAtLeast`, платформе) и Bot API.

## Цель
1. **Проверить по актуальным официальным источникам** (с датой в `docs/homescreen.md`): точные названия методов и событий добавления иконки и проверки статуса, с какой версии Bot API/клиента они работают, особенности платформ
   (iOS, Android, Desktop, Web), что именно возвращает проверка статуса, как узнать об отказе. Названия из контракта — **гипотезы**, не факты. Если метода нет или не удалось подтвердить — это результат: пиши прямо.
2. **Пункт в «Настройках»** (`miniapp/homescreen-row.js` через реестр): строка «Добавить на рабочий стол» с состояниями: «недоступно в этом Telegram» (метода нет/версия мала), «можно добавить», «ожидание», «уже добавлено»
   (только по подтверждению проверки статуса), «не получилось/отказ» (с повтором). **Не заявлять успех** без подтверждения (событие или повторная проверка статуса). Состояния без вечных спиннеров (таймаут).
3. **Нет навязчивых предложений:** никаких всплывающих окон при каждом входе; автоматическое предложение **не реализовывать**.
4. **Предложить правило автоподсказки** в `docs/homescreen.md`: конкретное (например, «один раз после N завершённых партий, не чаще раза в M дней, с кнопкой „Не напоминать"») — **как предложение владельцу**, не как утверждённый порог;
   перечислить риски (раздражение, нарушение ожиданий), как измерять результат, чем это отличается от «ссылки на внешнюю оплату» (ничем не связано с оплатой).
5. Отдельно в `docs/homescreen.md`: что **не** гарантируется (иконка открывает то же Mini App внутри Telegram; поведение зависит от клиента), что не проверено на телефоне.

## Границы
Файлы из `owns`. Не менять магазин, коллекции, оплату. Не добавлять внешних скриптов (SDK Telegram уже подключён страницей — используй существующий `tg`).

## Зависимости
Только каркас реестра строк (`lead-contracts`). От магазина и платежей **не зависит**.

## Вход / выход
Вход: реестр `settings-rows.js`. Выход: `miniapp/homescreen.js`, `homescreen-row.js`, документ `docs/homescreen.md`, тесты, отчёт; в отчёте — ссылки и дата проверки источников.

## Проверки
`bot/homescreen.test.js` (чистая логика состояний на фиктивных ответах: нет метода, версия мала, статус «добавлено/не добавлено/неизвестно», отказ, таймаут, повторное нажатие); `tools/e2e-homescreen.mjs` на заглушке Telegram с разными
наборами методов (нет метода; метод есть, статус «не добавлено»; успех подтверждён; отказ; успех **не** подтверждён → иконка не объявляется добавленной), 320/360/390/430 px, длинные подписи, фокус, `assertNoJump`;
**«на зубы»** (`tools/graphit-icon-teeth.mjs`): объявить успех без подтверждения; показать строку при отсутствии метода; убрать таймаут; показывать подсказку автоматически — тесты падают. Скриншоты посмотреть глазами.
Не проверено на телефоне: реальное добавление иконки, внешний вид в клиентах — так и написать.

## Общие правила исполнителя (одинаковы у всех заданий пакета)

* **Где ты:** запущен скриптом `tools/graphit-run.mjs` в своей рабочей копии `../TelegramBotPoker-gr-homescreen` на ветке `gr/homescreen`. Проверь:
  `git branch --show-current` → `gr/homescreen`. Основную папку `~/TelegramBotPoker` и ветку `redesign` **не трогай**. `git push` **не делай** — слияние и публикацию
  выполняет скрипт. Коммить только в свою ветку; перед **каждым** коммитом — `npm test` целиком; коммиты русскими предложениями («коллекции: …»).
* **Повторный запуск:** если в ветке уже есть твои коммиты или `docs/graphit-launch/reports/homescreen.md`, сначала прочитай `git log --oneline gr/integration..HEAD`
  и свой отчёт, **продолжи** с места остановки, не переделывай готовое и не дублируй файлы.
* **Зона:** правь только файлы из `agents.json` → `owns` («Карта ответственности» — `docs/graphit-launch/ownership.md`). Общие файлы (`MESSAGES.md`,
  `docs/redesign.md`, `package.json`, `AGENTS.md`, `docs/brain/*` кроме своих решений, `miniapp/index.html`) **не правь**: тексты, токены, строки e2e и память
  оформи фрагментами в отчёте. Чужую зону не правь даже «по мелочи».
* **Связь с другими агентами нет** (нет `SendMessage`): нужное изменение контракта — раздел «Запросы к контракту» в отчёте и минимальный совместимый вариант.
  Контракт — `docs/graphit-launch/contracts.md`; при противоречии побеждают `design/collections/SPEC.md`, затем фактический код.
* **Правила проекта (`AGENTS.md`):** личность только из подписанного `initData`; персональные `view`, чужие карты/колоды не передавать; оформление не влияет на правила,
  часы, рейтинг, шансы; `server/game.js` не менять; токен бота не спрашивать и не показывать, `.env` не открывать; без PR, выкатки, `--force`, правок на сервере;
  интерфейс русский, числа `1.200`, покерные действия английские (Fold, Check, Call, Bet, Raise, All-in); дизайн-система `docs/redesign.md`
  (плоско, без золота, градиентов, свечения, теней; токены; 6/8/12; зона нажатия ≥ 44 px; ничего с внешних доменов).
* **Порты и параллельность:** другие исполнители работают одновременно на этом же компьютере. Для браузерных проверок тебе выдана переменная `E2E_PORT` (не меняй её); если тест упал из-за занятого порта или
  нагрузки — повтори этот файл отдельно, не записывай это как красное без повторной проверки (и пиши в отчёт, что повторял).
* **Тесты не ослаблять.** Падает тест — по умолчанию неправ код. Каждую новую защиту проверь «на зубы» (верни поломку — тест падает) и запиши результат.
  Не заявляй проверку в живом Telegram: эмуляция Chromium — не Telegram.
* **Решения:** свои решения — файлами `docs/brain/decisions/NNN-короткое-имя.md` по шаблону `000-template.md`, номера **125–127** (только твой диапазон).
* **Отчёт (обязательно):** `docs/graphit-launch/reports/homescreen.md` по-русски простыми словами: 1) что сделано; 2) какие проверки запущены и результат (числа); 3) таблица «защита →
  как сломана → упал ли тест»; 4) что не удалось/не проверено, **отдельно «Не проверено на телефоне в живом Telegram»**; 5) «Запросы к контракту»; 6) «Фрагменты для общих файлов»
  (тексты для `MESSAGES.md` с местом в коде; токены для `docs/redesign.md`; строки e2e для `package.json`; заметки для памяти проекта); 7) вопросы владельцу.
* **Статус (обязательно, последним шагом):** `docs/graphit-launch/reports/homescreen.status.json`:
  `{"id":"homescreen","status":"done|partial|blocked","summary":"одна-две фразы","at":"ISO-время завершения (например, 2026-10-27T12:34:56Z; поле обязательно и должно меняться при каждой записи)","tests":{"npm_test":"N/N","other":["…"]},"commits":["хэш…"],"not_verified":["…"],"requests":["…"]}`.
  `done` — всё в задании выполнено и проверки зелёные; `partial` — часть сделана (что именно — в `summary`); `blocked` — дальше нельзя (причина). Отчёт и статус коммитятся в твою ветку.
