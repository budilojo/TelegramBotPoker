# Задание: server

**Серверная часть демонстрации «Графита».** Полностью автономна от клиентов: проверяется тестами через настоящий хаб.

## Обязательные материалы
`AGENTS.md`; `docs/brain/00-index.md`, `status.md`, `tasks.md`, последний файл `docs/brain/sessions/`; `docs/graphit-launch/README.md`, `00-plan.md`, `contracts.md`,
`ownership.md`, `acceptance.md`; `design/collections/README.md`, `SPEC.md`, `ASSET-LIST.md`, `CLAUDE-CODE-PROMPT.md`; `docs/brain/decisions/106-shop-tab-counter.md`;
`docs/redesign.md`, `docs/game-hub.md`, `MESSAGES.md` (разделы про покер, дурак, лобби, профиль).
Контракт: разделы **1–6, 11** (`contracts.md`) и «Поправки (фаза 1)». Код: `bot/hub.js`, `bot/app.js`, `bot/store.js` (в том числе `MemStore`), `bot/room.js`, `bot/view.js`,
`bot/games/poker/index.js`, `bot/games/durak/{index,rules,view}.js`, `bot/profile.js` (как публичные данные профиля попадают в `view`), `bot/harness.js`, существующие тесты хаба и приватности
(`bot/hub.test.js`, `bot/*privacy*`, `bot/chat.test.js`) как образец «что получил каждый телефон», `docs/brain/decisions/106-shop-tab-counter.md`.

## Цель
Реализовать в `bot/collections/` (новая папка) и точечных блоках существующих файлов:
1. **Демосреда:** опция `collectionsDemo` в `App`, читается в `bot/index.js` из окружения `COLLECTIONS_DEMO` (только ровно `1`), по умолчанию выключена; документировать в `.env.example`
   (закомментированная строка и объяснение «только для демонстрационной среды»). Не использовать `cosmeticsUnlocked` и права администратора как демо-право.
2. **Таблицы** `collection_demo_grant`, `collection_choice`, `collection_req` (раздел 4) в `Store` **и** `MemStore`; версия схемы не меняется; **проверить**, что старый `bot/store.js`
   (`git show 7afb285:bot/store.js` в папку вне проекта) открывает базу, созданную новым кодом.
3. **Протокол** `{t:'col'}` (раздел 2): `state`, `grant`, `apply`, `clear` с валидацией по каталогу (`miniapp/collections/catalog.js`), владением (демо-строки учитываются **только** при включённой
   демосреде), слотом и цветом, идемпотентностью `req`, лимитом 20/мин по `app.clock.now()`, словесными отказами из `protocol.js`; сообщение приходит из любой сессии, кроме `admin`;
   подключение в `bot/hub.js` одним блоком рядом с `shop` (решение 106 и `shop` не менять). Поле `collections: {enabled, demo}` в состоянии хаба, если так нужно клиенту — иначе в `state` ответе.
4. **Снимок раздачи** (раздел 5): `room.look` (сериализуется с комнатой; старые комнаты без поля читаются как база); лобби — живое; раздача — заморозка; следующая — пересбор;
   стол — выбор текущего хоста; рубашки — покер, каждому сидящему; рамки — каждому. Точки подключения — из «Поправок (фаза 1)». Перенос хоста, переподключение и перезапуск
   не меняют снимок посреди раздачи. Проверка прав при снимке (нет права → база).
5. **Поля `view`** (раздел 6) покера и дурака: `look` и `players[].frame`; результаты хранят снимок рамки на момент итога.
6. **Приватность и независимость:** оформление не меняет ходы, часы (`room.turn`), рейтинг, шансы; ничего об оформлении не попадает в карточку группы, чат, рейтинг, чужие `view`.

## Границы
Файлы из `owns` (в `bot/store.js`, `bot/hub.js`, `bot/app.js`, `bot/room.js`, `bot/view.js`, `bot/games/*` — только необходимые блоки, помеченные комментарием `// collections`). Клиентский код,
SVG, тексты интерфейса — не твои. `bot/shop.js` и таблицы магазина не менять. `server/game.js` не менять.

## Зависимости
Требуется `lead-contracts` (`catalog.js`, `protocol.js`, поправки). Твой результат нужен `screens` и итоговой интеграции.

## Вход / выход
Вход: `miniapp/collections/catalog.js`, `protocol.js`. Выход: серверная часть + `view.look`/`players[].frame` по контракту, тесты, отчёт; в отчёте — **точный список** добавленных полей `view`, имён функций
и мест вызова (для `screens`), фактическое поведение хоста.

## Проверки (все обязательны)
* `bot/collections.test.js`: протокол; личность из `initData`, подмена полей тела игнорируется; чужой id; отказы словами; идемпотентность и гонка двух страниц одного игрока; лимит;
  `MemStore` и `Store` одинаково; перезапуск (серилизация) сохраняет снимок и выбор.
* **Демо-изоляция:** выключено по умолчанию; `COLLECTIONS_DEMO` = `0`, `true`, `yes`, пусто, ` 1`, `1 ` — выключено; клиентские поля `demo`, `unlocked`, `price`, `item` не включают;
  демо-строки в базе при выключенной демосреде игнорируются; `grant` вне демо → `COL_DEMO_OFF`; демо-право не читается ни одной проверкой «реальных прав» (их нет) и не становится реальным.
* **Снимок:** лобби сразу; раздача заморожена при смене выбора всеми (хост и не хост); переподключение, перенос хоста, выход/возврат; следующая раздача берёт новый выбор и стол нового хоста;
  нет права → база; дурак — партия и «ещё одна партия».
* **Приватность через хаб** (`bot/collections.privacy.test.js`): три страницы за партию покера и дурака, **записать все сообщения каждой** (вся история), проверить: нет чужих карт/колод, нет
  `owned`/`choice`/`pending`/демо-флагов/цен/id пользователей других людей; `look.backs` по местам без id; результаты содержат только публичное оформление.
* **Неизменность правил:** одна и та же колода с оформлением и без → одинаковые ходы, состояния, часы, рейтинг.
* **«На зубы»** (`tools/graphit-server-teeth.mjs` или `bot/collections.teeth.test.js`): вернуть поломку по каждой защите (включить демо по умолчанию; доверять `demo` из тела; игнорировать
  выключение демо для строк базы; не замораживать снимок; брать выбор не хоста; класть `choice` в чужой `view`; пропустить проверку владения; удвоить выдачу по повторному `req`) — тесты обязаны падать.
* Весь `npm test`; старые комнаты из базы читаются; старый код открывает базу.

## Общие правила исполнителя (одинаковы у всех заданий пакета)

* **Где ты:** запущен скриптом `tools/graphit-run.mjs` в своей рабочей копии `../TelegramBotPoker-gr-server` на ветке `gr/server`. Проверь:
  `git branch --show-current` → `gr/server`. Основную папку `~/TelegramBotPoker` и ветку `redesign` **не трогай**. `git push` **не делай** — слияние и публикацию
  выполняет скрипт. Коммить только в свою ветку; перед **каждым** коммитом — `npm test` целиком; коммиты русскими предложениями («коллекции: …»).
* **Повторный запуск:** если в ветке уже есть твои коммиты или `docs/graphit-launch/reports/server.md`, сначала прочитай `git log --oneline gr/integration..HEAD`
  и свой отчёт, **продолжи** с места остановки, не переделывай готовое и не дублируй файлы.
* **Зона:** правь только файлы из `agents.json` → `owns` («Карта ответственности» — `docs/graphit-launch/ownership.md`). Общие файлы (`MESSAGES.md`,
  `docs/redesign.md`, `package.json`, `AGENTS.md`, `docs/brain/*` кроме своих решений, `miniapp/index.html`) **не правь**: тексты, токены, строки e2e и память
  оформи фрагментами в отчёте. Чужую зону не правь даже «по мелочи».
* **Связь с другими агентами нет** (нет `SendMessage`): нужное изменение контракта — раздел «Запросы к контракту» в отчёте и минимальный совместимый вариант.
  Контракт — `docs/graphit-launch/contracts.md`; при противоречии побеждают `design/collections/SPEC.md`, затем фактический код.
* **Правила проекта (`AGENTS.md`):** личность только из подписанного `initData`; персональные `view`, чужие карты/колоды не передавать; оформление не влияет на правила,
  часы, рейтинг, шансы; `server/game.js` не менять; токен бота не спрашивать и не показывать, `.env` не открывать; без PR, выкатки, `--force`, правок на сервере;
  интерфейс русский, числа `1.200`, покерные действия английские (Fold, Check, Call, Bet, Raise, All-in); дизайн-система `docs/redesign.md`
  (плоско, без золота, градиентов, свечения, теней; токены; 6/8/12; зона нажатия ≥ 44 px; ничего с внешних доменов).
* **Порты и параллельность:** другие исполнители работают одновременно на этом же компьютере. Для браузерных проверок тебе выдана переменная `E2E_PORT` (не меняй её); если тест упал из-за занятого порта или
  нагрузки — повтори этот файл отдельно, не записывай это как красное без повторной проверки (и пиши в отчёт, что повторял).
* **Тесты не ослаблять.** Падает тест — по умолчанию неправ код. Каждую новую защиту проверь «на зубы» (верни поломку — тест падает) и запиши результат.
  Не заявляй проверку в живом Telegram: эмуляция Chromium — не Telegram.
* **Решения:** свои решения — файлами `docs/brain/decisions/NNN-короткое-имя.md` по шаблону `000-template.md`, номера **110–113** (только твой диапазон).
* **Отчёт (обязательно):** `docs/graphit-launch/reports/server.md` по-русски простыми словами: 1) что сделано; 2) какие проверки запущены и результат (числа); 3) таблица «защита →
  как сломана → упал ли тест»; 4) что не удалось/не проверено, **отдельно «Не проверено на телефоне в живом Telegram»**; 5) «Запросы к контракту»; 6) «Фрагменты для общих файлов»
  (тексты для `MESSAGES.md` с местом в коде; токены для `docs/redesign.md`; строки e2e для `package.json`; заметки для памяти проекта); 7) вопросы владельцу.
* **Статус (обязательно, последним шагом):** `docs/graphit-launch/reports/server.status.json`:
  `{"id":"server","status":"done|partial|blocked","summary":"одна-две фразы","at":"ISO-время завершения (например, 2026-10-27T12:34:56Z; поле обязательно и должно меняться при каждой записи)","tests":{"npm_test":"N/N","other":["…"]},"commits":["хэш…"],"not_verified":["…"],"requests":["…"]}`.
  `done` — всё в задании выполнено и проверки зелёные; `partial` — часть сделана (что именно — в `summary`); `blocked` — дальше нельзя (причина). Отчёт и статус коммитятся в твою ветку.
