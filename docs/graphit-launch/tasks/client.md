# Задание: client

**Клиент коллекций:** новые экраны витрины, карточки, примерки, получения, инвентаря и применения. Проверяется на заглушке сервера и затем интеграцией.

## Обязательные материалы
`AGENTS.md`; `docs/brain/00-index.md`, `status.md`, `tasks.md`, последний файл `docs/brain/sessions/`; `docs/graphit-launch/README.md`, `00-plan.md`, `contracts.md`,
`ownership.md`, `acceptance.md`; `design/collections/README.md`, `SPEC.md`, `ASSET-LIST.md`, `CLAUDE-CODE-PROMPT.md`; `docs/brain/decisions/106-shop-tab-counter.md`;
`docs/redesign.md`, `docs/game-hub.md`, `MESSAGES.md` (разделы про покер, дурак, лобби, профиль).
Контракт: разделы **1–4, 8, 11**. Посмотри **глазами** `design/collections/references/01, 02, 03, 04, 07, 08, 09–11` (ориентиры; SPEC выше картинок; кнопки покупки на PNG — референс будущего). Код: `miniapp/app.js`, `miniapp/net.js`,
`miniapp/nav.js`, `miniapp/settings-rows.js`, `miniapp/ui.js` (шторки `showSheet/refreshSheet`, `h()`, `toast`), `miniapp/profile.js`, `miniapp/solo.js` (форма и сегменты как образец), `docs/scroll.md`,

## Цель
В `miniapp/collections/` и `miniapp/collections.css` реализовать по SPEC и контракту:
1. **Вход:** строка «Коллекции» в «Настройках» через `miniapp/collections/settings-row.js` — только при `state.enabled && state.demo` (сервер), с подписью «Демонстрация · Без оплаты». Вне демо точки входа **нет**, прямой
   маршрут/хэш не открывает экраны; вкладка «Магазин» не меняется.
2. **Витрина:** коллекция «Графит»; три предмета и комплект; отметки «В вашей коллекции» / «Применено» / доступно; состояния загрузки без прыжков.
3. **Карточка** предмета/комплекта: название, изображение (`art.js` → `/collections/art/…`, при ошибке — базовый запасной вид), назначение, «Навсегда», состав; **четыре подписанных цвета** с галочкой и
   светлым нейтральным контуром выбранного (не синим, не по цвету); текст «Все 4 цвета включены»; цены демонстрационные, только в демо и с пометкой; **рубашки дурака не обещать**.
4. **Примерка:** отдельное локальное состояние, **не меняет** текущую партию и не отправляет ничего на сервер; рубашка на закрытых картах и блок «Так видят друзья» — **только здесь**; стол и профиль
   показываются на образцах.
5. **Демополучение:** кнопка «Получить для демонстрации», подпись «Демонстрация · Без оплаты»; запрос `grant` с `req`; успех **только после ответа сервера**; никакой фиктивной «успешной оплаты»; при
   частичном комплекте — показать имеющееся и недостающее, кнопку комплекта заблокировать с пояснением, что правило цены дополнения не утверждено; повторное получение невозможно («Уже в вашей коллекции»).
6. **Получение:** состав, переключатели применения, переход в инвентарь; получение само не обязано менять выбранное.
7. **Инвентарь:** вкладки «Карты», «Столы», «Профиль»; база и полученное; выбор цвета; «Применено» / «Применится со следующей раздачи» (по `pending`/`when`); возврат к базе; подтверждение выбора **после ответа сервера**.
8. **Состояния:** загрузка, пустой инвентарь (база доступна, пояснение, переход в витрину), нет связи («Повторить»; владение не выдавать, выбор не терять), ожидание ответа (защита от повторного нажатия, прежний вид до ответа),
   ошибка применения (прежний выбор, объяснение словами, «Повторить»), уже куплено. Описать (не реализовывать) будущую оплату: отмена, ожидание, ошибка, восстановление — только в отчёте.
9. Доступность: подписи, фокус, состояние выбора не только цветом, зоны ≥ 44 px, 320/360/390/430 px, длинные названия; без прыжков (`assertNoJump`), `prefers-reduced-motion`.
10. Подключение сообщений: ветка `msg.t === 'col'` в `miniapp/net.js` → `bus.onCollections`; маршрут экрана в `miniapp/app.js` (один блок). Решение 106 и вкладки не менять.

## Границы
Файлы из `owns`. Экраны игр и `ui.js` не меняй (это `screens`). Каталог и протокол — только читать. Сервер — только через контракт (в e2e можно временно использовать настоящий сервер из репозитория, как
в существующих `tools/e2e-*.mjs`; серверного модуля может **ещё не быть** в твоей ветке — тогда сделай тестовую заглушку ответов по контракту в своём e2e и укажи это в отчёте).

## Зависимости
Требуется `lead-contracts`. С `server` и `assets` не связан жёстко: `art.js` должен переживать отсутствие файлов (запасной вид).

## Вход / выход
Вход: `catalog.js`, `protocol.js`, реестр строк. Выход: клиентские экраны, стили (только токены; новые значения — предложением в отчёте для `docs/redesign.md`), e2e, отчёт со скриншотами (описанием, что на них видно),
список текстов для `MESSAGES.md`.

## Проверки
`bot/collections.client.test.js` (чистая логика состояния: ожидание/повтор/ошибка/идемпотентность `req`); `tools/e2e-collections.mjs` на **четырёх** ширинах (320/360/390/430) со **всеми состояниями**; `layout`, `kit`, `contrast` для
твоих экранов; скриншоты **посмотреть**; **«на зубы»** (`tools/graphit-client-teeth.mjs`): показать выдачу до ответа сервера; включить вход вне демо; разрешить повтор по двойному нажатию; показать «Так видят друзья» в игре;
сделать цвет выбранного синим/единственным признаком — тесты падают.

## Общие правила исполнителя (одинаковы у всех заданий пакета)

* **Где ты:** запущен скриптом `tools/graphit-run.mjs` в своей рабочей копии `../TelegramBotPoker-gr-client` на ветке `gr/client`. Проверь:
  `git branch --show-current` → `gr/client`. Основную папку `~/TelegramBotPoker` и ветку `redesign` **не трогай**. `git push` **не делай** — слияние и публикацию
  выполняет скрипт. Коммить только в свою ветку; перед **каждым** коммитом — `npm test` целиком; коммиты русскими предложениями («коллекции: …»).
* **Повторный запуск:** если в ветке уже есть твои коммиты или `docs/graphit-launch/reports/client.md`, сначала прочитай `git log --oneline gr/integration..HEAD`
  и свой отчёт, **продолжи** с места остановки, не переделывай готовое и не дублируй файлы.
* **Зона:** правь только файлы из `agents.json` → `owns` («Карта ответственности» — `docs/graphit-launch/ownership.md`). Общие файлы (`MESSAGES.md`,
  `docs/redesign.md`, `package.json`, `AGENTS.md`, `docs/brain/*` кроме своих решений, `miniapp/index.html`) **не правь**: тексты, токены, строки e2e и память
  оформи фрагментами в отчёте. Чужую зону не правь даже «по мелочи».
* **Связь с другими агентами нет** (нет `SendMessage`): нужное изменение контракта — раздел «Запросы к контракту» в отчёте и минимальный совместимый вариант.
  Контракт — `docs/graphit-launch/contracts.md`; при противоречии побеждают `design/collections/SPEC.md`, затем фактический код.
* **Правила проекта (`AGENTS.md`):** личность только из подписанного `initData`; персональные `view`, чужие карты/колоды не передавать; оформление не влияет на правила,
  часы, рейтинг, шансы; `server/game.js` не менять; токен бота не спрашивать и не показывать, `.env` не открывать; без PR, выкатки, `--force`, правок на сервере;
  интерфейс русский, числа `1.200`, покерные действия английские (Fold, Check, Call, Bet, Raise, All-in); дизайн-система `docs/redesign.md`
  (плоско, без золота, градиентов, свечения, теней; токены; 6/8/12; зона нажатия ≥ 44 px; ничего с внешних доменов).
* **Порты и параллельность:** другие исполнители работают одновременно на этом же компьютере. Для браузерных проверок тебе выдана переменная `E2E_PORT` (не меняй её); если тест упал из-за занятого порта или
  нагрузки — повтори этот файл отдельно, не записывай это как красное без повторной проверки (и пиши в отчёт, что повторял).
* **Тесты не ослаблять.** Падает тест — по умолчанию неправ код. Каждую новую защиту проверь «на зубы» (верни поломку — тест падает) и запиши результат.
  Не заявляй проверку в живом Telegram: эмуляция Chromium — не Telegram.
* **Решения:** свои решения — файлами `docs/brain/decisions/NNN-короткое-имя.md` по шаблону `000-template.md`, номера **117–120** (только твой диапазон).
* **Отчёт (обязательно):** `docs/graphit-launch/reports/client.md` по-русски простыми словами: 1) что сделано; 2) какие проверки запущены и результат (числа); 3) таблица «защита →
  как сломана → упал ли тест»; 4) что не удалось/не проверено, **отдельно «Не проверено на телефоне в живом Telegram»**; 5) «Запросы к контракту»; 6) «Фрагменты для общих файлов»
  (тексты для `MESSAGES.md` с местом в коде; токены для `docs/redesign.md`; строки e2e для `package.json`; заметки для памяти проекта); 7) вопросы владельцу.
* **Статус (обязательно, последним шагом):** `docs/graphit-launch/reports/client.status.json`:
  `{"id":"client","status":"done|partial|blocked","summary":"одна-две фразы","at":"ISO-время завершения (например, 2026-10-27T12:34:56Z; поле обязательно и должно меняться при каждой записи)","tests":{"npm_test":"N/N","other":["…"]},"commits":["хэш…"],"not_verified":["…"],"requests":["…"]}`.
  `done` — всё в задании выполнено и проверки зелёные; `partial` — часть сделана (что именно — в `summary`); `blocked` — дальше нельзя (причина). Отчёт и статус коммитятся в твою ветку.
