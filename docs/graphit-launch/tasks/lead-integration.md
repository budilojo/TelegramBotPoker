# Задание: lead-integration

**Фаза 2 координатора:** слияние, общие файлы, полный прогон, итоговый отчёт. Запускается **последним**, после того как все исполнители сдали статусы.

## Обязательные материалы
`AGENTS.md`; `docs/brain/00-index.md`, `status.md`, `tasks.md`, последний файл `docs/brain/sessions/`; `docs/graphit-launch/README.md`, `00-plan.md`, `contracts.md`,
`ownership.md`, `acceptance.md`; `design/collections/README.md`, `SPEC.md`, `ASSET-LIST.md`, `CLAUDE-CODE-PROMPT.md`; `docs/brain/decisions/106-shop-tab-counter.md`;
`docs/redesign.md`, `docs/game-hub.md`, `MESSAGES.md` (разделы про покер, дурак, лобби, профиль).
Все отчёты и статусы: `docs/graphit-launch/reports/*.md`, `*.status.json`; `docs/research/*.md`; `docs/homescreen.md`; `.graphit-run/state.json` и журналы (если доступны). `docs/next-deploy-prompt.md` (только чтобы **не** выкатывать).

## Цель
1. **Состояние:** `git log --oneline origin/redesign..HEAD`, `git status`; убедиться, что в `gr/integration` слиты все ветки со статусом `done` (скрипт слил их по очереди). Что `partial/blocked` — разобрать: можно ли довести малыми правками (1–3 строки, назвать в отчёте)
   или это хвост. Разрешить конфликты слияния, если скрипт их передал; **ничьи изменения не стирать**.
2. **Общие файлы** (ты единственный владелец): перенести фрагменты исполнителей в `MESSAGES.md` (раздел «Коллекция «Графит» (демонстрация)» с местами в коде), `docs/redesign.md` (токены/правила, если предложены; исключения игрового арта),
   `package.json` (строки новых e2e в `e2e`: `tools/e2e-collections.mjs`, `e2e-collections-look.mjs`, `e2e-homescreen.mjs`), `bot/README.md` (переменная `COLLECTIONS_DEMO`), новый `docs/collections-demo.md` (**как поднять демосреду**: переменная окружения,
   что она включает, чем отличается от рабочего режима, как убедиться, что она выключена, предупреждение «не включать на рабочем сервере»; **токен не показывать**), `AGENTS.md` (строки таблицы «Документы» для `docs/graphit-launch/`, `docs/research/`, `docs/homescreen.md`,
   `docs/collections-demo.md`). Номера решений 130–132 — для общих решений (например, «демонстрация изолирована от рабочего режима»).
3. **Полный прогон** на объединённой ветке: `npm test`; `npm run e2e` (в том числе новые файлы); `npm run layout`; `npm run kit`; `npm run contrast`; `npm run preview` — **скриншоты на 320/360/390/430 px посмотреть глазами**
   (витрина, карточка, цвета, примерка, получение, инвентарь, покер и дурак с каждым цветом, лобби/результаты, «Настройки» со строками). Падение — исправить в зоне владельца малой правкой или записать хвостом; тесты не ослаблять.
4. **Сквозной сценарий демонстрации** (`acceptance.md`) прогнать полностью; затем **рабочий режим** (демо выключено): входа нет, `grant` отклонён, вкладка «Магазин» «скоро» и счётчик работает (решение 106).
5. **Приватность по всей истории** каждого телефона (покер и дурак): повторить/усилить тест исполнителя; убедиться, что оформление не влияет на ходы/часы/рейтинг.
6. **Проверка границ:** `git diff --stat origin/redesign` не содержит `server/game.js`, `server/`, `public/`, `deploy/`, `.env*`; нет реальных платёжных вызовов (поиск `sendInvoice`, `createInvoiceLink`, `XTR`, `refundStarPayment`, `pre_checkout`); старый набор и решение 106 не затронуты;
   демосреда по умолчанию выключена (`git grep COLLECTIONS_DEMO`).
7. **Память проекта** (`docs/brain/`): новая сессия `sessions/2026-10-27-graphit-realizaciya.md` (или текущая дата); `status.md` (в «Работает (проверено)» — только то, что проверено запуском, дата и способ; в «Не проверено» — телефон, живой Telegram; **не отмечать
   функции реализованными в живом Telegram**); `tasks.md` (отметить выполненные пункты; **приоритеты владельца не менять**; «Ближайший шаг» обновить — выкатка только по слову владельца); `ideas.md`; индекс решений; своя часть решений.
8. **Итоговый отчёт** `docs/graphit-launch/reports/FINAL.md` (по-русски, для владельца-не-программиста): что сделано; какие проверки прошли (числа); что не прошло или не проверено; **что проверить руками на телефоне (список из 6–10 действий)**; ответы на исследования
   в 5–8 строк с ссылками на документы; раздел **«Что решает владелец»** (вопросы раздела 9 плана с рекомендациями) и **«Условия перехода к платежам»** (проверяемые, без дат); как включить демосреду (ссылка на `docs/collections-demo.md`). И `FINAL.status.json`:
   `{"id":"lead-integration","ok":true|false,"status":"done|partial|blocked","summary":"…","at":"ISO-время завершения","tests":{"npm_test":"N/N","e2e":"…","layout":"…","kit":"…","contrast":"…"},"not_verified":["…"],"push_ready":true|false}`.
   `ok` и `push_ready` — **true только если все проверки зелёные**; иначе `false` и причина; скрипт в этом случае ничего не публикует.

## Границы
Не выкатывать, не создавать PR, не делать `git push` (публикацию делает скрипт при `push_ready: true`), не включать демосреду на рабочем окружении, не подключать платежи, не менять `server/game.js`. Чужие файлы — только малые правки для конфликтов/дефектов с записью в `FINAL.md`.

## Зависимости
Все исполнители (`server`, `assets`, `client`, `screens`, `homescreen`, `research`) имеют статус `done`/`partial`, ветки слиты или переданы тебе.

## Вход / выход
Вход: ветка `gr/integration` с результатами. Выход: коммиты в `gr/integration` (общие файлы, правки), `FINAL.md`, `FINAL.status.json`; `git status` чистый.

## Проверки
См. цели 3–6; все команды и числа — в `FINAL.md`; для любого красного — причина и решение. Новые защиты, добавленные тобой, — «на зубы».

## Общие правила исполнителя (одинаковы у всех заданий пакета)

* **Где ты:** запущен скриптом `tools/graphit-run.mjs` в своей рабочей копии `../TelegramBotPoker-gr-lead-integration` на ветке `gr/lead-integration`. Проверь:
  `git branch --show-current` → `gr/lead-integration`. Основную папку `~/TelegramBotPoker` и ветку `redesign` **не трогай**. `git push` **не делай** — слияние и публикацию
  выполняет скрипт. Коммить только в свою ветку; перед **каждым** коммитом — `npm test` целиком; коммиты русскими предложениями («коллекции: …»).
* **Повторный запуск:** если в ветке уже есть твои коммиты или `docs/graphit-launch/reports/lead-integration.md`, сначала прочитай `git log --oneline gr/integration..HEAD`
  и свой отчёт, **продолжи** с места остановки, не переделывай готовое и не дублируй файлы.
* **Зона:** правь только файлы из `agents.json` → `owns` («Карта ответственности» — `docs/graphit-launch/ownership.md`). Общие файлы (`MESSAGES.md`,
  `docs/redesign.md`, `package.json`, `AGENTS.md`, `docs/brain/*` кроме своих решений, `miniapp/index.html`) **не правь**: тексты, токены, строки e2e и память
  оформи фрагментами в отчёте. Чужую зону не правь даже «по мелочи».
* **Связь с другими агентами нет** (нет `SendMessage`): нужное изменение контракта — раздел «Запросы к контракту» в отчёте и минимальный совместимый вариант.
  Контракт — `docs/graphit-launch/contracts.md`; при противоречии побеждают `design/collections/SPEC.md`, затем фактический код.
* **Правила проекта (`AGENTS.md`):** личность только из подписанного `initData`; персональные `view`, чужие карты/колоды не передавать; оформление не влияет на правила,
  часы, рейтинг, шансы; `server/game.js` не менять; токен бота не спрашивать и не показывать, `.env` не открывать; без PR, выкатки, `--force`, правок на сервере;
  интерфейс русский, числа `1.200`, покерные действия английские (Fold, Check, Call, Bet, Raise, All-in); дизайн-система `docs/redesign.md`
  (плоско, без золота, градиентов, свечения, теней; токены; 6/8/12; зона нажатия ≥ 44 px; ничего с внешних доменов).
* **Порты и параллельность:** другие исполнители работают одновременно на этом же компьютере. Для браузерных проверок тебе выдана переменная `E2E_PORT` (не меняй её); если тест упал из-за занятого порта или
  нагрузки — повтори этот файл отдельно, не записывай это как красное без повторной проверки (и пиши в отчёт, что повторял).
* **Тесты не ослаблять.** Падает тест — по умолчанию неправ код. Каждую новую защиту проверь «на зубы» (верни поломку — тест падает) и запиши результат.
  Не заявляй проверку в живом Telegram: эмуляция Chromium — не Telegram.
* **Решения:** свои решения — файлами `docs/brain/decisions/NNN-короткое-имя.md` по шаблону `000-template.md`, номера **130–132** (только твой диапазон).
* **Отчёт (обязательно):** `docs/graphit-launch/reports/lead-integration.md` по-русски простыми словами: 1) что сделано; 2) какие проверки запущены и результат (числа); 3) таблица «защита →
  как сломана → упал ли тест»; 4) что не удалось/не проверено, **отдельно «Не проверено на телефоне в живом Telegram»**; 5) «Запросы к контракту»; 6) «Фрагменты для общих файлов»
  (тексты для `MESSAGES.md` с местом в коде; токены для `docs/redesign.md`; строки e2e для `package.json`; заметки для памяти проекта); 7) вопросы владельцу.
* **Статус (обязательно, последним шагом):** `docs/graphit-launch/reports/lead-integration.status.json`:
  `{"id":"lead-integration","status":"done|partial|blocked","summary":"одна-две фразы","at":"ISO-время завершения (например, 2026-10-27T12:34:56Z; поле обязательно и должно меняться при каждой записи)","tests":{"npm_test":"N/N","other":["…"]},"commits":["хэш…"],"not_verified":["…"],"requests":["…"]}`.
  `done` — всё в задании выполнено и проверки зелёные; `partial` — часть сделана (что именно — в `summary`); `blocked` — дальше нельзя (причина). Отчёт и статус коммитятся в твою ветку.
