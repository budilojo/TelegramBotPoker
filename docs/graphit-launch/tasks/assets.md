# Задание: assets

**Графические ресурсы «Графита»:** самостоятельные SVG в четырёх цветах из одного генератора. Работай независимо от сервера и клиента.

## Обязательные материалы
`AGENTS.md`; `docs/brain/00-index.md`, `status.md`, `tasks.md`, последний файл `docs/brain/sessions/`; `docs/graphit-launch/README.md`, `00-plan.md`, `contracts.md`,
`ownership.md`, `acceptance.md`; `design/collections/README.md`, `SPEC.md`, `ASSET-LIST.md`, `CLAUDE-CODE-PROMPT.md`; `docs/brain/decisions/106-shop-tab-counter.md`;
`docs/redesign.md`, `docs/game-hub.md`, `MESSAGES.md` (разделы про покер, дурак, лобби, профиль).
Контракт: раздел **7** и `miniapp/collections/catalog.js` (палитры). Просмотри **глазами** `design/collections/references/01, 02, 03, 07, 08` (референсы геометрии), и существующие картинки
карт (`miniapp/cards/*.svg`, размеры 200×280), аватары профиля (`miniapp/profile.js`, `docs/profile.md`: круг 32–56 px), геометрию овалов `.felt` покера (`miniapp/games/poker.js: layoutTable`)
и `.dk-felt` дурака (`miniapp/games/durak.js: layoutDurak`).

## Цель
Создать `tools/build-graphit-art.mjs` (чистый Node без зависимостей, **детерминированный**: повторный запуск даёт те же байты) и сгенерированные им файлы в `miniapp/collections/art/` по
разделу 7 контракта: рубашка (подробная и упрощённая), орнамент стола и центральный ромб, рамка (подробная и малая), знак профиля, миниатюры, композиция комплекта — **в четырёх цветах**
(`graphite`, `sapphire`, `bordeaux`, `petrol`; HEX из SPEC и `catalog.js`), `manifest.json`, `art/README.md`.
* **Одна геометрия**, одинаковые `viewBox`, масштаб, силуэты, толщины линий и расположение элементов; меняются только цвета (фон предмета и линия). Мотив: переплетающиеся геометрические линии
  и небольшой центральный ромб. Подробная версия — для магазина; упрощённая убирает второстепенные линии, но узнаётся и **читается в реальных малых размерах**: закрытые карты (ширина ~18–60 px),
  рамка на аватаре 32–56 px, знак ~14–24 px.
* Восстанови геометрию по референсам, **не копируй ошибки генерации** (тональные переходы, тени, шум, разные толщины, слишком тонкие линии, случайные цвета интерфейса). Не вырезай макеты и не встраивай PNG.
* **Таблицу стола** сделай применимой на практике: опиши в `art/README.md`, как наложить орнамент на овал покера и дурака (рекомендованный способ, пропорции, безопасные зоны, чтобы **центр
  оставался свободным**, карты/банк/кнопки читались на 320 px; что делать с разным соотношением сторон; можно ли использовать повторяющийся фрагмент). Для `screens` это единственный источник.
* Рамка не обрезает аватар (прозрачный центр, безопасный круг); знак — простой полый ромб, не знак рейтинга и не индикатор готовности.
* Недопустимо: градиенты, фильтры, тени, прозрачность ради «перехода», `<image>`, внешние ссылки, `<script>`, `<style>` с `url()`; текст внутри SVG; золото. Декор — `aria-hidden`.

## Границы
Только файлы из `owns`. Подключение ресурсов к интерфейсу — не твоё (`client`, `screens`). Лица карт и масти не затрагиваются.

## Зависимости
Требуется `lead-contracts` (имена файлов и палитра). Нужен `screens` (после твоего `done`).

## Вход / выход
Вход: `catalog.js`. Выход: генератор, ресурсы, манифест, `art/README.md`, тесты, отчёт; в отчёте — размеры и вес файлов, метод и числа контрастов.

## Проверки
* `bot/collections.art.test.js`: список и имена файлов совпадают с контрактом; для каждого вида четыре цвета; структура (последовательность путей/`d`, `viewBox`, `stroke-width`) **одинакова** во всех четырёх,
  отличаются только цвета; цвета только из палитры; нет запрещённых элементов и атрибутов (проверка разбором SVG); бюджет веса (подробные ≤ 24 КБ, упрощённые ≤ 8 КБ — реальные числа в отчёте);
  манифест соответствует диску; генерация воспроизводима (хэш двух запусков одинаков); нет внешних адресов.
* **Контраст:** вычислить отношение линии к фону предмета (цель ≥ 3:1) для каждого цвета и показать числа; **Петроль** отличим от зелёного индикатора `#137A43`: измерить и описать метод и результат
  (цвет линии и фона, не только оттенок; рядом с «Ваш ход»).
* **Глазами:** собрать контрольные листы (Playwright, как `tools/preview.mjs`) в реальных малых размерах и на тёмных подложках проекта (`#0A1216`, `#13212A`, `#1D2D35`); сравнить все четыре цвета;
  найти мерцание узора на 1–2 px (муар), слипание линий; результаты — в отчёте.
* **«На зубы»** (`tools/graphit-art-teeth.mjs`): вернуть поломку — добавить градиент, поменять толщину в одном цвете, цвет вне палитры, внешний `href`, `<image>`, раздуть файл — тесты падают.

## Общие правила исполнителя (одинаковы у всех заданий пакета)

* **Где ты:** запущен скриптом `tools/graphit-run.mjs` в своей рабочей копии `../TelegramBotPoker-gr-assets` на ветке `gr/assets`. Проверь:
  `git branch --show-current` → `gr/assets`. Основную папку `~/TelegramBotPoker` и ветку `redesign` **не трогай**. `git push` **не делай** — слияние и публикацию
  выполняет скрипт. Коммить только в свою ветку; перед **каждым** коммитом — `npm test` целиком; коммиты русскими предложениями («коллекции: …»).
* **Повторный запуск:** если в ветке уже есть твои коммиты или `docs/graphit-launch/reports/assets.md`, сначала прочитай `git log --oneline gr/integration..HEAD`
  и свой отчёт, **продолжи** с места остановки, не переделывай готовое и не дублируй файлы.
* **Зона:** правь только файлы из `agents.json` → `owns` («Карта ответственности» — `docs/graphit-launch/ownership.md`). Общие файлы (`MESSAGES.md`,
  `docs/redesign.md`, `package.json`, `AGENTS.md`, `docs/brain/*` кроме своих решений, `miniapp/index.html`) **не правь**: тексты, токены, строки e2e и память
  оформи фрагментами в отчёте. Чужую зону не правь даже «по мелочи».
* **Связь с другими агентами нет** (нет `SendMessage`): нужное изменение контракта — раздел «Запросы к контракту» в отчёте и минимальный совместимый вариант.
  Контракт — `docs/graphit-launch/contracts.md`; при противоречии побеждают `design/collections/SPEC.md`, затем фактический код.
* **Правила проекта (`AGENTS.md`):** личность только из подписанного `initData`; персональные `view`, чужие карты/колоды не передавать; оформление не влияет на правила,
  часы, рейтинг, шансы; `server/game.js` не менять; токен бота не спрашивать и не показывать, `.env` не открывать; без PR, выкатки, `--force`, правок на сервере;
  интерфейс русский, числа `1.200`, покерные действия английские (Fold, Check, Call, Bet, Raise, All-in); дизайн-система `docs/redesign.md`
  (плоско, без золота, градиентов, свечения, теней; токены; 6/8/12; зона нажатия ≥ 44 px; ничего с внешних доменов).
* **Порты и параллельность:** другие исполнители работают одновременно на этом же компьютере. Для браузерных проверок тебе выдана переменная `E2E_PORT` (не меняй её); если тест упал из-за занятого порта или
  нагрузки — повтори этот файл отдельно, не записывай это как красное без повторной проверки (и пиши в отчёт, что повторял).
* **Тесты не ослаблять.** Падает тест — по умолчанию неправ код. Каждую новую защиту проверь «на зубы» (верни поломку — тест падает) и запиши результат.
  Не заявляй проверку в живом Telegram: эмуляция Chromium — не Telegram.
* **Решения:** свои решения — файлами `docs/brain/decisions/NNN-короткое-имя.md` по шаблону `000-template.md`, номера **114–116** (только твой диапазон).
* **Отчёт (обязательно):** `docs/graphit-launch/reports/assets.md` по-русски простыми словами: 1) что сделано; 2) какие проверки запущены и результат (числа); 3) таблица «защита →
  как сломана → упал ли тест»; 4) что не удалось/не проверено, **отдельно «Не проверено на телефоне в живом Telegram»**; 5) «Запросы к контракту»; 6) «Фрагменты для общих файлов»
  (тексты для `MESSAGES.md` с местом в коде; токены для `docs/redesign.md`; строки e2e для `package.json`; заметки для памяти проекта); 7) вопросы владельцу.
* **Статус (обязательно, последним шагом):** `docs/graphit-launch/reports/assets.status.json`:
  `{"id":"assets","status":"done|partial|blocked","summary":"одна-две фразы","at":"ISO-время завершения (например, 2026-10-27T12:34:56Z; поле обязательно и должно меняться при каждой записи)","tests":{"npm_test":"N/N","other":["…"]},"commits":["хэш…"],"not_verified":["…"],"requests":["…"]}`.
  `done` — всё в задании выполнено и проверки зелёные; `partial` — часть сделана (что именно — в `summary`); `blocked` — дальше нельзя (причина). Отчёт и статус коммитятся в твою ветку.
