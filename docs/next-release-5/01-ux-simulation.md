# S — симуляция «новичок» по всем играм (UX)

Прочитай скилл `ux-ui-audit` (раздел 1). **Цель — найти неинтуитивное и непоследовательное в управлении**, пока ничего не чинишь (кроме безобидных опечаток).

## Что сделать
1. Пройди скриптами (Playwright, заглушка Telegram, `E2E_PORT` свой) главный путь каждой игры: покер (fold/call/raise/all-in, «настоящие карты» и бот), дурак (атака, подкидывание, защита, «взять», «бито», перевод), UNOQ (сыграть карту, выбор цвета, добор, «UNO»), шахматы и шашки (ход тапом и перетаскиванием, сдача, ничья, откат), нарды (кубики, ход, отмена), морской бой (расстановка, поворот, «случайно», выстрел). Плюс общее: вход, главная, лобби, приглашение, профиль, поддержка, рейтинг, магазин, меню в партии, «Вернуться к столу».
2. Для каждого главного действия запиши в таблицу: **жест(ы), число касаний, подсказка, что видно при отказе**. Построй **матрицу единообразия жестов** (одно действие — одинаково ли во всех играх и ролях).
3. Найди: разные жесты для одного смысла (известный пример: Дурак), тупики, немые состояния, случайные необратимые действия без подтверждения, двойные/противоречивые подсказки, места, где нужна инструкция.
4. Результат: `docs/next-release-5/ux-sim-report.md` (таблицы + находки в формате скилла с серьёзностью и предложением) и воспроизводимые скрипты `tools/ux-sim-*.mjs`. В `package.json` — скрипт `ux:sim`.
5. Исправлять **ничего не нужно** (чинят V–X). Но скрипты должны быть воспроизводимы, и проверка «на зубы»: если подменить жест (например, отключить второй тап), скрипт должен это заметить.

Проверки: `npm test`, ваши скрипты; метки доказательств по плану; чего не проверить без телефона — перечислить.
