# T — автоскан вёрстки: что выезжает, обрезано, налезает

Прочитай скилл `ux-ui-audit` (раздел 2).

## Что сделать
1. Создай `tools/ui-scan.mjs` (+ `npm run ui:scan`): обходит экраны и состояния (хаб, лобби всех игр, стол каждой игры в характерных состояниях, итоги, магазин/«Мои вещи»/примерка, профиль, рейтинг, шторки, чат, админка по возможности) на **320, 360, 390, 430 px** и сообщает по каждому элементу:
   горизонтальную прокрутку страницы; элемент вне экрана или вне родителя; текст обрезан/переполняет (`scrollWidth > clientWidth`, `overflow:hidden` с потерей текста); наложение блоков друг на друга; зоны нажатия < 44 px; одиночные буквы/слова в строке; нижняя панель и чат, закрывающие действия. Выдача: экран, ширина, селектор, координаты, снимок.
   Используй существующие сцены `tools/preview.mjs`, `tools/layout-check.mjs`, e2e как источник состояний; добавь «тяжёлые» данные: длинные имена, `1.000.000`, 8 игроков, пустые списки, ошибки.
2. Запусти скан по всему приложению, **посмотри снимки проблемных мест глазами**, отфильтруй ложные срабатывания (с причиной), составь `docs/next-release-5/ui-scan-report.md`: таблица «экран × ширина → найдено», список реальных дефектов с серьёзностью и предложением исправления.
3. «На зубы»: временно сломай вёрстку (например, `white-space:nowrap` на длинном имени) — скан должен упасть/сообщить.
4. Сам исправления не вноси (кроме тривиальных очевидных в 1–2 строки; их перечисли): чинит X.

Проверки: `npm test`, `npm run layout`, `npm run kit`, `npm run contrast`; тест скана в `npm test`, если уместно (без сети и реального браузера — как у `layout-check`).
