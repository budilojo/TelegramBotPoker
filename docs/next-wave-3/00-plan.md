## Что просил владелец (коротко)

1. **Обучение** (в покере) — расширить: правила, комбинации и позиции, префлоп и
   постфлоп, математика покера, диапазоны, вероятности и Pot Odds, EV / Fold Equity /
   SPR, основы GTO и продвинутое GTO. От простого к сложному, со схемами и
   интерактивными примерами.
2. **Тренировка** — новая кнопка **на одном уровне с «Обучением»** (Покер → Обучение,
   Покер → Тренировка). Восемь направлений, уровни по нарастающей, настоящая работа с
   картами, диапазонами, ставками и столом (не только выбор из вариантов), **разбор
   после решения** (почему верно, какие были альтернативы, какие ошибки сделаны).
3. **Определение уровня** при первом запуске: «начать с нуля» / «определить мой
   уровень» (короткая интерактивная диагностика) / «по истории игр» (качество решений
   в контексте — **не** победы, фишки и число партий). Отдельные навыки: префлоп,
   диапазоны, математика, постфлоп. Предложить стартовую сложность по направлениям,
   дать изменить вручную.
4. **Связь режимов**: из ошибки (например, по Pot Odds) — «Изучить тему» → урок →
   возврат **к тому же заданию**; из уроков — к упражнениям по теме.
5. **Прогресс и статистика**: пройденные уровни, точность, освоенные навыки, история
   ошибок, рекомендуемые следующие задания, динамическая сложность, повторение слабых
   тем с интервалами.
6. **Аватарки**: готовые картинки из папки владельца **`аватарки`** подключить к
   профилю, выбору аватара и показу за столом. **Не перегенерировать.**
7. **Исправить «прыжки» интерфейса**: в игровых режимах при выборе числа игроков,
   блайндов, таймеров, режимов, вкладок, списков, ползунков и переключателей экран
   дёргается и прокручивается наверх. Найти **первопричину**, а не маскировать
   возвратом `scrollTop`. Проверить и новые разделы, особенно матрицу 13×13.

## Контракты (чтобы работать независимо)

### 1. Реестр тем — `miniapp/train/topics.js` (уже есть)

`SKILLS` (preflop, ranges, math, postflop), `TRACKS` (8 направлений → навык), `TOPICS`
(id, название, навык, раздел урока), `LESSON_SECTIONS`. **id не переименовывать и не
удалять.** Владелец — V; остальные добавляют темы только в свой комментарий-блок и после
`git pull --rebase`. Один и тот же `topic` стоит в уроке (U) и в ошибках упражнений
(W, X) — по нему работает связка (Y).

### 2. Упражнение (V определяет окончательно в «контрактном коммите»; W, X пишут под это)

Упражнение — **чистая функция без DOM**, чтобы его проверяли тесты:

```
Упражнение = {
  id, track, topic, skill, level (1…5),
  kind,                      // 'pick' | 'cards' | 'range' | 'slider' | 'bet' | 'table' | 'order' | …
  make(seed) → задание,      // детерминировано от seed: тот же seed = то же задание
}
задание = {
  prompt,                    // текст по-русски (число с точками: 1.000.000)
  setup,                     // что показать: карты, борд, банк, стеки, позиции, диапазоны
  check(answer) → разбор,    // чистая проверка ответа
}
разбор = {
  ok, score,                 // верно / оценка 0…1 (частично верно — тоже бывает)
  mistakes: [{ code, topic, text }],   // что сделано не так; topic — из реестра
  why,                       // почему верный ответ именно такой (2–4 предложения)
  alternatives: [{ label, verdict, text }],  // другие варианты и чем они хуже/лучше
  solution,                  // что нарисовать в разборе (верный диапазон, верная ставка…)
}
```

Каждое число в `why`/`alternatives` вычисляется **кодом** (`poker-math.js`), а не
пишется руками: иначе тест «пересчитай и сравни» нечем проверить.

### 3. Виджеты — `miniapp/train/widgets/<имя>.js`

Каждый: `export function mount(props) → Element` (+ `update(el, props)` если нужно).
Принадлежность: `range-grid.js` (матрица 13×13) — W; `cards.js`, `board.js`, `odds-bar.js`,
`bet-slider.js`, `table-seat.js` и прочее — X; `choice.js` (выбор варианта),
`explain.js` (панель разбора), `progress-bar.js` — V. Брать чужой виджет можно только
после того, как он в `redesign`.

### 4. Прогресс — сообщения страницы и хранение (V; Y добавляет `placement` и журнал решений)

Всё — **про самого игрока**, его личность только из `initData`, никаких «чей» в теле.

```
{ t:'train', op:'get' }                              → { t:'train', progress }
{ t:'train', op:'result', ex, topic, track, level, score, ms, mistakes:[code], seed }
{ t:'train', op:'level',  skill, level }             // ручная смена сложности
{ t:'train', op:'placement', skills:{preflop:2,…}, via:'zero'|'quiz'|'history' }   // Y
{ t:'train', op:'reset' }                            // «Сбросить мой прогресс»
```

Сервер проверяет: известные `track`/`topic`/`skill`, уровень 1…5, `score` 0…1,
ограничения на размеры и частоту (по часам `app.clock.now()`), не более N записей на
игрока (ротация). Только **новые таблицы** через `CREATE TABLE IF NOT EXISTS`, версия
схемы (`meta.schema`) **не поднимается** (откат безопасен — как у `profiles`). Прогресс
**личный**: не в рейтинг, не в чат, не в группу, не в `view` стола, не в админку
(кроме общих чисел «сколько человек открыло Тренировку», если V решит — без имён).

### 5. Связка Обучение ↔ Тренировка (Y владеет `miniapp/train/link.js`)

```
openLesson(topicId, { returnTo })      // returnTo = { exercise, seed } или null
openTraining({ track?, topic?, exercise?, seed? })
```
После урока, открытого из ошибки, кнопка «Вернуться к заданию» открывает **то же
упражнение с тем же seed** (задание не меняется). Контекст возврата живёт в памяти
приложения (и `sessionStorage` на случай перезагрузки WebView), а не в адресе.

### 6. Прокрутка (Z → все)

`tools/lib/scroll-probe.mjs` (Z, первым пушем): `assertNoJump(page, {scroller}, action)` —
запоминает позицию прокрутки, выполняет действие (клик по сегменту, ползунку,
переключателю), проверяет, что позиция **та же** и страница не «подпрыгнула». Свои
экраны (V, W, X, U, Y) покрывают e2e-проверками с этим помощником. **Никто не
восстанавливает `scrollTop` руками после перерисовки** — это запрещено заданием
владельца; Z чинит причину в общем коде отрисовки.

### 7. Нажатие 44 px и матрица 13×13

Правило проекта — зона нажатия не меньше 44 px. Матрица 13×13 на 320 px этого дать
**не может** (ячейка ≈ 22 px). Решение — не нарушить молча, а дать способ: режим
«увеличить» (2× с прокруткой внутри матрицы), выбор рисованием пальцем с лупой,
нажатие по заголовку строки/столбца, готовые наборы («пары», «одномастные», «топ-N%»),
отмена. Исключение из проверок записать **с причиной** (как исключения контраста).
Ответственный — W; проверяет Z (часть 3).

### 8. Подсказки в игре — не возвращать

Решение 016 остаётся: **во время настоящей партии живых подсказок нет**. «Разбор после
решения» в Тренировке и уроки — не подсказки в игре. Журнал решений (Y) пишет, но
игроку во время партии ничего не показывает.

### 9. Честность содержания

Покерные «эталоны» (диапазоны открытия, размеры ставок, GTO-частоты) — **не выдумывать
и не выдавать за солвер**. Допустимо: (а) то, что считается точно и проверяется кодом
(комбо, ауты, шансы, pot odds, EV, MDF, эквити против случайной руки); (б) учебные
ориентиры, **явно названные приближёнными**, с источником (или с пометкой «правило
порядка, не точный солвер»). Каждый такой набор данных — отдельным файлом с
комментарием «откуда» и в `docs/poker-training.md`. Не знаете, верно ли, — в отчёт
владельцу как «не проверено», а не в приложение как факт.
