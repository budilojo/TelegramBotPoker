## Что сделать

### Шаг 1 — `poker-math.js` ПЕРВЫМ пушем (на него опираются U, W, Y)

Чистый модуль без DOM и без зависимостей от `bot/` (клиент не импортирует `bot/`):
- оценщик 5–7 карт (категория + кикеры, сравнение рук), **независимо реализованный**;
  в тестах сверяется с `bot/eval.js` на большой случайной выборке (десятки тысяч рук,
  фиксированный seed) — расхождений быть не должно;
- **точные** вероятности перебором: ауты по улицам (флеш-дро, стрит-дро открытое/
  гатшот, оверкарты, комбо-дро), «поймать к ривёру», эквити руки против руки и против
  **диапазона** (набор рук из `W`-формата `Set<'AKs'>`) по борду любой длины (перебор
  оставшихся карт; для префлопа — Монте-Карло с seed **или** предрасчёт, назови);
- `potOdds(bet, pot)`, нужное эквити для колла, `ev(call|fold|bet)` с fold equity,
  безубыточная частота блефа, `mdf`, `spr`, неявные шансы (`impliedOdds`), правило 2 и 4
  vs точное значение (с ошибкой правила);
- блокеры/комбо на борде (`combosGiven` — договорись с W: общая функция живёт в
  `miniapp/train/ranges/hands.js` у W; ты её импортируешь, когда запушена).
Тест `bot/train.math.test.js`: оценщик == `bot/eval.js`; вероятности дро == перебор
вручную и == известные значения (флеш-дро 9 аутов на флопе → ~35 % к ривёру; 8 аутов
стрита — ~31,5 % и т. п. — **сверь с независимым расчётом, не с памятью**); `potOdds`/
`ev`/`mdf` на ручных примерах; ошибка правила 2/4 в заданных границах. Как только тесты
зелёные — **пуш и сообщить U** (`ListAgents` → `SendMessage`).

### Шаг 3 — направления (контент-файлы, регистрация через V)

Каждое: уровни 1…5, ≥ 12 заданий на уровень (генератор с seed), `topic` из реестра,
`mistakes[].topic` — для «Изучить тему», `why`/`alternatives` с **вычисленными** числами.
Виды — настоящая работа, а не только `pick`:

- **`outs`** (Ауты и вероятности): «коснитесь карт-аутов на борде» (виджет `board`:
  отметить все аутов; разбор — какие пропущены/лишние, **с учётом** карт, дающих сопернику
  более сильную руку — «нечистые» ауты), «сколько процентов к ривёру?» (ползунок/ввод),
  правило 2 и 4 против точного. Ур. 1 — один флеш-дро; ур. 3 — комбо-дро и нечистые
  ауты; ур. 5 — эквити против диапазона.
- **`potodds`** (Pot Odds и EV): банк, ставка, ваше эквити → выгоден ли колл; вычисли
  нужное эквити `bet/(pot+2·bet)` вводом, **ползунком подберите размер ставки**,
  при котором соперник на грани безубыточности; EV колла/фолда/ставки в фишках
  (ввод числа); implied odds (ур. 3–4); fold equity для полу-блефа (ур. 4–5); разбор
  показывает расчёт по шагам.
- **`postflop`** (Постфлоп-стратегия): флоп, позиции, анамнез → ставить/чек, размер
  ставки (`bet-slider`), c-bet, check-raise, игра с дро и с вэлью; **стол**
  (`table-seat`/`pot`), история ходов; ур. 1: «сильная рука — ставьте»; ур. 3: размер по
  текстуре; ур. 5: смешанные решения («ставка 1/3 в 60 %, чек — в 40 %» — принимать
  ответ «допустимо» двух вариантов).
- **`hands`** (Разбор сложных раздач): целая раздача по улицам (4–6 решений подряд), на
  каждом решении — выбор и разбор; итог по раздаче («вы потеряли ~X BB EV на ривере»
  — только если EV считается честно: иначе качественно); длинные, но сохраняется
  состояние при выходе не нужно. Не менее 10 раздач на 5 уровней.
- **`advanced`** (Продвинутая стратегия): SPR и выбор линии, MDF и защита, блокеры
  (взять блеф с нужным блокером; виджет `range-grid` от W — когда будет), баланс
  вэлью/блефов на ривере (подберите число блефов к вэлью для безубыточности
  соперника — расчёт), эксплуатация против перекоса.
  **Честность (контракт 9):** где задание опирается не на расчёт, а на «правило
  порядка», в разборе пометка «ориентир, не точный расчёт».

### Шаг 4 — проверка своих упражнений

Тесты упражнений: `make(seed)` детерминирован; `solution` проходит `check` → `ok:true`;
пустой/случайный ответ — не `ok` (кроме случаев, где «чек» — верно: тогда ответ
«чек» ок, остальное нет); числа в `why` совпадают с `poker-math` (тест достаёт числа из
разбора и сверяет); темы в реестре. **«На зубы»:** подмени формулу pot odds /
вероятность / оценщик — тесты падают (отчёт). `tools/e2e-train-math.mjs` (в
`npm run e2e`): по одному заданию каждого направления в браузере, разбор, 320 и 390 px,
клавиатура у поля суммы, `assertNoJump` (Z) при движении ползунка и выборе размера.
