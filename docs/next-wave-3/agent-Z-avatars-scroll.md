## ЧАСТЬ 1 — «прыжки» экрана: найти и убрать первопричину

### Задание владельца (пункт 8)

> В игровых режимах при выборе числа игроков, смене блайндов, таймеров и других
> настроек, режимов, вкладок, выпадающих списков, ползунков и переключателей экран
> дёргается и **прокручивается наверх**. Найди первопричину: пересоздание компонента,
> сброс состояния, повторное создание страницы, `scrollTo`/`scrollIntoView`/`focus`,
> изменение высоты контейнера, особенности Telegram WebView, сдвиги вёрстки. Позиция
> прокрутки должна **сохраняться**. Исправление должно устранять первопричину, а не
> маскировать её временным возвратом `scrollTop` после каждого изменения. **Без
> искусственной блокировки экрана.** Проверь iOS/Android WebView — только если
> действительно проверял.

### Шаги

1. **Воспроизведи сначала, чини потом.** `tools/lib/scroll-probe.mjs`:
   `assertNoJump(page, { scroller }, action)` и `measure(page, { scroller }, action)` →
   `{ before, after, max, jumped }`; находит реальный прокручиваемый элемент (документ,
   `#app`, `.sheet`, `.screen`, `.lobby` — **выясни, кто прокручивается** в каждом
   экране, это ключ), снимает `scrollTop`, высоту `scrollHeight`, `document.activeElement`,
   запоминает, пересоздан ли узел (метка `data-probe` на элементе до и после),
   выполняет действие и **ловит скачок на лету** (`requestAnimationFrame`-наблюдатель на
   время действия, чтобы поймать «подпрыгнул и вернулся»). Пушь его **первым** — остальные
   агенты подключат свои e2e. Для воспроизведения подними форму игры с ботами
   (покер, 320×568 и 390×844), лобби покера с настройками хоста, и сними таблицу
   «экран → действие → был ли скачок → причина». Эмуляция Playwright воспроизводит
   DOM-причины, **но не поведение клавиатуры и жестов в iOS/Android WebView — так и
   пиши**.
2. **Найди причины** (проверяя каждую гипотезу замером, не на веру). Известные следы,
   которые нужно проверить: (а) `refreshSheet()` перестраивает шторку целиком
   (`$sheets.replaceChildren(...)`) — прокручиваемый элемент `.sheet` создаётся заново, и
   его `scrollTop` обнуляется; форма покера после волны 1 высотой ≈ 1000 px на 320 px, так
   что на коротких экранах скачок виден; (б) `bus.render()` пересобирает `$app` при
   каждом состоянии с сервера — вместе со скроллером; (в) `focus()`/`scrollIntoView` на
   перерисованных полях (`miniapp/games/poker.js` ~1035, `miniapp/profile.js` ~93);
   (г) смена высоты шторки/контейнера при переключении вкладок «Партия / Обучение /
   Тренировка» (разные по высоте панели) и `visualViewport`; (д) `Telegram.WebApp.expand()`
   и события `viewportChanged`; (е) `overflow-anchor`, `scroll-behavior`. Допиши то, что
   найдёшь. **Итог — список реальных причин с доказательством (замер до/после), а не
   догадок.**
3. **Исправь причину.** Принципы: **стабильность DOM**. Прокручиваемый элемент (контейнер
   шторки/экрана) создаётся **один раз** и живёт, пока экран/шторка открыты; перерисовка
   меняет только его содержимое **точечно** (обновление текста, классов выбранных
   сегментов, значений) либо заменяет дочерние узлы внутри того же скроллера — тогда
   `scrollTop` сохраняется сам, браузером, без ручного восстановления. Для шторок: разделить
   «оболочку» (`backdrop`, `.sheet`, `grab`, прокручиваемое тело) и «содержимое»;
   `refreshSheet()` не пересоздаёт оболочку; для экранов — то же в `app.js`/`bus.render()`
   (не пересобирать `$app` целиком, когда изменилась мелочь). Образец — уже работающий
   шаблон `mounted`/patch в `miniapp/profile.js`. **Запрещено:** сохранить `scrollTop`
   перед перерисовкой и вернуть после (маска), блокировать прокрутку экрана, прятать
   проблему `overflow: hidden`/`position: fixed` на `body`. Фокус: не вызывать
   `focus()`/`scrollIntoView` без причины; для клавиатуры оставить `block: 'nearest'` и
   только когда поле действительно закрыто. Высота: резервировать (`min-height`) там, где
   панели разной высоты переключаются вкладками, чтобы экран не «дышал».
4. **Покрой тестами «на зубы»:** `tools/e2e-scroll.mjs` (в `npm run e2e`): для каждого
   экрана из таблицы — прокрутить до середины, нажать сегмент / ползунок / переключатель /
   выпадающий список, проверить `jumped === false`; **верни старую перерисовку** (откат
   исправления) — тест обязан упасть (отчёт). Плюс юнит-тест на оболочку шторки: узел
   `.sheet` и его прокручиваемое тело — тот же элемент до и после `refreshSheet()`
   (если в проекте есть способ тестировать `ui.js` без браузера — иначе только e2e).
5. `docs/scroll.md` — коротко: причины, как устроено теперь, **правило для новых экранов**
   («не пересоздавай скроллер; обновляй точечно; свой e2e с `assertNoJump`»).

Прокрутку и клавиатуру в **реальных** iOS и Android WebView Telegram (моя проверка —
только Chromium с эмуляцией телефона: это не WebView), жесты свайпа Telegram, рисование

блайнды в лобби, переключить «Партия / Обучение / Тренировка», нарисовать диапазон,
сменить аватар).
