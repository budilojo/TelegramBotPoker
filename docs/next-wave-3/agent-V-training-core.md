## Задание владельца (пункты 2, 5)

> **Тренировка** — отдельная кнопка на том же уровне навигации, что «Обучение»
> (Покер → Обучение, Покер → Тренировка). Восемь направлений (префлоп-решения;

> ошибок, рекомендуемые следующие задания, динамическая сложность, повторение слабых тем.

## Что сделать

### Шаг 0 — изучить и описать (в файле сессии)

Как сейчас устроен путь «Игры с ботами → Покер → форма → Обучение»; какие экраны/маршруты
есть в `app.js`; как нижняя навигация решает, где ей скрываться; как клиент шлёт сообщения
(`bus`) и как сервер принимает (`HUB_ACTIONS`, `bot/hub.js`). Вывод — **куда встанут
Обучение и Тренировка**: «на одном уровне» значит два равноправных входа из покера
(например, три сегмента «Партия · Обучение · Тренировка» в форме покера, где «Обучение»
и «Тренировка» открывают **полные экраны**, а не шторку: матрица 13×13 и разборы не
помещаются в шторку). Решение и причины — `decisions/057`.

### Шаг 1 — «контрактный коммит» (пушни как можно раньше, остальные ждут)

   `make(seed)`, `check`, `разбор`), виды (`kind`), виджеты (п. 3), сообщения прогресса
   (п. 4), правила добавления упражнения/направления/уровня. Уточнения к плану — со

2. `miniapp/train/engine.js` (чистый модуль, без DOM): реестр упражнений

3. Пустой каркас экранов: Тренировка (8 направлений карточками, уровни, статистика),
   экран упражнения (шапка «Назад · направление · уровень · 3/10», область задания,

   варианта — для простых `pick`). W, X и Y подключают свои направления, регистрируя

   автоматически** (один `import` на файл в `miniapp/train/content/index.js`, который ты
   создаёшь пустым с комментариями «W / X добавляют свои строки здесь»).

### Шаг 2 — сервер и хранение (новые таблицы, версию схемы не поднимать)

`bot/train.js` + таблицы в `bot/store.js` через `CREATE TABLE IF NOT EXISTS` (выбери
сам, предложение): `train_skill(user_id, skill, level, rating, n, updated_at)`,
`train_result(id, user_id, ex, track, topic, level, score, ms, at)` (не больше 500 на
игрока, ротация), `train_topic(user_id, topic, mastery, interval_days, due_at,
lapses, updated_at)` (для повторения), `train_mistake(…)` (история ошибок: код ошибки,
тема, когда, сколько раз). Проверка, что **старый код открывает базу с лишними
таблицами** — как делал T (`git show 7afb285:bot/store.js` во внешнюю папку; результат в
отчёт). Сообщения — контракт п. 4; личность **только** `initData`; проверка всех полей
(известные `track/topic/skill`, диапазоны, размеры, частота — `app.clock.now()`, не
больше разумного числа результатов в минуту); отказ словами (`ERRORS`/`CORE_ERRORS`,
`MESSAGES.md`). Прогресс приходит игроку в ответ `get` и после `result`. **Прогресс
личный:** не попадает в `view` стола, в чат, в рейтинг, в карточку группы; «Сбросить мой
прогресс» (подтверждение). Админке — только общие счётчики без имён, и только если не
усложняет; иначе — в `ideas.md`.

### Шаг 3 — навыки, адаптация, повтор, статистика

- **Навыки** (`skills.js`): четыре (`SKILLS`), у каждого `level` 1…5 и `rating` (число
  0…100, скользящее: свежие ответы весят больше), по направлениям — собственная
  «пройдено уровней». Что значит «уровень пройден»: например, 8 из 10 заданий уровня
  с оценкой ≥ 0,7 (реши сам и запиши в `decisions/058`).
- **Динамическая сложность:** после серии заданий — предложение «повысить/понизить
  уровень» **с объяснением** («7 из 8 верно — перейдём на 3-й»), без молчаливого
  скачка; ручное переопределение навыка всегда доступно и сильнее авто. Подбор
  следующего задания: рекомендованные = слабые темы со сроком повторения + следующий
  непройденный уровень + одно «закрепить» из уже освоенного; объяснение «почему это
  задание» одной строкой.
- **Повторение с интервалами** (`srs.js`, простое и объяснимое — не копировать
  чужие алгоритмы вслепую): ошибка по теме → тема «слабая», возвращается через 1, 3, 7,
  14 дней при правильных ответах и «сбрасывается» при ошибке. Время — по часам
  приложения на сервере (в тестах `FakeClock`), а не из клиента.
- **Статистика:** экран «Мой прогресс» — по навыкам (уровень, шкала), по направлениям
  (пройдено уровней, точность за 30 дней), «освоенные навыки» (порог — реши и назови),
  **последние ошибки** (тема → «Изучить тему» через Y; пока Y не готов — кнопки нет),
  рекомендации. Пустое состояние — человеку, который ещё ничего не решал: одна фраза и
  кнопка. Графики — простые (шкалы, столбики) из токенов; не тащи библиотек.

### Шаг 4 — интерфейс раздела

Экран «Тренировка»: восемь карточек направлений (название, одна строка, «уровень 2 из
5», кружок прогресса), вверху блок «Рекомендуем сейчас» (1 карточка), внизу «Мой прогресс».
Экран упражнения: задание крупно и без прокрутки на 320×568, если возможно; **нижняя
панель с главным действием всегда на месте**; после ответа — панель разбора выезжает
**без пересборки задания** (карты и состояние остаются, подсвечиваются верное/неверное);
«Дальше» / «Повторить это» / «Изучить тему» (Y). Прерывание в середине — сохранение
не нужно, но «Назад» спрашивает подтверждение, если ответ уже набран. Нижняя навигация
(`nav.js`) на этих экранах **скрыта** (как за столом) — доска и кнопки не страдают;
реши, нужна ли она на списке направлений. Вёрстка 320…390 px, зоны нажатия ≥ 44 px
(матрица 13×13 — особый случай, контракт 7, решает W).

## Тесты («на зубы» — обязательно)

`bot/train.test.js`: личность из `initData`, чужой id в теле игнорируется; неизвестный
`track/topic/skill`, уровень вне 1…5, `score` вне 0…1, лишние поля, огромные строки —
отказ словами; частота; ротация 500; прогресс не попадает в `view` стола/чат/рейтинг
(«что получил каждый телефон»); сброс; изолированность двух игроков; повторение с
`FakeClock` (интервалы 1/3/7/14, сброс при ошибке); адаптация (серии → предложение, не
молчаливый скачок; ручной уровень сильнее); таблицы создаются повторно и на пустой базе;
старый код открывает базу. Движок: `make(seed)` детерминирован (тест на все
зарегистрированные упражнения: два вызова с одним seed дают одно и то же; ответ
из `solution` проходит `check` с `ok:true` — **это ловит неверные упражнения W и X**);
каждое упражнение отдаёт тему из реестра. Сломай каждую защиту — тест падает (отчёт).
`tools/e2e-train.mjs` (в `npm run e2e`): Покер → Тренировка → направление → решить →
разбор → «Дальше»; статистика; 320 и 390 px; поведение «Назад»; нет ошибок в консоли;
`assertNoJump` (Z) на переключателях.
