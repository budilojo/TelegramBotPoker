## Что сделать

### 1. Журнал решений — только вперёд, только своё, прозрачно

- Новая таблица (через `CREATE TABLE IF NOT EXISTS`, **версию схемы не поднимать**):
  `decision_log(id, user_id, hand_key, street, position, hole, board, pot, to_call,
  stack, action, amount, strength, equity, kind, at)`. Пиши **только решения самого
  игрока и только то, что он видел сам** (его карты, общий борд, банк, ставки, позицию).
  Чужие карты — никогда. Кто принимал решение — человек за столом **или** игрок в
  партии с ботами. Ограничение: не больше N (например, 300) последних на игрока,
  ротация; в `events`/админку — ничего.
- Хук в комнате покера: на каждое действие человека (не бота!) вызвать
  `logDecision(room, userId, snapshot)`. **Не менять игру**: исключение внутри журнала
  глотается и пишется в журнал сервера, партия идёт дальше (тест: упавший журнал не
  ломает раздачу). Не замедлять: запись асинхронно/пачкой, если нужно.
- Игрок должен знать: в «Настройках тренировки» строка «Игра запоминает ваши решения
  в покере, чтобы подобрать уровень. Видите их только вы» + кнопка **«Удалить историю
  решений»** (и это же при «Сбросить мой прогресс» у V). Решение о хранении и сроке —
  `decisions/071`.
- Нужны ли решения из партий **с друзьями** или только из партий с ботами —
  реши и запиши. Рекомендация: с друзьями тоже (это и есть «история игр»), но сохраняется
  только решение самого игрока.

### 2. Оценка качества решений — честно и осторожно

`bot/decisions.js` → `rateDecision(row)`: возвращает `{ verdict: 'good'|'ok'|'mistake'|
'unknown', skill, topic, reason }`. **Оценка — эвристика, не солвер.** Помечай
«ошибкой» только очевидное и измеримое: например, фолд при pot odds сильно ниже
эквити руки против случайной (вычисляемо), колл с эквити сильно ниже нужного, фолд
без ставки там, где можно бесплатно сыграть (check), олл-ин без причины с мусором
против небольшой ставки, не-повышение с лучшими стартовыми руками из ранней позиции… —
реши набор правил, каждое — отдельной функцией с тестом, ссылкой на `topic` и
пояснением. Всё сомнительное — `unknown` (в учёт не идёт). **Контекст**: позиция,
стек, банк, число соперников. **Не используй** итог раздачи (выиграл/проиграл) и число
фишек/партий как оценку. Сверь свои вердикты с `poker-math` (X) — когда он будет;
пока — с `bot/eval.js` и `equity`.

### 3. Выбор способа определить уровень (`placement.js`)

Показывается **один раз** при первом открытии «Тренировки» (и доступен позже из «Настроек
тренировки» → «Определить уровень заново»). Три карточки с одной фразой каждая:

1. **«Начать с нуля»** — все навыки на уровне 1. Сразу в Тренировку.
2. **«Определить мой уровень»** — диагностика 8–12 заданий (≈ 3 минуты), по 2–3 на
   каждый навык (`preflop`, `ranges`, `math`, `postflop`), **адаптивно**: верно → задание
   сложнее, неверно → проще (уровни 1…5 из банков W и X); интерактивные задания с
   картами/ставками/матрицей, не только выбор. Любое задание можно пропустить
   («Не знаю») — это считается как неверное, но не штрафует сильнее. Прогресс-полоса,
   «Назад»/выход с сохранением нескольких ответов не нужен. Итог — экран «Ваш уровень»:
   по каждому навыку шкала и **предложенный старт по направлениям** (например, «Префлоп:
   2 — Любитель»), короткое объяснение («по вашим ответам»), и **для каждого навыка
   можно изменить вручную** (− / +) и подтвердить.
3. **«По истории игр»** — если в `decision_log` достаточно решений (порог, например,
   ≥ 40, из них ≥ 5 по каждому навыку; иначе навык не оценивается — «мало данных»):
   показывает, **на чём основана оценка** («за последние 120 решений: 14 спорных, 3
   явные ошибки: колл при невыгодных шансах…»), а не просто число; стартовые уровни по
   навыкам, где данных хватает, остальные — предложение пройти диагностику. Если
   данных мало (у большинства сегодня их нет!) — кнопка серая, объяснение словами:
   «Пока мало решений: сыграйте ещё N раздач или пройдите диагностику». **Не показывай
   фальшивый результат.**

Все результаты → `op:'placement'` (V хранит навыки). Сервер проверяет значения и
**не доверяет клиенту**, что «диагностика пройдена»: допустимы только уровни 1…5, не
выше `lvl` +2 от того, что игрок реально сдал? — реши и запиши (это не безопасность
рейтинга: прогресс личный и ничего не открывает; но граница уровня не должна давать
ошибок в хранилище). Ручной выбор — всегда разрешён.

### 4. Связка Обучение ↔ Тренировка (`link.js`)

Контракт 5. `openLesson(topicId, {returnTo})`, `openTraining({track, topic, exercise,
seed})`. Реализуй:
- Панель разбора упражнения (`explain.js` V) для каждой ошибки с `topic` показывает
  кнопку **«Изучить тему: Pot Odds»** → урок (U) → кнопка **«Вернуться к заданию»**
  → **то же упражнение с тем же seed**, состояние задания (карты, борд) прежнее;
  ответ можно дать заново (пометка «повтор»). Контекст возврата — в памяти приложения
  и `sessionStorage` (выживает перезагрузку WebView); «Назад» Telegram и экранная кнопка
  ведут туда же; после возврата не плодится стек экранов (нажатие «Назад» из задания —
  в Тренировку, а не снова в урок).
- Из урока: «Потренироваться» → `openTraining({topic})` → упражнения по теме на текущем
  уровне игрока (если банка нет — честное «Упражнений по этой теме пока нет» и пропуск
  кнопки на уровне данных, а не заглушка).
- `recommend.js`: «рекомендуемые следующие задания» для V (слабая тема со сроком
  повторения → непройденный уровень → закрепить); единый источник для экрана «Тренировка».
- Нет бесконечных циклов (урок → упражнение → урок): ограничь глубину и покажи «домой».
