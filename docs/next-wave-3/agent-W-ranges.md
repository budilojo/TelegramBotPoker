## Что сделать

### 1. Чистая логика (не зависит от других)

`miniapp/train/ranges/hands.js`: 169 стартовых рук (пары, одномастные `s`, разномастные
`o`), положение в матрице (пары по диагонали, `s` выше, `o` ниже — **стандарт**),
число комбинаций (6 / 4 / 12), `comboCount(set)`, процент диапазона от 1326 комбо,
разбор строки «77+, ATs+, KQo» ↔ набор (`parseRange`/`formatRange`, с понятной ошибкой на
неверный ввод), сравнение диапазонов: `diff(user, ref)` → `{ missed, extra, ok }` + доля
совпадения по **комбинациям**, а не по клеткам (пара тузов — 6 комбо, KQo — 12).
Блокеры (карты на руках убирают комбо у соперника) — функция `combosGiven(hand, deadCards)`.

### 2. Виджет матрицы `range-grid.js` (самое сложное — делай аккуратно)

- 13×13, подписи рядов/столбцов (A…2), клетка показывает «AKs», «77», «T9o»; цвета —
  **токены** проекта (`tokens.css`), не градиенты; выбранные — по смыслу (зелёный =
  «играю», не просто цвет: ещё и рамка/значок — для дальтоников); пропущенные и лишние в
  разборе помечаются формой (рамка, зачёркивание), не только цветом.
- **Ввод пальцем и мышью:** тап по клетке; **рисование** (протяни по клеткам — пока
  режим «рисовать»); тап по заголовку ряда/столбца — вся строка; кнопки наборов
  («Пары», «Одномастные», «Туз-X», «Топ 10 %», «Очистить»), **отмена/повтор** (≥ 20 шагов),
  счётчик «12,4 % · 164 комбо». Pointer Events, `touch-action: none` **только внутри
  матрицы в режиме рисования** — вне матрицы страница прокручивается как обычно;
  переключатель «Рисовать / Прокручивать» нужен, если иначе нельзя прокрутить экран на
  320 px, — реши и объясни. Клавиатура: стрелки, пробел — выбрать (доступность).
- **44 px и 320 px** (контракт 7): клетка ≈ 22 px — **не скрывай это**. Дай режим
  «увеличить» (2×, прокрутка внутри матрицы, перетаскивание), **лупу** над пальцем при
  рисовании (чтобы палец не закрывал клетку), чёткие границы клеток, подписи ≥ 11 px
  из шкалы кеглей. Исключение из `layout-check`/`contrast`-проверок добавь **с причиной**
  (как оформлены прежние исключения). Запиши в `decisions/063`.
- Режимы виджета: `edit` (набор), `readonly` (показ эталона/диапазона соперника),
  `diff` (разбор: верные, пропущенные, лишние, разные оттенки по частоте), `heat`
  (частоты: клетка может быть «иногда» — для смешанных стратегий, 0…100 %; закрась
  долей, не градиентом — «заливка снизу» плоской полосой).
- Рендер: **не пересобирать всю матрицу** при каждом касании — менять только
  изменившиеся клетки (иначе «прыжки» и лаг). Это же требование Z.

### 3. Эталоны (`data.js`, честность — контракт 9)

Источник «эталона» нужно выбрать и **назвать**. Варианты (пойми и выбери, объяснив):
(а) **вычисляемый** учебный эталон: рейтинг 169 рук по эквити против случайной руки
(считается скриптом `tools/build-range-data.mjs` через `bot/eval.js`, результат
сохранён и проверяется тестом) + порог «топ N %» по позиции и сценарию — это
**приблизительно**, пометка «учебный ориентир, не солвер»; (б) опубликованные упрощённые
таблицы открытия — только если источник и условия указаны и числа сверены; ищи через
WebSearch, но **не копируй чужую таблицу целиком без лицензии** — берёшь идею и
проценты, формируешь сам. Если надёжного источника нет — делай (а) и скажи владельцу
открыто, что «настоящие GTO-диапазоны» нужны как отдельная покупка/данные. Покрой
сценарии: открытие рейзом по позициям (UTG, MP, CO, BTN, SB) для 6-max, защита BB от
рейза (колл / 3-бет), 3-бет и колл против открытия по позиции, колл-диапазон «мелких
пар и коннекторов». Размеры стеков — 100 BB (учебно); оговори. Всё сохраняется как
данные с метаданными `{ scenario, position, source, approx: true }`.

### 4. Направления и упражнения (контент-файлы, регистрация через V)

- **`preflop`** (Префлоп-решения): «Рука + позиция + что было до нас → действие»:
  открыть/сбросить (ур. 1: очевидные), защита BB, колл/3-бет/сброс против открытия,
  против 3-бета, размеры открытия, борьба блайндов (ур. 4–5). Виды: `table` (стол с
  местами, рука внизу, кнопки Fold/Call/Raise с выбором размера — **настоящий** ввод
  ставки, не только кнопки), `pick`, `range` (выберите все руки, которые вы откроете с
  BTN — без подсказок). Ур. 1–5 по нарастающей: очевидные руки → пограничные →
  позиции/размеры → давление → смешанные частоты («иногда колл, иногда 3-бет»).
- **`ranges`** (Тренажёр диапазонов): «Соберите диапазон открытия с CO» → разбор через
  `diff` по комбо: что пропущено, что лишнее, **почему** именно это (какие правила
  затронуты: «слабые тузы с чужой мастью — под большим давлением»), оценка 0…1 по
  взвешенному совпадению (грубая ошибка на пограничной руке штрафуется меньше, чем на
  очевидной). Режимы: `по подсказке-названию` («пары 77+ и ATs+» → поставьте), `по
  диапазону соперника` (ответный диапазон), `оцените процент диапазона` (на глаз:
  «сколько это % рук?»), `найди ошибку в диапазоне` (в готовом диапазоне 2–3 неверные
  клетки — тапните их). Ур. 5: диапазоны 3-бета/колла с частотами (`heat`).
- **`readrange`** (Чтение диапазонов): «Соперник открыл с UTG, потом c-bet на сухом
  борде — какие руки у него?»; задание — **закрасить диапазон** (виджет `edit`) или
  выбрать, какой из показанных диапазонов подходит; затем сужение по улицам (рейз на
  терне исключает такие-то руки). Считай комбо с учётом блокеров (`combosGiven`).
  Ур. 1: «сильный/слабый/дро» по действию; ур. 5: сужение по трём улицам с блокерами.
- В каждом упражнении: `topic` из реестра, `mistakes[].topic` — тема для «Изучить
  тему»; `why`/`alternatives` — с **вычисленными** числами, не руками. Не менее 12
  заданий (генератор с seed даст больше) на каждый уровень каждого направления; ранние
  уровни проще — проверь глазами и тестом.

## Тесты («на зубы» — обязательно)

`bot/train.ranges.test.js`: 169 рук и 1326 комбо сходятся (6·13 + 4·78 + 12·78 = 1326);
`parseRange`↔`formatRange` взаимно обратны (в т.ч. «77+», «A5s-A2s», «KQo», тире,
плюс); `diff` и комбо-процент на ручных примерах; блокеры уменьшают комбо верно (AA с
тузом на руках = 1); эталонные данные: ранг рук по эквити совпадает с **независимым**
пересчётом (`bot/eval.js`/`equity`) на выборке (допуск из-за Монте-Карло указать);
диапазоны вложены по позициям (UTG ⊂ MP ⊂ CO ⊂ BTN — если ваш источник это
гарантирует; иначе тест фиксирует, где нет); каждое упражнение: `make(seed)`
детерминирован, `solution` проходит `check` с `ok:true`, ответ «ничего не выбрано» —
не `ok`, тема из реестра. Виджет в браузере (e2e): тап, рисование, строка, набор
«Пары», отмена, режим «увеличить», подсветка ошибок, 320 и 390 px, **`assertNoJump`**
(Z) при нажатиях по матрице и наборам. **«На зубы»:** сломай подсчёт комбо, `diff`,
блокеры — тесты падают. `tools/e2e-ranges.mjs` (в `npm run e2e`).
