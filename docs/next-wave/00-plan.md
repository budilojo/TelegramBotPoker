Каждый агент получает свой файл `agent-*.md`; в нём — что делать, чьи файлы
нельзя трогать и кто работает рядом.

## Где пересекаются зоны (и как не мешать друг другу)

- **`miniapp/games/poker.js` и `durak.js`** трогают A (анимации, вёрстка стола) и
  C (в самом конце — одна кнопка смайликов). C делает кнопки **последним шагом**,
  после `git pull --rebase`; конфликт, если будет, — в разных местах файла,
  решается «оставить обе стороны».
- **`miniapp/ui.js`** — зона A. C туда не пишет (свой код — в новом
  `miniapp/reactions.js`). Нужна мелочь из `ui.js` — только читать.
- **`miniapp/solo.js`** — зона B. D не правит его: игры в списке «Игры с ботами»
  берутся из реестра (`miniapp/games/index.js`, поле `solo` модуля игры).
- **`bot/hub.js`** — трогает только C, и только маленьким блоком (приём `react`).
- **`miniapp/games/battleship.js`** — D (экран) и C (одна кнопка в конце).
- **Тесты и e2e** — каждый свои файлы; общие (`tools/e2e-solo.mjs`) — только B.

## Общие правила (читают все агенты)

1. **Сначала прочитать:** `AGENTS.md`, затем `docs/brain/00-index.md`,
   `docs/brain/status.md`, `docs/brain/tasks.md`, последний файл из
   `docs/brain/sessions/`, и `docs/brain/decisions/` по теме. Всё, что там
   помечено «предположение», — не факт, проверяйте.
2. **Ветка — `redesign`.** Коммиты по-русски, понятным предложением, мелкими
   шагами. Перед каждым пушем: `git pull --rebase origin redesign`, затем
   `git push origin redesign`. **Никогда `--force`.** Pull request не создавать.
   На сервер ничего не выкатывать.
3. **Перед каждым коммитом — `npm test`** (все зелёные). Тронули экран —
   ещё `npm run layout`, `npm run kit`, `npm run contrast` и нужный e2e
   (`tools/e2e-*.mjs`), и `npm run preview` — **посмотреть скриншоты глазами**.
4. **Тест упал — по умолчанию неправ код, а не тест.** Устаревшее ожидание
   исправлять можно, но назвать это в отчёте. Каждую новую защиту проверить «на
   зубы»: вернуть код к сломанному виду — тест обязан упасть.
5. **Дизайн:** токены из `miniapp/tokens.css`; плоско, без градиентов, свечения и
   объёмных теней; зелёный — только смысл; шрифты и картинки — только свои, ничего
   с внешних доменов; зона нажатия от 44 px; проверка от 320 px ширины.
6. **Тексты по-русски**, числа с точками; новые тексты — в `MESSAGES.md`.
7. **Подсказки выключены у всех** (`docs/brain/decisions/016`): не возвращать.
8. **Не запускать пачки субагентов.** Выбор, который можно сделать самому,
   делать и называть в отчёте. Не делать больше, чем просили.
9. **Простым языком в отчёте** (владелец — не программист): что сделано, что
   проверено и как, что НЕ проверено (живой Telegram, телефон — говорить прямо),
   что осталось.

## Память проекта: как обновлять, когда агентов несколько

В конце работы **каждый агент** обновляет `docs/brain/` — но так, чтобы четверо не
сталкивались:

- **Свой файл сессии:** `docs/brain/sessions/2026-10-21-<буква>-<тема>.md`
  (например, `2026-10-21-A-karty.md`): что сделано, что проверено и как, что не
  закончено, следующий шаг, вопросы владельцу. Только проверяемые факты;
  предположения помечать словом «предположение».
- **Свои номера решений** в `docs/brain/decisions/` (по шаблону `000-template.md`),
  чтобы номера не совпали: **A — 017–019, B — 020–022, C — 023–026, D — 027–029,
  E — 030–032**. Принято решение — отдельный файл; идея, не ставшая задачей, —
  в `docs/brain/ideas.md` (дописать строку внизу).
- **`status.md`:** добавить **одну-две строки** в таблицу «Работает (проверено)»
  (дата, способ) и, если нужно, в «Не проверено». Чужие строки не править.
- **`tasks.md`:** отметить свой пункт `[x]`; **«Ближайший шаг» не менять** — его
  ведёт владелец вместе с главным агентом после слияния всей волны. Своё
  предложение, каким должен быть следующий шаг, — в файле сессии.
- **Конфликт при `git pull --rebase`** в `status.md` / `tasks.md` / `ideas.md` —
  почти наверняка «оба дописали»: **оставить обе стороны**, ничего не стирать.
- Закоммитить память **вместе с работой** и запушить.

## Что проверяет главный агент после слияния

Когда A–D закончили: `git pull`, полный `npm test`, `npm run e2e`, `layout`,
`kit`, `contrast`, `preview`; свести «Ближайший шаг» в `tasks.md`; написать
владельцу промт выкатки под эту волну (раздел «Что едет» в
`docs/next-deploy-prompt.md`).
