## Что хочет владелец

«Чтобы во время игры можно было слать смайлики, которые нам надо нагенерировать;
они должны быть красивые и оригинальные.» Картинки владелец генерирует сам по
`docs/next-wave/images-emoji.md` (талисман «Фишка», 16 реакций) — их положит
агент E во второй волне. **Тебе нужно построить механику так, чтобы картинки
подключались подменой файлов, а пока работали запасные юникод-эмодзи.**

## Как это должно работать

**Набор — закрытый.** Вместо свободного текста — фиксированный список реакций
(идентификаторы в `bot/reactions.js`, единый список для сервера и клиента):

`gg` · `wow` · `haha` · `sad` · `think` · `fire` · `bluff` · `allin` · `thanks` ·
`sorry` · `hello` · `angry` · `facepalm` · `cool` · `wait` · `cheers`
(названия по-русски — в `images-emoji.md`; тексты положи в `MESSAGES.md`).

**Сервер** (`bot/reactions.js` + блок в `bot/hub.js`):
- Сообщение страницы `{ t: 'react', id }`. Личность — **только из `initData`**
  (`session.user`), всё остальное из тела игнорируется («никто не ходит за другого»).
- Неизвестный `id` — отказ словами. Реакцию шлёт только **сидящий за столом**
  игрок (зритель — отказ словами); в игре с ботами — только владелец партии.
- **Лимит:** не чаще одной реакции в 3 секунды и не больше шести в минуту на
  человека, по часам приложения (`app.clock.now()`, не `Date.now()` — тесты
  двигают `FakeClock`). Отказ — словами с сообщением «подождите N с».
- **Рассылка:** всем страницам этого стола лёгким сообщением
  `{ t: 'react', seat|uid, id, at }` — **без** пересборки состояния, **без**
  записи в базу, **без** перерисовки карточки в группе (иначе упрёмся в лимиты
  Telegram — см. `bot/outbox.js`). Реакции **не сохраняются**: после перезапуска
  их нет, в `serialize` комнаты они не попадают.
- Реакция не раскрывает ничего тайного (у неё только `id` и кто прислал) — но
  проверь тестом «что получил каждый телефон»: ни одного лишнего поля о картах.

**Клиент** (`miniapp/reactions.js`, `miniapp/reactions.css`):
- Кнопка «смайлик» (≥ 44 px) у каждого игрока-участника → шторка-сетка 4×4 с
  картинками реакций (`showSheet` из `ui.js` — только вызов), тап — отправка.
  Пока идёт «подождите» — кнопка бледная.
- **Показ:** пузырь с картинкой над аватаркой того, кто прислал, на ~3 секунды,
  не больше одного пузыря на человека (новая заменяет старую). Покер, дурак, UNOQ —
  у места за столом; дуэли (шахматы, шашки, нарды, морской бой) — у планки
  соперника/своей. `prefers-reduced-motion` — без анимации появления.
- **«Не показывать смайлики»:** переключатель в меню стола (`localStorage`,
  по-умолчанию показывать); у выключившего пузыри не рисуются, кнопка скрыта.
- Картинки: `miniapp/emoji/<id>.png` (512×512 прозрачный PNG; в интерфейсе
  показываются 40–64 px). **Пока файлов нет — запасной юникод-эмодзи**
  (таблица `id → эмодзи` в `miniapp/reactions.js`): подмена файлов не требует
  правок кода. **Ничего не грузить с внешних доменов.**
- Дизайн-правила (`00-plan.md`, п. 5) — токены, плоско, 44 px, от 320 px. Пузырь
  не должен закрывать карты на столе и кнопки действий; покажи на скриншотах.

## Порядок работы

1. Сервер + тесты (`bot/reactions.test.js`): личность из `initData`, подмена в теле,
   неизвестный `id`, зритель, лимит (с `FakeClock`), рассылка **всем** страницам
   стола, «не в базу» (проверить `serialize` и содержимое хранилища), «не в
   карточку группы» (`tg.calls` без правок), собранное каждым телефоном.
   **«На зубы»:** убрать лимит / принять `id` из тела / записать в комнату — каждый
   тест обязан упасть.
2. Клиентский модуль и стили (новые файлы), экран шторки.
3. **Последним шагом** — подключение в клиентах игр (по одной кнопке): `poker.js`,
   `durak.js`, `colors.js`, `chess.js`, `checkers.js`, `nardy.js`, `battleship.js`.
   Перед этим `git pull --rebase origin redesign`; в `poker.js` и `durak.js`
   смотри, что A уже сделал.
4. `npm test`, `npm run layout`, `npm run kit`, `npm run contrast`, e2e покера и
