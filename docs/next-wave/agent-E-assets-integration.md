# Агент E — подключить иконки игр и смайлики (вторая волна)

Запускать **только когда** владелец сложил готовые картинки в папку
`assets-incoming/` (см. `images-icons.md` и `images-emoji.md`) **и** агенты A–D
закончили (или хотя бы C — смайлики — запушил механику).

Прочитай **`docs/next-wave/00-plan.md`** (общие правила, как обновлять память),
`AGENTS.md`, `docs/redesign.md`. Ты — агент **E**.

## Что лежит во входной папке

```
assets-incoming/icons/<имя>.png     poker durak unoq chess checkers nardy battleship school bots app   (1024×1024)
assets-incoming/emoji/<id>.png      gg wow haha sad think fire bluff allin thanks sorry hello angry facepalm cool wait cheers   (512×512, прозрачные)
```

Не все файлы могут быть — подключай те, что есть; для остальных остаётся то, что
было (запасной вариант не ломать).

## Что сделать

1. **Осмотреть каждую картинку глазами** (`Read` показывает картинки). Проверить
   требования владельца и проекта: **плоско — без градиентов, свечения, блеска**;
   читается в 48–96 px; иконка в центре с запасом по краям; смайлики — одна семья
   (талисман «Фишка»), прозрачный фон. Что не подходит — **не подключать, а
   перечислить владельцу** с причиной.
2. **Подготовить файлы** (без новых зависимостей: Chromium из Playwright, `sips`
   или `convert`, если есть на машине; иначе скажи владельцу):
   - иконки → `miniapp/icons/<имя>.png`, **256×256** (для плиток 56–64 px при ×3),
     PNG-8 или оптимизированный PNG, **не больше ~25 КБ** каждая;
   - смайлики → `miniapp/emoji/<id>.png`, **128×128**, прозрачный фон, не больше
     ~12 КБ каждый.
   Исходники из `assets-incoming/` **в git не класть** (большие) — проверить
   `.gitignore`, добавить строку для `assets-incoming/`.
3. **Иконки игр в интерфейсе:** хаб группы (`miniapp/hub.js`, `gameIcon`,
   `miniapp/hub.css` — плитки `.gc-icon.g-<id>`), список «Игры с ботами»
   (`miniapp/solo.js` — **файл правит агент B; перед правкой `git pull --rebase`**,
   меняй только функцию `gameIcon`), строки лобби. Раньше плитка собиралась из
   фона и двух картинок карт (`iconCards`); теперь — одна картинка
   `miniapp/icons/<id>.png`, а **если файла нет — прежняя плитка** (запасной
   вариант). Углы скругляет CSS (токены скруглений из `miniapp/tokens.css`).
   Школа/обучение (`school`) и «Игры с ботами» (`bots`) — на соответствующих
   карточках/кнопках, если они там есть.
4. **Смайлики:** `miniapp/reactions.js` (агент C) показывает картинки из
   `miniapp/emoji/<id>.png`, а пока их нет — запасные юникод-эмодзи. Убедись, что
   подмена заработала (шторка с выбором, пузырь над аватаркой), и что размеры
   нормальные на 320 px.
5. **Профиль бота (`app.png`)** в код не подключается: аватарку бота владелец ставит
   сам через @BotFather (`/setuserpic`). Скажи ему это одной строкой.
6. **Проверки:** `npm test`, `npm run layout`, `npm run kit`, `npm run contrast`
   (картинки не должны ломать вёрстку и контраст подписей), `npm run preview` —
   **посмотреть** хаб, экран ботов, лобби, шторку смайликов и пузырь на 320 и
   390 px. Сетевая проверка: ни одного запроса к внешним доменам.
7. **Вес:** итоговый размер `miniapp/icons` + `miniapp/emoji` в отчёте (цель — не
   больше ~600 КБ вместе).

## Чего не делать

Не перерисовывать и не перекрашивать картинки владельца палитрой проекта (игровой
арт — содержание, а не оформление). Не добавлять внешние ссылки на картинки.

## Память

Файл сессии `docs/brain/sessions/2026-10-21-E-kartinki.md`, решения 030–032 (какие
размеры и как устроен запасной вариант), строки в `status.md`. Скажи владельцу
простыми словами: какие картинки подключены, какие нет и почему, что посмотреть на
телефоне.
