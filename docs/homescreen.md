# Иконка на рабочий стол

Строка «Добавить на рабочий стол» в «Настройках». Код: `miniapp/homescreen.js` (логика состояний, без DOM), `miniapp/homescreen-row.js` (строка), реестр — `miniapp/settings-rows.js`.
Не связано с магазином, коллекциями и оплатой.

## 1. Что проверено по официальным источникам (дата: 2026-10-27)

Источник: <https://core.telegram.org/bots/webapps> (на момент проверки страница описывает Bot API 10.1 от 11 июня 2026; список изменений Bot API 8.0 от 17 ноября 2024).

| Что | Факт из документации |
|---|---|
| `Telegram.WebApp.addToHomeScreen()` | есть, **Bot API 8.0+**; «предлагает пользователю добавить Mini App на главный экран» |
| `Telegram.WebApp.checkHomeScreenStatus([callback])` | есть, **Bot API 8.0+**; в callback приходит `status`: `unsupported` (добавление не поддерживается), `unknown` (добавить можно, но узнать, добавлено ли, нельзя), `added` (уже добавлено), `missed` (не добавлено) |
| событие `homeScreenAdded` | есть, 8.0+, без параметров: «Mini App успешно добавлено». Документация предупреждает: если устройство не умеет определять установку, **событие может не прийти, даже когда иконка добавлена** |
| событие `homeScreenChecked` | есть, «после проверки статуса», поле `status` с теми же четырьмя значениями |
| событие `homeScreenFailed` | **в официальной документации не найдено** (название из контракта оказалось гипотезой). Код слушает его необязательно и на него не опирается |
| `Telegram.WebApp.isVersionAtLeast(v)` | есть; версию Bot API клиента сравнивает с `v` |
| платформы | в списке изменений 8.0 — «мобильные устройства». Какие именно клиенты (iOS, Android) и как ведут себя Desktop/Web, документ **не уточняет** — это не подтверждено |

Как проверено: страница прочитана целиком через загрузку и разбор текста; отдельных документов по платформам не найдено. Что возвращает вызов `addToHomeScreen()` при отказе — не описано: ни события отказа, ни кода ошибки нет.
Ниже в коде это учтено: отказ определяется не событием, а **таймаутом и повторной проверкой статуса**.

## 2. Как устроено

Состояния: `unavailable` «недоступно в этом Telegram» · `checking` «проверяем» · `can` «можно добавить» · `pending` «ожидание» · `added` «уже добавлено» · `failed` «не получилось» (с кнопкой «Повторить»).

* Нет `tg`, нет одного из методов, `isVersionAtLeast('8.0')` ложно/бросает → «недоступно», методы не вызываются.
* При открытии «Настроек» — одна проверка статуса (таймаут 6 с → «не удалось проверить», не вечный спиннер). `added` → «добавлено»; `missed`/`unknown` → «можно добавить»; `unsupported` → «недоступно»; всё прочее → ошибка.
* Нажатие «Добавить» → «ожидание» (кнопки нет, второе нажатие невозможно). **«Добавлено» объявляется только** по `homeScreenAdded` или по ответу `added` на повторную проверку.
  Если за 30 с события нет — Telegram **спрашивается заново**; `added` → добавлено, `missed`/`unknown` → «Telegram не подтвердил добавление… попробуйте ещё раз», молчание → «не удалось проверить».
* Исключение из `addToHomeScreen()` → «не получилось».
* Автоматического предложения **нет**: добавить можно только нажатием кнопки в «Настройках» (тест это проверяет по исходникам).

Известное ограничение: «Настройки» перерисовываются при каждом обновлении состояния страницы; строка при этом создаётся заново и заново спрашивает статус. Если перерисовка придёт в «ожидании», ожидание сбросится на проверку, и
уже добавленная иконка честно покажется как «добавлено». Если строка создана до ответа и событие пришло в промежутке — оно может быть пропущено, повторная проверка это исправит.

## 3. Что не гарантируется

* Иконка открывает **то же Mini App внутри Telegram**, а не отдельное приложение. Внешний вид, название, значок и запуск без сети определяет клиент.
* Поведение зависит от клиента и версии: в одних `unknown` (не можем узнать), в других `added`/`missed`; событие `homeScreenAdded` может не прийти. Поэтому «ожидание» не вечно и успех не домысливается.
* Если пользователь удалит иконку — приложение этого не узнает, пока не откроют «Настройки» и не спросят статус.

## 4. Не проверено на телефоне в живом Telegram

Всё выше про поведение — по документации и по заглушке в Chromium. **Не проверено:** реальное добавление иконки на iOS и Android, что возвращает проверка статуса на этих клиентах, приходит ли `homeScreenAdded`,
как выглядит системное окно, как иконка выглядит и запускается, поведение Desktop/Web. Это нужно посмотреть на телефоне владельца.

## 5. Предложение владельцу: автоподсказка (НЕ реализована, пороги НЕ утверждены)

Предлагаемое правило (числа — для обсуждения):

* показать мягкую плашку **один раз** после **3** завершённых партий (за всё время);
* **не чаще раза в 30 дней**, не более 2 показов суммарно;
* только если проверка статуса вернула «не добавлено» (`missed`) — при `unknown`/`unsupported`/`added` не показывать;
* только между партиями (экран результата или список игр), **никогда** посреди хода и при входе в приложение;
* две кнопки: «Добавить» и «Не напоминать» — после второй не показывать никогда; закрытие крестиком считать «позже»;
* факт показа и выбор хранить на сервере по `user_id` (или в `localStorage` как запасной вариант) — решение о хранилище нужно принять отдельно.

Риски: раздражение (особенно у тех, кто уже решил «нет»); нарушение ожиданий — окно Telegram появляется неожиданно; ложное «не добавлено» там, где статус неизвестен; нагрузка на экран результатов.
Как мерить: доля показов → нажатий «Добавить» → подтверждённых `added`; доля «Не напоминать»; возвращаемость на 7-й и 30-й день у добавивших против сравнимой группы без показа; жалобы. Остановить, если «Не напоминать» нажимают чаще, чем «Добавить».
Связь с оплатой: **никакой**. Это не ссылка на внешнюю оплату, не покупка и не награда; иконка ничего не открывает и не даёт. Правила Telegram об оплате этой подсказки не касаются.
