# Аудит: модель угроз

Аудит — red team по `docs/next-audit-prompt.md`. Атакуется только локальная
копия с поддельным токеном и заглушкой Telegram; боевой сервер, домен и
Telegram не трогаются, `.env` не открывается.

## Что защищаем (по убыванию цены)

1. **Скрытое в игре** — чужие карты (покер, дурак, UNOQ), порядок колоды,
   будущий борд, будущие кубики нард, чужой флот в морском бое. Утечка ломает
   игру для всех за столом, а для игр «на интерес» — доверие к боту.
2. **Личность** — ход за другого, сидение за чужим местом, ответ на чужую
   ничью/откат, отписка другого от рассылок.
3. **Права** — пульт владельца (обслуживание, «завершить всё», закрыть чужой
   стол, рассылка всем), права хоста стола (настройки, удаление, фишки).
4. **Доступность** — один человек не должен уметь уронить бота, занять процессор
   или память, засыпать группу карточками, сбить всем таймеры.
5. **Честность результатов** — рейтинг (накрутка, двойные начисления),
   результаты в группе, сохранение фишек.
6. **Секреты и сервер** — токены ботов, база, бэкапы, права файлов.

## Кто атакует

| Атакующий | Что у него есть | Чего он хочет |
|---|---|---|
| **Игрок за столом** | свой Telegram, свой подписанный `initData`, DevTools/свой клиент — шлёт любые JSON по WebSocket | увидеть чужие карты/флот/кубики, сходить вне очереди или за другого, отменить проигрыш, накрутить рейтинг |
| **Посторонний в группе** | состоит в группе, видит карточки и коды столов | открыть чужой стол, удалить/завершить чужую игру, заспамить группу лобби |
| **Посторонний вне группы** | знает или подбирает код стола/группы, может собрать ссылку `startapp=<любой код>` (Telegram подписывает любой `start_param`, который есть в ссылке) | зайти в хаб чужой группы, создать там лобби (карточки в чужом чате), посмотреть чужую партию |
| **Хост стола** | права хоста одного стола | права над другими столами/игроками, чужие карты |
| **Злой сайт** | жертва открыла страницу в браузере | открыть WebSocket от её имени (CSWSH) |
| **Шумный клиент** | много соединений, большие/битые кадры | уронить процесс, съесть память/CPU, сбить часы |
| **Владелец (ADMIN)** | доверен | его ошибка (кривой текст рассылки) не должна ронять бота |

Атакующего с доступом к серверу (root, `.env`, база) модель не рассматривает:
он уже победил; проверяются только права файлов и то, чтобы бот сам не отдал
это наружу.

## Границы доверия

```
Telegram (подписывает initData и from.id)          ← доверен
   │
   ├─ обновления бота (long polling) → app.js       ← from.id доверен, текст/имена — нет
   └─ Mini App (браузер игрока)                      ← НЕ доверен целиком
        └─ WebSocket /ws → server.js → hub.js → games/*/handle
              личность = только checkInitData() при hello
              всё остальное в сообщении — враждебный ввод
```

- Подпись `initData` проверяется **один раз** при `hello`; дальше личность —
  `session.user.id`, и модули игр получают её как `uid`.
- `start_param` подписан, но **выбирается атакующим** (ссылку собирает он
  сам). Значит подпись на `start_param` — не право доступа: код стола или
  группы и есть ключ. Это — по замыслу, но вынесено в решения владельца.
- Хост стола — не администратор системы.
- ADMIN — по списку из `.env`; второй вход — подпись админ-бота, ведущая только
  в пульт.

## Поверхность атаки (входы)

| Вход | Код | Кто контролирует |
|---|---|---|
| WebSocket-сообщения `{t:…}` | `bot/server.js` → `bot/hub.js` → `bot/games/*/index.js` | игрок |
| HTTP статика, `/health` | `bot/server.js` | кто угодно в интернете (через Caddy) |
| Команды и кнопки в группе | `bot/app.js` `onCommand`, `onCallback` | член группы |
| Личка бота: `/start t_…`, `/start g_…` | `bot/app.js` `onPrivate` | кто угодно |
| Имена, названия групп | `bot/fmt.js` → HTML Telegram и страница | игрок/админ группы |
| `startapp` / `?room=` | `hub.open` | кто угодно |
| Пульт и админ-бот | `hub.handleAdmin`, `bot/admin-bot.js`, `bot/broadcast.js` | ADMIN |
| База и бэкапы | `bot/store.js`, `deploy/backup.sh` | процесс бота |
| Установка | `deploy/*` | владелец |

## Где ждём проблем (гипотезы на старт)

- окно годности `initData` 24 ч и `auth_date` из будущего;
- различие ответов (оракул существования кода);
- гонки между `await` в обработке одной страницы и между страницами, ботами и
  таймерами;
- `JSON` и прототипные ключи (`__proto__`, `constructor`) в именах игр, кодах,
  настройках;
- рост структур в памяти (`lastAgain`, `lastShare`, `players`, `sessions`);
- чужое в «косвенных» каналах: карточка, итоги, шеринг, пульт, `pingText`,
  тексты ошибок, вид бота;
- морской бой — свежий модуль со скрытой информацией;
- `Date.now()` напрямую в `room.js` (часы уровней блайндов);
- отсутствие проверки `Origin` у WebSocket и заголовков безопасности.
