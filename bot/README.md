# Chip Table Bot

Телеграм-бот, который заменяет покерные фишки компании, играющей настоящими
картами за одним столом. Бота добавляют в групповой чат, он набирает игроков и
ведёт всю денежную часть: стеки, ставки, банк, очередь хода, блайнды,
сайд-поты.

Карты раздают люди. **Бот не раздаёт карты, не определяет комбинации и не
решает, кто выиграл.**

---

## Запуск

1. `@BotFather` → `/newbot` → токен.
2. **Privacy mode оставить включённым** (он включён по умолчанию;
   `/setprivacy` → `Enable`). Боту не нужно читать переписку компании: команды,
   ответы на его собственные сообщения и нажатия кнопок приходят и так.
3. Добавить бота в группу. Права администратора не обязательны — без них
   он просто не сможет закреплять сообщение-стол и подчищать служебные
   сообщения, на игру это не влияет.

```bash
npm install
BOT_TOKEN=123456:AA... npm run bot
```

В чате: `/newgame` → все жмут «Сесть за стол» → хост жмёт «Начать игру».

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `BOT_TOKEN` | — | обязательна |
| `DB_PATH` | `./data/bot.db` | где лежат столы |
| `DRAW_INTERVAL_MS` | `1000` | минимальный интервал между перерисовками |
| `PORT` | — | если задан, поднимается health-эндпоинт |
| `TZ` | системная | часовой пояс в шапке стола |

Требуется **Node 22.5+** — из-за встроенного `node:sqlite`. Это единственное
место, где бот поднимает планку относительно веб-приложения.

## Главное: никто не ходит за другого

Telegram подписывает отправителя. В каждом `callback_query` есть `from.id` —
настоящий аккаунт того, кто нажал кнопку, и клиент его подделать не может.
Это и есть вся модель безопасности: **ни токенов, ни паролей, ни кодов
подтверждения в боте нет вообще.**

Отсюда четыре правила, которые держит `bot/app.js`:

1. **Кнопка — не разрешение.** Клавиатура в группе видна всем и нажать её
   может каждый. Каждое нажатие заново проверяется на сервере:
   `callback_query.from.id === room.hand.actorId`.
2. **Отказ всегда озвучен.** `answerCallbackQuery` вызывается на каждый
   callback, включая отклонённые: «Сейчас ходит Макс». Молчаливый отказ
   человек читает как «бот завис».
3. **Анонимные админы не играют.** Их апдейты приходят от общего аккаунта
   `GroupAnonymousBot` (`1087968824`) либо с `sender_chat` вместо `from`. Двух
   анонимов различить нельзя, поэтому места за столом они не получают —
   с объяснением, а не молча.
4. **Один Telegram-аккаунт — одно место.** `p.id` игрока в движке **и есть**
   его Telegram id, так что повторный `/join` физически не может создать
   второе место.

Права разделены на три независимые проверки, ровно как в вебе:
`isHost` (настройки, роли, удаление) · `canRunTable` (undo, темп раздач) ·
`canDecideWinner` (закрыть банк).

Чего в боте **нет** и не должно быть: сессий, токенов, восстановления места,
драки двух вкладок. Личность даётся извне и не теряется — половина сложности
веб-версии здесь просто не нужна.

## Архитектура

```
bot/
  index.js     точка входа: grammY, long polling, graceful shutdown
  app.js       ядро: маршрутизация апдейтов, права, вызовы движка
  room.js      свой слой комнат: роли, отложенные блайнды, undo, seq
  render.js    чистая функция room -> { text, keyboard }
  outbox.js    всё, что говорит с Telegram: склейка, лимиты, ошибки правки
  store.js     SQLite (node:sqlite), одна строка на чат
  identity.js  кто нажал — и можно ли ему вообще играть
  cb.js        кодек callback_data (64 байта)
  fmt.js       числа, экранирование, колонки под <pre>
  tg-stub.js   фальшивый Telegram для тестов
  harness.js   обвязка, чтобы тест читался как раздача
```

**`server/game.js` импортируется как есть.** Это чистый движок ставок с нулём
ввода-вывода; переписывать покер заново — гарантированные баги в минимальном
рейзе, коротком олл-ине и сайд-потах, которые там уже отловлены. Один источник
правды на веб и бота.

**`server/rooms.js` переиспользовать нельзя** — он завязан на токены сессий,
WebSocket-снапшоты и `publicState`. Идеи оттуда взяты: разделение
ROLE/PERMISSION, отложенные блайнды, undo-снапшоты (глубина 40),
`canDecideWinner`.

## Интерфейс

Скрытой информации в этой игре нет — карты физические, бот знает только фишки.
Поэтому всё живёт в групповом чате, и прятать ни от кого ничего не нужно.

```
♠️ РАЗДАЧА #12 · ФЛОП · 14:31

БАНК  2 450 · блайнды 250/500 · D Иван

  Иван        10 000  fold
› Макс         9 750  ← ходит
  Дима         9 500  BB 500
  Саша         8 500  raise 1 500

▶️ Макс · Ставка 1 500 · коллировать 1 250
```

Строки игроков лежат в `<pre>`, чтобы колонки сходились на телефоне, и
выравниваются по **визуальной** ширине: эмодзи и CJK занимают две ячейки.
Маркер хода — обычный ASCII-символ: эмодзи в этой колонке сдвинул бы одну
строку и развалил всю таблицу.

**Одно сообщение на раздачу**, закреплённое, правится через `editMessageText`.
Новое сообщение создаётся только на новой раздаче: завершённая раздача
остаётся в чате как запись, а свежая появляется внизу, где люди смотрят, а не
уезжает вверх под разговор.

**Размер ставки без слайдера.** Пресеты `½ банка` / `банк` / `+BB` / `+5BB`
считаются той же формулой, что и в вебе, и те, что оказались ниже минимального
рейза или совпали с олл-ином, просто не показываются. Плюс «Своя сумма» через
`ForceReply` с серверной валидацией по `minTotal`/`maxTotal`.

**ALL-IN требует второго нажатия.** Случайно поставить половину банка
неприятно, но поправимо; случайно поставить весь стек — нет.

**FOLD исчезает, когда можно чекнуть бесплатно** — сбросить карты даром всегда
ошибка, и на телефоне это самое дорогое случайное нажатие.

### Победитель

Приложение не знает комбинаций. После торговли показываются крупные кнопки с
именами тех, кто имеет право на банк; **сбросившие не показываются никогда**.
Несколько банков проходят по шагам: `MAIN POT` → `SIDE POT 1` → экран
распределения → подтверждение. Фишки двигаются только после подтверждения.

Суммы в превью берутся из `previewPayouts()` — это та же функция движка,
которая потом реально раздаёт фишки, поэтому превью не может разойтись с
результатом. Банк, на который претендует один игрок, помечается «ВОЗВРАТ» и
считается сам. Undo доступен хосту и дилеру.

## Ограничения Telegram и что с ними сделано

| Ограничение | Что сделано |
|---|---|
| ~30 сообщений/с и ~20/мин в один чат, правки считаются | одно сообщение-стол; перерисовки склеиваются (leading+trailing throttle, 1 с) и рисуют **последнее** состояние, а не очередь промежуточных |
| `editMessageText` с тем же текстом → `400: message is not modified` | последний отрисованный текст и клавиатура хранятся в комнате и сравниваются до отправки; сама ошибка тоже ловится |
| `callback_data` ≤ 64 байта | формат `a:raise:37:500`; игроки адресуются **индексом места**, а не Telegram id (2 байта вместо 13); тест проверяет весь набор кнопок на реальных длинных id |
| `answerCallbackQuery` обязателен | вызывается на каждый callback, включая отказы и падения |
| Privacy mode | остаётся включённым: команды, ответы боту и callback'и приходят и так |
| Группа → супергруппа меняет `chat.id` | `migrate_to_chat_id` перепривязывает комнату и строку в базе |
| Люди выходят из группы, блокируют бота, у них нет `@username` | идентификация по `from.id`, показывается `first_name`; вышедшего складывают (fold), если очередь дошла до него; ушедшему хосту наследует самый ранний участник |
| Бот не может написать первым в личку | весь игровой процесс живёт в группе, обязательных личных сообщений нет |
| Сообщение-стол удалили руками | правка падает с «message to edit not found» → публикуется новое |
| `429 retry_after` | пережидается один раз, затем повтор |

## Состояние и перезапуски

Состояние в памяти, сохраняется в SQLite при каждом изменении — синхронно и
атомарно, поэтому падение через миллисекунду после действия не теряет ничего.
SQLite, а не JSON-снапшот из веб-версии: нет состояния «файл записан наполовину».

После рестарта столы поднимаются из базы и **перерисовываются** — игра
продолжается с того же места, тот же игрок на ходу. Часы уровня блайндов при
сохранении паркуются: время, которое бот пролежал, столу не засчитывается.
`ForceReply`-подсказка и взведённый ALL-IN перезапуск не переживают намеренно —
их нужно нажать заново.

## Хостинг: честно

**Существующий Render на бесплатном тарифе для бота не годится.** Он усыпляет
сервис после ~15 минут тишины. Веб-приложению это прощается — первый зашедший
подождёт минуту. Бота это убивает: спящий процесс не получает апдейты, и игра
просто встанет посреди раздачи.

**Выбрано: long polling на процессе, который не засыпает.** Конкретно —
Render *Background Worker* или Fly.io/VPS на постоянном тарифе. Причины:

- long polling не требует публичного URL, TLS и регистрации вебхука: та же
  команда работает на ноутбуке, на VPS и в контейнере;
- встроенный поллер grammY обрабатывает апдейты строго по одному, что убирает
  целый класс гонок между двумя одновременными нажатиями;
- для домашней игры трафик мизерный, а вебхук добавил бы инфраструктуры
  больше, чем пользы.

Если хочется остаться на Render Web Service — задайте `PORT`, поднимется
health-эндпоинт, и его можно пинговать извне. Это **обход, а не решение**:
бесплатный тариф всё равно даёт 750 часов в месяц на аккаунт и просыпается не
мгновенно. Для стола, за которым сидят люди, честнее платный always-on.

## Тесты

```bash
npm test          # 139: 60 исходных серверных + 79 бота
npm run test:bot  # только бот
```

Telegram заменён стабом (`bot/tg-stub.js`), и стаб намеренно не поддакивает:
он воспроизводит `message is not modified`, «message to edit not found» и
отвергает `callback_data` длиннее 64 байт.

Покрыто:

- **Идентичность** (`identity.test.js`, 20): чужой `from.id` не ходит за
  текущего игрока; анонимный админ отбрасывается; не-хост не меняет настройки
  и роли; не-дилер не закрывает банк; каждый отказ озвучен; один аккаунт —
  одно место.
- **Поток** (`app.test.js`, 32): двойное нажатие применяется один раз;
  сохранение фишек после каждой раздачи; сайд-поты дают ровно то
  распределение, которое показал `previewPayouts` до подтверждения; ALL-IN в
  два нажатия; своя сумма и чужой ответ на подсказку; рестарт посреди
  раздачи; миграция в супергруппу; склейка перерисовок; 64 байта на реальных
  id.
- **Рендер** (`render.test.js`, 14): снапшоты текста для лобби, торговли,
  вскрытия с тремя банками, распределения, итогов; экранирование враждебного
  имени; выравнивание колонок с эмодзи.
- **Кодек и база** (`cb.test.js` + `store.test.js`, 13).

Правило проекта соблюдено: ни один ассерт не ослаблен ради зелёного прогона.
Два теста, которые проходили вхолостую, переписаны так, чтобы дойти до
проверки, и один из них вскрыл расхождение в движке — см. `ENGINE-NOTE.md`.

Раздачи карт, определения комбинаций, автоматического выбора победителя,
