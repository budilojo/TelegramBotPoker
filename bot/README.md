# Покер в чате

Телеграм-бот для техасского холдема в групповом чате компании. Бота добавляют
в группу, он набирает игроков, **сам тасует и сдаёт**, присылает каждому его
две карты **в личку**, открывает борд, принимает ставки кнопками или
командами (`/call`, `/raise 300`, `/fold`…), сам вскрывает руки и раздаёт
банк — включая сайд-поты.

Фишки виртуальные. Никаких настоящих денег, платежей и ставок на деньги.

---

## Запуск

1. `@BotFather` → `/newbot` → токен.
2. **Privacy mode оставить включённым** (он включён по умолчанию). Боту не
   нужно читать переписку: команды, ответы на его сообщения и нажатия кнопок
   приходят и так.
3. Добавить бота в группу. Права администратора не нужны.

```bash
npm install
BOT_TOKEN=123456:AA... npm run bot
```

В группе: `/newgame` → все жмут «Сесть за стол» → хост жмёт «Начать игру».

**Каждый игрок один раз нажимает Start в личке у бота.** Telegram запрещает
боту писать первым, и без этого карты в личку не придут. Бот помогает: кто
жмёт «Сесть за стол», не открыв личку, тот сразу попадает в чат с ботом, где
остаётся нажать Start. Если кто-то всё равно не нажал — игра не встаёт: свои
карты он видит кнопкой «🂠 Мои карты» (см. ниже).

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `BOT_TOKEN` | — | обязательна |
| `DB_PATH` | `./data/bot.db` | где лежат столы |
| `DRAW_INTERVAL_MS` | `1000` | минимальный интервал между перерисовками |
| `PORT` | — | если задан, поднимается health-эндпоинт |
| `TZ` | системная | часовой пояс в шапке стола |

Требуется **Node 22.5+** — из-за встроенного `node:sqlite`.

## Как играть

```
/newgame              создать стол (автор — хост)
/join  /leave         сесть / встать (повторный /join — «я вернулся»)

/check  /call  /fold
/raise 300            поднять ДО 300: столько всего будет перед вами на этой улице
/bet 200              поставить 200 (если ставки ещё нет)
/allin                ва-банк
/next                 следующая раздача
/table                показать стол внизу чата

в личке у бота:
/start                разрешить боту присылать карты
/cards                мои карты в текущих раздачах

хост:
/stack 10000          стартовый стек (только до старта)
/blinds 25 50         блайнды (в игре — со следующей раздачи)
/levels 20 | off      растущие блайнды
/level                поднять уровень досрочно
/timer 60 | off       таймер хода (15–600 с); с ним раздачи идут сами
/rebuy  /kick  /host  докупка, удаление, передача прав
/pause  /resume
/undo                 отменить своё последнее действие хоста (не ставку и не карту)
/finish               итоги с P/L
/cancel               удалить стол
```

Всё то же самое есть кнопками под столом. `/raise` и `/bet` взаимозаменяемы —
бот сам поймёт, ставка это или повышение, но сумму проверит строго: «3к» или
«2.5» не угадываются, а отклоняются с диапазоном. `/call`, когда коллировать
нечего, — это чек; обратное неверно: `/check` перед ставкой фишки не ставит.

## Два железных правила

### 1. Никто не ходит за другого

Telegram подписывает отправителя. В каждом `callback_query` и каждом
сообщении есть `from.id` — настоящий аккаунт, и клиент его подделать не
может. Это вся модель безопасности: **ни токенов, ни паролей, ни кодов.**

- **Кнопка — не разрешение, команда — тоже.** Клавиатура видна всем, а
  `/fold` может набрать кто угодно. Каждое нажатие и каждая команда заново
  сверяются на сервере с `room.hand.actorId`.
- **Отказ всегда озвучен.** На кнопку — `answerCallbackQuery` («Сейчас ходит
  Макс»), на команду — ответ на сообщение. Молчаливый отказ читается как
  «бот завис».
- **Анонимные админы не играют** — ни кнопками, ни командами. Их апдейты
  приходят от `GroupAnonymousBot` (`1087968824`) либо с `sender_chat`, и двух
  анонимов не различить.
- **Один аккаунт — одно место.** `p.id` игрока в движке и есть его Telegram id.
- **Права хоста** (настройки, докупки, удаление, пауза, итоги) проверяются по
  `from.id === room.hostId`. Хост — это право, а не место: он может играть или
  нет.
- **Единственное исключение — таймер хода**, и включает его только хост
  (`/timer 60`). Это правило стола, а не чья-то воля: ход за игрока делает
  бот, когда время вышло, и только бесплатный — чек, если можно, иначе фолд.
  Таймер может закончить вашу раздачу, но не может потратить ваши фишки.
  Никакой человек по-прежнему не может сходить за другого.

### 2. Никто не видит чужих карт

Карманные карты покидают бота ровно двумя путями:

1. **Личное сообщение** на `chat_id` = Telegram id владельца. В нём только его
   две карты.
2. **Всплывающее окно «🂠 Мои карты»** — ответ на нажатие кнопки, который
   Telegram показывает **только нажавшему**. Ответ считается по `from.id` в
   момент нажатия, поэтому кнопка у всех одна и та же и ни на кого не
   указывает: нажав «чужую» копию, вы увидите свои карты.

В группе — только борд, а на вскрытии — руки тех, кто **обязан** их показать
(см. «Кто показывает карты»). **Сбросившие не показываются никогда.** Если все
сбросили, карты победителя тоже закрыты. `/cards` в группе ничего не
показывает и отсылает в личку.

Тесты проверяют это не по финальному экрану, а по **всему**, что бот когда-либо
отправил или отредактировал — включая удалённые сообщения: карта, мелькнувшая
в группе на одну правку, утекла так же.

## Карты

- **Колода** — Фишер–Йетс на `crypto.randomInt`, а не на `Math.random()`:
  последний предсказуем по нескольким выходам.
- **Сдача** — с места слева от баттона, по карте за круг, как у живого дилера.
- **Борд** открывается за движком: движок перешёл на флоп — на столе 3 карты,
  тёрн — 4, ривер — 5. Олл-ин до ривера — остаток борда сдаётся сразу.
- **Вскрытие** автоматическое. Каждый банк отдаётся лучшей руке **среди своих
  претендентов**: короткий олл-ин с тузами берёт основной банк, а сайд-пот, на
  который он не претендовал, уходит лучшей руке среди остальных.
- **Делёж и лишняя фишка** — забота движка (`awardPots`), бот их не считает.
  Лишняя фишка уходит первому слева от баттона.
- **Оценщик** (`eval.js`) — перебор всех 21 пятёрки из семи карт. Не самый
  быстрый способ, зато очевидно правильный; тест сверяет частоты категорий на
  семи картах с точными вероятностями.

### Кто показывает карты

- **Победитель спорного банка** — показывает: без этого банк не забирают.
  При делёже показывают все, кто делит.
- **Игрок в олл-ине** — показывает всегда, выиграл он или нет.
- **Остальные проигравшие сбрасывают молча.** В группе — «карты не показаны»:
  ни карт, ни названия комбинации (название тоже выдаёт руку).
- **Возврат неуравненной ставки** победой не считается: он подписан «↩️
  возврат», без кубка, и не заставляет открыть карты.

### Олл-ин: борд открывается по улице

Если ставки кончились до ривера, исход уже решён и банк уже роздан, но группа
видит это как за живым столом: сначала руки тех, кто в олл-ине, потом флоп,
тёрн — по полторы секунды, — и ривер вместе с результатом. Пока борд
открывается, кнопки «Следующая раздача» нет, а «Мои карты» показывает только
то, что уже на столе, — всплывающее окно не может опередить группу.

Кадры идут по таймерам, а не через `sleep`: grammY отдаёт боту апдейты по
одному, и четыре секунды сна в обработчике заморозили бы все чаты бота.

`server/game.js` про карты не знает ничего — он общий с веб-версией, где карты
настоящие. Карты живут в `room.hand` рядом с раздачей движка и сериализуются
вместе с ней.

## Интерфейс

```
♠️ РАЗДАЧА #1 · ФЛОП · 14:31

🂠 J♠️ 9♥️ 4♦️

БАНК 3 000 · блайнды 250/500 · D Иван
  Иван         9 500  BTN
  Макс         8 500  bet 1 000
› Дима         9 500  ← ходит
  Саша         9 500
▶️ Дима · ставка 1 000 · коллировать 1 000
/call · /raise 2000…9500 · /allin · /fold
```

- **Одно сообщение на раздачу**, правится через `editMessageText`. Завершённая
  раздача остаётся в чате как запись: борд, руки, кто что забрал.
- **Стол следует за разговором.** Когда люди пишут команды, стол уезжает вверх.
  Бот видит это по `message_id` пришедшей команды (в супергруппе id идут
  подряд): если под столом больше одного сообщения, новое состояние
  публикуется внизу, а старая копия удаляется. Удалять свои сообщения в группе
  бот может без прав админа. При игре кнопками стол просто правится на месте.
- **Масти — эмодзи** (♠️♥️♦️♣️): красные и чёрные различаются цветом на любом
  телефоне. Поэтому карты никогда не попадают внутрь `<pre>` — эмодзи там
  ломают колонки.
- **Подсказка команд — в `<code>`.** Голый `/allin` в сообщении бота Telegram
  превращает в ссылку, которая *отправляет* команду по тапу. `<code>` по тапу
  копируется.
- **ALL-IN кнопкой — в два нажатия.** Набранный `/allin` — сразу: набор — уже
  решение. В меню `/` нет `/fold` и `/allin` — пункт меню это один тап.
- **FOLD-кнопки нет, когда чек бесплатный.** Набрать `/fold` можно всегда.

### Повтор команды

У кнопки есть `seq`, и старая кнопка отклоняется. У команды его нет. Поэтому
одинаковая команда от того же человека в пределах секунды считается повтором
и не применяется. Это важно ровно в одном месте: хедз-ап большой блайнд своим
`/check` закрывает префлоп и первым ходит на флопе — дубль прочекал бы флоп,
которого автор ещё не видел.

### Таймер хода и автораздача

Выключены по умолчанию. `/timer 60` включает оба:

- **На ход — 60 секунд** (от 15 до 600). На столе — время «ход до 14:31:45 —
  потом фолд». Именно время, а не тикающий счётчик: счётчик превратил бы
  каждую секунду в правку сообщения и сжёг бы лимит чата за минуту.
- **Время вышло** — бот делает бесплатный ход: чек, если можно, иначе фолд.
- **Два таймаута подряд** — игрок пересаживается в «пропуск»: раздачи ему не
  идут, на столе пометка. `/join` — вернуться. Свой ход между таймаутами
  обнуляет счёт.
- **Новая улица — новая минута**, даже если ходит тот же игрок.
- **Следующая раздача — сама через 10 секунд** (после открытия олл-ин-борда,
  если он был). Нажать «Следующая раздача» раньше можно, двух раздач не будет.
- **Раздача, в которой никто не сходил сам** (только таймауты), ставит стол на
  паузу — бот не раздаёт в пустую комнату. Продолжает хост: `/resume`.
- **Если за столом меньше двух игроков**, автораздача останавливается один раз
  и не повторяет попытку каждые 10 секунд.
- **Пауза останавливает часы**, `/resume` продолжает с оставшимся временем.
- **Рестарт не съедает время**: таймеры сохраняются как «сколько осталось»,
  а не как момент срабатывания, — бот, пролежавший десять минут, не выкинет
  по таймауту всех разом.

### Undo — только для действий хоста

С настоящими картами отменить ставку было безвредно. Здесь колоду держит бот,
и любой откат игры — эксплойт: отменил фолд после флопа — сыграл флоп бесплатно;
отменил раздачу — перетасовал руку, которая не понравилась. Поэтому **любое
игровое событие — сдача, ставка, фолд, вскрытие — очищает стек undo.** Хост
может отменить свою докупку, смену блайндов, удаление, передачу прав — но
только сделанные после последней сдвинувшейся карты.

## Ограничения Telegram и что с ними сделано

| Ограничение | Что сделано |
|---|---|
| Бот не может написать первым | Start в личке — один раз; кнопка «Сесть» сразу открывает личку (`answerCallbackQuery` с `url` на `t.me/<бот>?start=`); недоставленное — пометка на столе и кнопка «Мои карты»; кто нажал Start посреди раздачи — получает текущие карты сразу |
| Deep-link payload контролирует пользователь | он ничего не значит: из лички нельзя сесть ни за какой стол, места занимают только в группе |
| Пользователь заблокировал бота | `my_chat_member` в личке → статус «нет лички», разблокировал → снова ок |
| ~30 сообщений/с и ~20/мин в группу | одно сообщение-стол; перерисовки склеиваются и рисуют **последнее** состояние; переезд вниз только когда стол реально засыпан |
| `message is not modified` | последний отрисованный текст и клавиатура сравниваются до отправки |
| `callback_data` ≤ 64 байта | `a:raise:37:500`; игроки — индексом места; тест гоняет все кнопки на длинных id |
| `answerCallbackQuery` обязателен | на каждый callback, включая отказы и падения |
| Всплывающее окно ≤ 200 символов | «Мои карты» укладывается, тест проверяет |
| Privacy mode | остаётся включённым; если в группе несколько ботов, голый `/check` может уйти не тому — меню шлёт `/check@бот`, и кнопки работают всегда |
| Группа → супергруппа меняет `chat.id` | `migrate_to_chat_id` перепривязывает стол и строку в базе |
| Люди выходят из группы | вышедшего складывают, если он был в раздаче; олл-ин не складывают — его рука доигрывает; если остался один — банк его, и никто не ходит за него |
| Сообщение-стол удалили | правка падает → публикуется новое |
| `429 retry_after` | пережидается один раз, затем повтор |

## Состояние и перезапуски

Состояние в памяти, сохраняется в SQLite при каждом изменении. Колода текущей
раздачи сохраняется вместе с ней: после рестарта **те же карманные карты, тот
же борд, и тёрн — та карта, что была следующей в колоде**, а не новая. После
раздачи несданный остаток колоды стирается — «что было бы на ривере» не лежит
ни в базе, ни в undo.

В той же базе — таблица `users`: кто нажал Start (`ok`), у кого доставка
отскочила (`fail`).

---

## Честно о доверии

**Кто запускает бота, тот технически может прочитать базу** — а в ней колода
текущей раздачи и все карманные карты. Для компании друзей это обычная
ситуация «кто-то хостит»; но это надо понимать. Бот нигде не показывает эти
данные, логов с картами не пишет.

---

## Хостинг: честно

**Render на бесплатном тарифе для бота не годится.** Он усыпляет сервис после
~15 минут тишины, а спящий процесс не получает апдейты — игра встанет посреди
раздачи.

**Выбрано: long polling на процессе, который не засыпает** — Render
*Background Worker*, Fly.io или VPS на постоянном тарифе:

- long polling не требует публичного URL, TLS и вебхука;
- встроенный поллер grammY обрабатывает апдейты строго по одному — целый
  класс гонок между двумя одновременными нажатиями исчезает;
- для домашней игры трафик мизерный.

`PORT` поднимает health-эндпоинт для хостов, которым нужен занятый порт. Это
обход, а не решение: бесплатный тариф всё равно засыпает.

## Тесты

```bash
npm test          # всё: 60 серверных + бот
npm run test:bot  # только бот
```

Telegram заменён стабом (`tg-stub.js`), и стаб не поддакивает: он
воспроизводит `message is not modified`, «message to edit not found»,
отвергает `callback_data` длиннее 64 байт и **отказывает в отправке в личку
тому, кто не нажимал Start** (403), как настоящий.

- **`timer.test.js`** — на фальшивых часах, которые двигает сам тест: таймер
  выключен по умолчанию; 59 секунд — ещё нет, 60 — чек или фолд и ни фишки;
  свой ход разоружает таймер; новая улица — новая минута; опоздавший таймер
  ничего не делает; два таймаута — пропуск; пауза и рестарт не съедают время;
  автораздача через 10 с, без двойной раздачи, пауза при пустой раздаче,
  остановка без повторов; кто показывает карты на вскрытии; возврат — не
  победа; олл-ин-борд по улицам, ривер вместе с результатом, «Мои карты» не
  опережает группу, обработчик не спит.
- **`cards.test.js`** — чужие карты: личка только владельцу, в группе ни одной
  карманной карты до вскрытия (по всем отправкам и правкам), сбросившие и
  проигравшие не показываются, при «все сбросили» карты победителя закрыты, «Мои карты»
  показывает только свои; колода; борд по улицам; лучшая рука берёт банк;
  делёж с нечётной фишкой; сайд-поты по претендентам; 25 случайных раздач со
  сверкой с независимым пересчётом; игрок без лички; Start по ссылке не сажает
  за стол; undo не пересдаёт; рестарт сдаёт тот же тёрн; длинная сессия из
  случайных ходов кнопками и командами.

## Чего здесь нет

- **Выбора «показать / сбросить» на вскрытии.** Правило фиксированное (см.
  выше): кнопка ждала бы каждого проигравшего, и вскрытие вставало бы.
- **Тикающего счётчика и напоминаний в личку «ваш ход».** Первое съело бы
  лимит правок, второе — превратило бы личку в спам.
